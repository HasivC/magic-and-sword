# UI：现状、缺什么、怎么改

**给用户的设计底稿。** 你说界面过于简陋、缺很多东西，想自己设计 ——
这份文件是**你设计之前需要知道的事实**：现在有什么、技术约束在哪、
哪些是"画得不好看"、哪些是"结构上根本做不了"。

> ⚠ **2026-09-19 用户更新了优先级：美术设计先不做，改为补充内容。**
> 这份底稿留着，等要做 UI 的时候直接用。
>
> ⚠ **2026-09-21 更正一条**：血契**不再是延伸机制**了。用户把它扶正成了核心 ——
> 「花超了的术式叫做**负值术式**，消耗血契才能释放」。存量和来源都实现了，
> HUD 上也有一行常驻显示。所以下面第 8 条已经过时，保留原文只为记录当时的判断。

> 结论先说：**现在 HUD 不可能做好看。**
> 不是审美问题 —— 它每帧被整个重建一遍（下面第一节），
> 所以不能有动画、不能有按钮、不能有 hover。
> 这个前提不修，任何设计稿都落不了地。

## 一、三个结构性问题（不是审美问题）

### 1. HUD 每帧被整个重新创建

`updateHud()` 在渲染循环里每帧调用，里面是：

```ts
statsEl.innerHTML = `...拼字符串...`     // 每帧
skillsEl.innerHTML = rows.join('')       // 每帧
```

**等于每秒把整个 HUD 的 DOM 删掉重建 120 次。** 后果：

| 想做 | 为什么做不了 |
|---|---|
| 血条平滑过渡 | 元素每帧都是新的，CSS transition 永远从零开始 |
| 技能栏上加个按钮 / 图标 hover | 鼠标还没移上去，元素已经被换掉了 |
| 冷却数字滚动、获得状态时弹一下 | 同上 |
| 状态图标上的倒计时环 | 同上 |

**必须先改成"只更新变化的部分"。** 这是所有 UI 改进的前置条件。

### 2. 配色散在 99 处

| 位置 | 硬编码颜色 |
|---|---|
| `web/src/main.ts` | 22 处 |
| `web/src/editor.ts` | 10 处 |
| `web/index.html` 的 CSS | 67 处 |

画布上的颜色在一张 `COLOR` 表里，HUD 的颜色在 TS 字符串里，
编辑器的颜色在 CSS 里 —— **同一个蓝 `#58a6ff` 写了三遍**。
想换一套配色要改三个文件，而且一定会漏。

**必须先抽成一份主题。**（CSS 变量 + 一张 TS 常量表，两边同源）

### 3. 画布和 HTML 是两套视觉语言

**分工本来该是这样**：

| | 谁来画 |
|---|---|
| 画在世界坐标系里（血条、飘字、瞄准线） | **canvas** |
| 固定在屏幕上（HUD、菜单、编辑器） | **HTML/CSS** |
| 美术件（图标、边框、血条皮） | **图片素材**（你出图，我接） |

现在**混着**：怪物血条是 canvas 画的（跟着世界走，对），
玩家 HP 是 HTML 文字（对），状态是 HTML 文字列表（凑合），
编辑器是 HTML 浮层（对）。问题是这三样**长得完全不一样** ——
canvas 里的血条是硬边圆角矩形，HTML 那边是 GitHub 深色主题。

## 三、**缺**什么（我数出来的）

按"缺了会不会影响玩"排序。

### 缺了会影响玩的

| # | 缺的东西 | 为什么重要 |
|---|---|---|
| 1 | **"为什么放不出来"的就地反馈** | 现在只有一行 toast，飘一下就没。技能栏那一格应该自己变灰 + 显示原因 |
| 2 | **资源不足的预判** | 能量剩 8、技能要 10 —— 现在按下去才知道放不出来 |

| 6 | **状态图标** | 现在是一行行文字。该是图标 + 层数 + 倒计时环 |
| 7 | **胜负结算** | 死了/清完了只有一行字。没有结算面板（用时、伤害、承受、施法次数） |
| 8 | ~~**血契显示**~~ ✅ **2026-09-21 做完了**。原文："血契是延伸机制 / 特殊玩法，不是核心机制" —— **这条已被用户推翻**：负值术式成了核心概念，血契 HUD 上常驻显示（`血契 7.2`），技能栏那格还会标出每一招要花多少、还差多少 |

## 四、你想设计的话，要分三层

设计 UI 有三种深度，**成本差很远**，得先定在哪一层：

| 层 | 你产出什么 | 我改什么 | 成本 |
|---|---|---|---|
| **A. 只换皮** | 配色、字体、间距、圆角、图标 | 抽主题文件 + 修 HUD 更新方式 | 小 |
| **B. 换布局和交互** | 线框图 / 截图（Figma、AE、纸上都行）：什么信息放哪、按什么键、点了会怎样 | 重写 HUD 结构 + 加交互 | 中 |
| **C. 连美术件一起** | 技能图标、血条皮、边框、面板背景（PNG，最好带九宫格） | 加图集 + 加载 + 九宫格绘制 | 大 |

**建议顺序：A → B → C。** 理由：
- A 是 B 的前提（不抽主题，每次改配色都要改三个文件）
- B 做完之后界面结构应该基本定型了，再往里填图才不会被推翻
- C 会让包变大、要做图集，等结构定了再上

### 三个技术选项（不管哪一层都要选）

| 方案 | 适合 | 代价 |
|---|---|---|
| **HTML/CSS**（现在这条路） | 菜单、HUD、编辑器 | 和 canvas 的视觉语言要自己统一 |
| **Canvas 绘制** | 跟世界绑定的东西（血条、飘字、指示器） | 排版、点击、滚动全要自己写 |
| **图片素材** | 图标、边框、皮肤 | 要图集 + 九宫格 + 加载器 |

**现在合理的分工**：跟世界走的 → canvas；固定屏幕上的 → HTML；
美术件 → 你出图我接。**不要**把菜单做成 canvas —— 那等于自己写一个浏览器。

## 五、你说"自己设计"的话，我需要你做的最小的事

**不用画出成品。** 只要能回答这三样，我就能动手：

1. **信息放哪** —— 一张纸画几个方块，写上"这里放血条""这里放技能图标"就够了
2. **视觉参考** —— 找 1~3 张你喜欢的游戏 HUD 截图，说喜欢哪里（这是最快的方式）
3. **配色** —— 主色 / 强调色 / 危险色 / 底色，四个色值就行（或者给我一张图我取色）

**你不需要会的**：不用管 HTML/CSS、不用管响应式、不用管性能。
那些是我的活。

**我能帮你的**：
- 把现在每个界面的**截图**渲染出来给你看（像特效预览器那样，不打开浏览器也行）
- 你给参考图，我**先做一版能跑的**，你在真机上看着改
- 抽主题、修 HUD 更新方式、接图标素材

## 六、我建议的下一步

**先做一件事：把 HUD 从"每帧重建"改成"只更新变化的部分"。**

理由：
- 它是**唯一一件不管你怎么设计都必须做的事**
- 它**不改变外观**（所以不会和你的设计冲突）
- 不做它，你设计得再好看也实现不了（没有动画、没有按钮、没有 hover）

做完之后你先看一版"结构对了但还很素"的界面，再决定要设计到什么程度。
