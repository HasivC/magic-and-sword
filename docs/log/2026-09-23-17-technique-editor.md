# 术式编辑器：把"组合"真的交到玩家手里

- **日期**：2026-09-21
- **触发**：玩家看了上一轮的成果之后，指出了我搞错的重点：
  > 术式是玩家创造的，不是你写死在代码里的，要有把技能组合成术式的界面，
  > 我要的不是只有几个技能的无聊游戏，而是成千上万种可能的术式组合，
  > 而你想把它们都写死在代码里？有问题应该问我而不是自作主张
- **动了哪些文件**：
  `src/pricing.ts`、`src/validator/{index,types}.ts`、`src/cli/validate.ts`、
  `web/src/{store,technique-editor}.ts`（新）、`web/src/{main,editor}.ts`、`web/index.html`、
  `tests/{store,web,pricing,smoke}.ts`、`package.json`、
  `schema/README.md`、`technique-system/README.md`、`docs/{STRUCTURE,ui-plan}.md`

## 一、我搞错了什么

我把"术式"当成**内容**写进了 `content/techniques/*.json`。那是测试夹具，
不是产品。**游戏的内容不是那 22 个技能，而是这些技能能拼出来的组合** ——
所以真正要交付的是**创作台**，不是更多的 JSON。

这件事其实早就写在 `docs/ui-plan.md` 第 17 条（"编术式本身"）和
`schema/README.md` 的"下一步"第 1 条里了。我知道它在那儿，但一直在打磨
旁边那些东西。这一轮把它做出来了。

## 二、先改地基：配平的责任从「技能」搬到「术式」

动手之前问了三个问题，玩家对"组合的限制从哪来"的回答把整个模型改了：

> 技能不必配平到 0，但要想编排为术式，术式必须配平（单个技能也可以成为术式）

这一句推翻了原来的地基。原来（第一版）是**每个技能自己必须配平到 0**，
那样的话：

- 任何组合都自动是平的 —— **"配平"这件事根本不存在**
- 玩家能决定的只有"能塞几个技能"
- 而且**账面上永远绿灯**，错得非常隐蔽

改完之后：

| | 是什么 | 要不要配平 |
|---|---|---|
| 技能 | **零件** | **不用。** 纯收益的火球（+17）和纯代价的长冷却收招（-8）都是合法零件 |
| 术式 | **成品** | **必须到 0。** 所有零件加起来收支相抵 |

**这才是"成千上万种组合"能成立的前提**：零件越不平衡，可玩的空间越大，
玩家做的事就是拿代价零件去抵掉收益零件 —— 也就是玩家最早说的
"牺牲射程换伤害、牺牲伤害换 CD"。

具体的改动：

- `priceTechnique` 成了**权威**（`pricing.ts`），每一行账打上 `skillId`，
  这样编辑器能把账按段分组显示（"第 2 段 突进 = 1.18 点"）。没有这个字段
  玩家看得到"差 6 点"却不知道从哪补。
- `validateSkill` **一条点数问题都不报**了。这里我一开始写成了警告
  （"这个零件不平衡"），又自己删掉了 —— 那是**假警报**：玩家会**故意**做歪零件，
  弹警告等于告诉他做错了。这个坑踩过好几次（`NO_DELIVERY`、
  `PREV_HIT_ON_FIRST_LINK`），不平衡这件事该由**编辑器里那条实时点数条**呈现。
- `validateTechnique` 现在算账并判配平。它需要**完整的技能表** ——
  所以 `npm run validate -- content/techniques/xxx.json`（只给一个文件）
  原来会把存在的技能全报成"内容库里没有这个技能"。修法是：技能表**永远读全**，
  和参数里要校验哪些文件无关。
- 新增 `UNKNOWN_SKILL` **错误**：零件引用不到时不能算成 0 点。
  不报的话账会静默地少算一整段，玩家看到"已配平"，而它其实是假的。

顺带确认了一件既有设计没被推翻：**花超了和没用完不对称**。
花超（合计为负）= 超模，**允许**，拿血契付（警告）；
没用完（合计为正）= 没配平，**错误**。理由：花超有代价在管，
额度没用完是纯粹的白送，没有任何东西在限制它。

## 三、术式编辑器

玩家选的形态是 **"两者是同一份数据的两种视图，先出列表，之后加图"**。
所以有一条硬约束：**编辑器只改 `Technique` 本身，不引入任何编辑器私有的中间结构。**
将来的图视图是同一份数据的另一种画法，不是另一套数据。

界面（`web/src/technique-editor.ts`，编辑器浮层的第二个页签）：

| 区域 | 干什么 |
|---|---|
| 工具条 | 选/新建/删除/复制出厂示范、导出 JSON、导入 JSON、复制分享码、粘贴分享码、**装到按键 1..0** |
| 术式头 | 名字、怎么按、怎么瞄（5 种模式）、射程、对谁有效（标签勾选） |
| 技能链 | 一段一个零件，可上下挪、可删；**每两段之间是一扇门** |
| 条件门 | 从 9 种条件里挑，可加可删；界面上直接写清"满足才进入第②段，不满足就**跳过**" |
| 零件库 | 22 个技能，**每个后面跟着它自己值多少点**，还标了"收益件 / 代价件" |
| 点数账 | **主视觉**：合计 + "还差 N 点 / 超了 N 点" + 每段小计 + 可展开的逐笔明细 |

三个我认为关键的决定：

**1. 零件库里显示每个零件值多少点。**
"我不知道哪块便宜"是没法做设计的。加之前就得看得见 ——
这正是"技能可以不平衡"这个模型能玩起来的前提。

**2. 账是主视觉，不是附注。**
玩家的循环是"加一个强零件 → 账面变负 → 加一个代价零件 → 回到 0"。
把账藏起来，这个循环就断了，玩家只能靠猜。

**3. 空术式不进编译。**
玩家点「新建」之后还没加任何技能的草案，编译出来是一条空时间轴，
编译器会为它报错 —— 结果是"刚打开编辑器就满屏红字"。
空草案是完全正常的中间状态，所以 `recompileAll()` 跳过 `skills.length === 0`，
它也不进 `library`（技能栏上不会出现一格按不出东西的键）。

同理，**打开游戏不会凭空造一份空术式**。第一版我让编辑器在没有任何存档时
自动 `createNew()`，那会立刻写进存档 + 刷一屏红字。改成"没有就是没有，
界面上给一句'点新建开始拼'"。

## 四、`store.ts`：两份可靠性要求完全不同的东西

**存档**坏了大不了回退；**分享码**是**别人给的字符串**，属于敌意输入。
后者必须挡严。

- 格式：`TS1.<base64url(JSON)>`。不用裸 JSON 是因为一段 JSON 里全是引号和括号，
  贴进聊天会被转义、被自动链接、有时候还会被换成中文引号；
  base64url 是一段连续字母数字，谁都不会动它。
- 解码是**分层**的，每层失败给人话原因：空码 / 不认识的前缀 / 别的版本
  （"这是第 2 代分享码"）/ 解不出来（"码被截断了"）/ 不是术式（"字段不全"）/
  不合法（走一遍校验器）。**"解码失败"这四个字对玩家没有任何用。**
- 解码前会去掉零宽字符和换行 —— 聊天软件很爱塞。

**边界划在"形状"和"玩法"之间**：`parseState` 只做形状检查，
**不**用完整校验去过滤存档。因为玩家可能是编到一半关掉浏览器的，
那份术式当然没配平 —— 用配平去过滤会**吃掉玩家的半成品**。

`tests/store.ts`（25 断言）钉的就是这些：截断的码、别的版本的码、
零宽字符、手改的码、坏 JSON 的存档、写不进去的存储。

## 五、让玩家做的东西**带得出去**

这是整条链上最容易漏的一环，也是"编辑器是不是玩具"的分界线。

以前技能栏只认场景 JSON 里写死的 `techniques`。玩家在编辑器里做多少份都上不了场。
现在：

```
存档（localStorage）→ loadContent 时把玩家术式放进同一张 techniques 表
                    → recompileAll 一并编译（只有一条编译路径，不分叉）
技能栏（loadout）   → restart() 里盖掉场景里那一套
                    → 场景里的只是**出厂默认**：让第一次打开的人有东西可放
```

⚠ 玩家改技能栏之后要 **`restart()` 重开一局**，不能就地改：
`spawn()` 时写在实体上的 `techniqueIds` 是一份快照，而正在飞的投射物、
正在跑的施法都拿着旧引用 —— 半路换会出现"这一发还是旧技能，下一发是新的"。
重开是唯一干净的做法，而且玩家在编辑器里本来就暂停着。

`tests/web.ts` 里加了一条端到端断言：**预置一份存档 → 真的 boot 一次
→ 断言那份术式出现在技能栏里，而且盖掉了场景里写死的破军突刺。**
这条断言证明的是"编辑器做的东西带得出去"，不是"某个函数返回了 true"。

## 欠账

- **图视图还没做。** 玩家选的是"先列表，之后加图"。数据已经是同一份
  （编辑器只改 `Technique`），加图不需要重写底层 —— 但那是单独一轮。
- **条件只支持平铺的 9 种**，没有 `not` / `anyOf` / `allOf`。嵌套条件在列表式
  界面里没法表达清楚（要缩进、要拖拽、要折叠），而它们至今零内容。
  真要"不满足 A 且满足 B 或 C"的时候，那也正好是该上图的时候。
- **分享码里只有术式，没有技能。** 所以对方缺技能时那份码是半废的 ——
  现在的做法是**当场列出缺哪几个**，而不是静默变成一个空术式。
  把技能也打进去是以后的事，那牵扯到"技能本身也要有版本"。
- **还没定价 `links`。** 带条件的段和无条件段现在同价，但"碰到了才生效"
  显然比"一定生效"弱。这是下一个该补的计价项。
- **射程 / 投射物 / 触发频率仍然没有计价项**（老欠账）。在"零件可以歪"的
  新模型下这一条的优先级变高了：射程是玩家最早提到的那条交易轴
  （"牺牲射程换伤害"），而它现在还是免费的。
- **花超了要不要改成硬错误**没定。现在走血契（警告）。血契被玩家澄清为
  **延伸机制**，所以"核心玩法里是不是就不允许超模"这个问题该由玩家定，
  我没自己决定。
