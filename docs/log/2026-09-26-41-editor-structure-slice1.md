结构不稳，任何布局、动效、拖拽都立不住。完整改造涉及两个编辑器 ~2300 行，

## 二、这一片做了什么

**① 焦点/光标接回来**（两个编辑器的渲染入口各包一层）

```ts
function render(): void {
  const focus = captureFocus(body)   // 记下"焦点在哪、光标在第几个字"
  renderInner()
  restoreFocus(body, focus)          // 放回去
}
```

它解决的是**真实的手感问题**：现在你正在改名字 / 拖滑块，编辑器自己重画一下，
元素被换掉 → **焦点和光标全没** ✗。这一片之后不丢了。

**② `patchBlock(host, key, html)`**：按 key 记住上次的 html，**一样就不重建** ✓
（`<details open>` 的展开状态、CSS transition 都要靠这个）。
工具就位了，但**还没接到页面上** —— 因为它只有在"页面一块一块挂"的时候才有用，
而现在是"拼一大串一次写进去"（一串里一个字变了整串都得重建 ✗）。

**③ 块地图**（写进 `editor-ui-brief.md`）：技能页 10 块 + 术式页 6 块，
每块**谁生成、里面什么是"会变的数"**。他改布局时照着找就行 ——
⚠ 而且这张表说明了一件要紧的事：**他现在就能改布局**（模板就是源码），
只有"动效 / 拖拽"这类需要结构稳定的东西才要等第 2、3 片。

## 三、⚠ 我自己在这儿炸过一次（诚实记录）

`captureFocus()` 第一版直接读 `root.ownerDocument.activeElement`，
而**测试的假 DOM 没有 `activeElement`** ✗ → 一个"把光标接回来"的小工具
把整个 boot 炸了，`tests/web.ts` **35 个断言一起红**，
报出来的却是"客户端加载失败 / 开局没报加载失败"—— 真因藏在最里面。

两件事因此定下来：

1. **渲染路径上的工具函数宁可什么都不做，也不能抛** —— 全部改写成"能用就用" ✓
2. 补了**回归测试**（`tests/web.ts`）：在没有 `ownerDocument` 的假 DOM 上，
   `captureFocus` 返回 `undefined`、`restoreFocus` 不抛 ✓

⚠ 顺带撞到一个类型问题：这个文件被 `tests/web.ts` import，于是同时被**两个工程**编译 ——
`tsconfig.web.json`（有 DOM 类型）和根 `tsconfig.json`（**故意没有 DOM 类型**，
引擎那侧 headless 是一道额外栅栏）。所以它只写"我实际用到的那几个方法"的形状
（`ElLike`），两边的栅栏都保住 ✓。里面那些成员还得写成**方法签名** ——
`contains?: (other: unknown) => boolean` 这种属性写法在 `strictFunctionTypes` 下参数逆变，
真 DOM 的 `contains(other: Node | null)` 对不上 ✗。
