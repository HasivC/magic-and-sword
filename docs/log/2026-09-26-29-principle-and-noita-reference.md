  > 2 把这句话记入文件作为宗旨：所有点数相关的可调整的值，都具有一个默认值，
  >   在这个默认值下点数是配平为0的。
  > 3 术式实际上参考的是 noita 的编程玩法，此游戏的技能对应 noita 的魔法，
  >   术式对应一把法杖的所有技能，搜索 noita 相关机制以确保你理解这段话。
  >   要不断向我提问来保证内容和我想的一样

  第 3 条做完了**调研**（下面有对照表）。

## 一、宗旨写在哪、以及它现在满足到什么程度

写进了两个地方：

- `schema/README.md` 第五节开头（**宗旨**那一节，原文引用）
- `schema/skill-schema.ts` 的文件头（作者会读那个文件）

⚠ 顺便核了一遍现状，**已经满足**的和**还没满足**的都列在那张表里，
要点是这条宗旨逼出了一个还没定的问题：

**时间类代价（阶段时长 / 能量 / 冷却 / 生命）的"默认值"是什么？**

- 射程/范围/规则位都有明确的"标准值"（偏离标准才计价），所以它们满足宗旨。
- 而时长/能量/冷却**写了就提供额度**（它们是代价），
  它们的"中性点"是"不写"（0）—— 那不叫默认值，那叫没有代价。
  照宗旨的字面意思，每一个都应该有一个"偏离它才计价"的基准
  （比如"标准前摇"），否则这条宗旨对时间类不成立。

## 二、Noita 调研（读的是官方 wiki）

读的三页（`noita.wiki.gg`）：[Wands](https://noita.wiki.gg/wiki/Wand)、
[Spells](https://noita.wiki.gg/wiki/Spells)、
[Guide: Wand Mechanics](https://noita.wiki.gg/wiki/Guide_To_Wand_Mechanics)。

要点（这几条决定了我们缺什么）：

- **法杖 = 一列魔法 + 一组数值**：Shuffle（乱序）、Spells/Cast（一次施法抓几个）、
  Cast Delay（每次施法的等待）、Recharge Time（牌堆走完或 wrap 之后的充能）、
  Mana Max / Mana Charge Speed、Capacity（槽位数）、Spread、Always Casts、Speed Multiplier。
- **魔法 = 效果本身 + 它的修正**：每个魔法带耗蓝、施法延迟修正、充能修正、
  伤害、散布、半径、速度、暴击率；还有"有限次数 Uses"。
- **施法顺序**：不乱序的法杖**从左到右依次施放**；牌堆走完 → 充能 → 从头发起。
  乱序法杖在充能/编辑/切换时把顺序打乱。
- **修正类魔法抓下一发**：一排修正后面跟一个投射物，全部叠在那一发上；
  修正只影响**当前这次施法**（触发器里的单独算）。
- **多重施法抓后面 N 个**：`Triple Spell` + 三个投射物 = 一次施法同时打出三个，
  它们**共享一次施法延迟**。
- **触发器/定时器**：投射物命中（或计时）时，**再放一串魔法**；
  触发器内部的施法延迟被忽略。
- **wrap**：一次施法块需要的魔法数超过牌堆剩余时，从头绕回来取。
- **法力不够就跳过那个魔法**（然后可能 wrap 过去）。

## 三、Noita → 本作 的对照（现状）

| Noita | 本作现在有什么 | 差什么 |
| --- | --- | --- |
| 魔法 Spell（一个效果 + 耗蓝 + 修正） | **技能 Skill** ✓ | 但我们的技能里塞了"时间轴（阶段）+ 效果（规则）"两样；Noita 的魔法没有时间轴，节奏由法杖的施法延迟/充能决定 |
| 法杖 Wand（一列魔法） | **术式 Technique**（技能链 / 序列 + `links`） | 法杖的**数值**一个都没有：容量、施法延迟、充能、法力、乱序、始终施放、每次施法数 |
| 施法顺序（左→右） | ✓ `skills` 就是按顺序 | |
| 牌堆走完 → 充能 → 从头 | 部分：序列**到底回绕** ✓ | "充能时间"没有（我们的 `cost.cooldown` 像是"每次施法的冷却"） |
| 多重施法（一次抓 N 个，共享延迟） | ❌ | 我们是一条链**依次**跑完 |
| 修正下一发 | ❌ | 我们的规则是"给自己/目标加效果"，没有"**改下一段技能**"这种载荷 |
| 触发器（命中时再放一串魔法） | 部分：`onHit` 能跑动作 | 不能"再放**一个技能**" |
| 乱序 Shuffle | ❌（我们的序列是可预测的固定顺序） | |
| 始终施放 Always Cast | 部分：常驻被动（`activeTechniques`） | 不是"每次施法附带的那一个" |
| 有限次数 Uses | ❌ | |
| 法力（法杖自带、会回） | 部分：角色的 `char.energy` | Noita 的法力在**法杖**上，不在人身上 |

## 四、玩家的回答（2026-09-21，逐条）

| 我问的 | 玩家的回答 |

| 法杖数值搬哪些 | **都不搬。**"技能已经包含了这些，术式就不必包含了。术式只是提供技能的各种组合以及条件触发等特殊技能。" <br>并且明确重申：**"不要做法杖，这个游戏是术式。"** |
| 修正 / 触发器做不做 | **两个都要**，而且"**可以在术式的编辑界面任意添加这两个**" |
| 宗旨按什么算 | **按技能算**："在玩家不调整技能属性时，默认值使得点数为 0。"<br>时间类代价**也给基准**；阶段时长这个属性"调成**有和无二选一**，选有就是默认值" |

## 五、第二轮回答 —— 模型定下来了（2026-09-21）

| 我问的 | 玩家的回答 | 我原来错在哪 |
| --- | --- | --- |
| 修正 / 触发器的形状 | "**是特殊技能**，它们只在**术式中**修饰其他技能时起作用" | 我以为是术式上的字段 —— 不是，它们是**技能**，只是离开术式就没用 |
| 固有效果能不能改 | "交流有问题。我的意思是**机制上的代价**：比如位移的**机制本身**是不应该有代价的，位移的**距离**有代价。我们在游戏里设置各种**互不相同的基础技能**，玩家获得它们后可以编辑，因此不会出现**两个账相同而效果不同的火球技能**" | 我把"机制"和"数值"混成一句话了。**机制免费、数值有价**，而且基础技能是**各不相同**的（不是同一份模板换皮） |
| 术式的账还剩什么 | "技能默认配平**不代表**技能不可以被编辑，注意我说的**默认**两字。玩家编辑后技能可以有盈亏，而**术式必须配平到 0**" | 我以为"技能默认配平"会让术式的账变得没意义 —— 不会，默认只是**起点** |
| 阶段时长的形状 | "**不调成二选一了，用三选一吧：无、默认值、默认值的 3 倍**（或更多倍？）" | 我提的二选一太窄 |

### 于是模型是这样（这一版我认为定下来了）

```
技能 Skill
├── effect        固有效果：机制（载体 + 载荷种类）+ 它的**数值**
│                 ⚠ 机制免费（"能位移"这件事不要钱），**数值有价**（位移多远、打多痛）
│                 ⚠ 它**不进规则栏**，在编辑器里单独一块
├── rules[]       额外行为 / 反应（原来的规则，照旧进账）
├── phases[]      时间轴：时长是**三档**（无 / 默认 / 默认×3）
└── cost          能量 / 冷却 / 生命（照旧进账）

特殊技能（**也是技能**，但只在术式里起作用）
├── 修正   —— 修饰它后面的技能
└── 触发器 —— 命中时再放一串

术式 Technique
└── 技能的组合 + 条件 + 这些特殊技能
    ⚠ **不做成法杖**：没有容量 / 法力 / 施法延迟 / 充能 / 乱序
```

**宗旨的落法**（按技能算）：

- 每个基础技能在它的**默认数值**下，点数合计 **0**。
- 玩家改任何一个数值 → 技能就有了盈亏 → 必须靠**别的技能或修正**补回来。
- **术式仍然必须配平到 0**（这条不变）。

⚠ 一个直接推论：**"基础技能"必须互不相同**（不是同一份火球换个名字），
因为"机制免费 + 数值有价"这条成立的前提是 —— **玩家不能凭空造一个新机制**。
玩家能造的是"数值 + 组合 + 修正"。

## 附：Noita 调研原文要点（存档）

读的是官方 wiki 三页（[Wands](https://noita.wiki.gg/wiki/Wand)、
[Spells](https://noita.wiki.gg/wiki/Spells)、

- 法杖数值：Shuffle / Spells-Cast / Cast Delay / Recharge Time / Mana Max /
  Mana Charge Speed / Capacity / Spread / Always Casts / Speed Multiplier。
- 魔法属性：Uses（有限次数）、Mana Drain、Cast Delay 修正、Recharge 修正、
  Spread、Radius、Speed、暴击、伤害与伤害类型。
- 不乱序法杖**从左到右依次施放**；牌堆走完 → 充能 → 从头再来；乱序法杖随机化顺序。
- **修正类魔法抓下一发**（一排修正叠在后面的投射物上，只影响当前这次施法）。
- **多重施法抓后面 N 个**（Triple Spell + 三个投射物 = 一次施法一起打出去）。
- **触发器 / 定时器**：命中（或计时）时**再放一串魔法**，触发器内部忽略施法延迟。
- wrap：一次施法块需要的魔法数超过牌堆剩余时，从头绕回来取。
- 法力不够 → 跳过那个魔法（然后可能 wrap）。

⚠ 玩家明确说了**不做法杖那一套**（容量/法力/延迟/充能/乱序都要不要），
所以上面这些**只作为理解"术式 = 组合 + 条件触发"的参照**，
