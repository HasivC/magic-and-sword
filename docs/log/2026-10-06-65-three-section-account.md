## 改了什么

### 一、规格（**逐条抄自定稿第十二节**，不重写）

> 三条判据（原文表格）

| 术式 | 合计 | 血契 |
| --- | --- | --- |
| **纯主动术式**（只有主动序列） | **可以为负** ✓ 为负 → **释放时消耗血契** ✓ | 能吃 ✓ |
| **纯常驻术式**（只有常驻序列） | **不能为负** ✗（报错）；**为正 → 黄色警告**（"为正没有什么用"） | **不能吃** ✗ |
| **混合术式**（两种序列都有） | **只有常驻那一边受约束**：**常驻序列的点数和 ≥ 0**；**主动序列照旧可以为负** | 能吃 ✓：`max(0, −主动和)` |

> **裁定 (A)**（原文）

```
血契 = max(0, −主动序列的点数和)
```

⇒ **常驻那边多出来的正额度，不能补贴主动那边**（两边完全切开）。
⚠ 另一案 (B)（`max(0, −(主动和 + 常驻和))`）**已作废**。
⇒ 还有一条："**为正就警告**"的判据是一条、不分术式类型（纯常驻为正 / 混合的常驻那半为正，
**同样警告**）；而**主动那半为正**那一格定稿明说"**实现时可以按警告处理，也可以只提示不报警**，
别为了这一格卡住实现" ⇒ 本片**不报**（留了口子）。

### 二、判据**没有新写第二份**

| 要判什么 | 判据在哪儿 |
| --- | --- |
| 这门术式**算不算账**（武器 / 魔法） | `school.ts` 的 `techniquePaysPoints`（日志 64 立的，**原样复用**） |
| 这一段**是不是常驻序列** | `school.ts` 的新 `isConstantSequence` = **既有的 `hasConstantWrapper`**（`at === 0` 的 `wrap` 副本）—— 和 `sim/compile.ts` 的 `constantSegments`、校验器那条 `WRAP_IN_NON_PRESS_TECHNIQUE` 读的是**同一句** |

⚠ **为什么"常驻序列"读包装、而不是读 `form: 'passive'`**：那是**技能**那一侧的分类。
而且今天两者**不相容** —— 探针实测：`activation: "auto"` + 常驻段 ⇒ 校验器报
`WRAP_IN_NON_PRESS_TECHNIQUE`（**错误**）而 `skill.last-stand-shield` 的 `form` 又不是 `passive`；
拿形态当判据的话，一条挂常驻技能的序列在 `press` 术式里会**既算不进账、又看不见**。
⇒ 判据只能是**包装**（"这一段参不参与按键激活"和"这一段是不是常驻序列"是同一件事）。

### 三、切分**不改账**

`priceTechnique` 里的实现：先按老路把整本账（`tech.skills` + 段上的修饰）算出来并**统一整数化**，
然后按段把**整数化之后**那批条目分成两半加总。所以：

- `activePoints + passivePoints === total` 是**构造出来的**（同一批整数分开加）；
- `total` / `kind` / `entries` **一个数都没变** ⇒ 出厂全 0、`calibrate`、`duel` 输出都不动；
- 新东西只在 `PriceResult.threeSection`（`{ activePoints, passivePoints, bloodPact, total }`）。

⚠ 拿不到原型表（`o.modifiers === undefined`）时**认不出常驻** ⇒ 整本账落进**主动**那半。
这是**安全方向**：若按常驻算，(A) 会把血契从"有"变成"没有"＝白送。

### 四、⭐ 那两处**看得见的行为变化**（逐条点名）

1. **变多的警告**：常驻那半**为正** ⇒ 新警告 `CONSTANT_SIDE_POSITIVE`
   （"为正没有什么用"，正是定稿点名的落点）；常驻那半**为负** ⇒ `CONSTANT_ONLY_NEGATIVE`
   （**纯常驻**，**错误**）/ `CONSTANT_SIDE_NEGATIVE`（**混合**，警告）。
   ⚠ **出厂 14 份一份都不触发**（一份用 `wrap` 的都没有）⇒ `validate` 仍是 **57 / 57 / 0 / 9**。
2. ⚠⚠ **一处新暴露出来的不一致（本片故意只钉住、不接线）**：
   `threeSection.bloodPact` 算的是**裁定 (A)**（只从主动那半来），
   而**引擎真正扣的那个数** `bloodPactCostOf` / `ValidationReport.bloodPactPerUse`
   还是 `kind === 'negative' ⇒ |合计|`，**没读切分**。
   构造出的纯常驻反例实测：表说**0**、引擎说**18**。
   ⚠ 本片**不动它** —— 换掉 `bloodPactCostOf` 会改引擎行为（`cast.ts` 的扣费），
   那是**用户裁定**的事。对**今天全部出厂内容**两者一致（都是 0），所以是**潜伏**的分歧。

## 为什么

- **"常驻那半边必须自己平"堵的是一条白嫖路径**（定稿原话）：一条超模常驻 + 一条亏模主动，
  合计正好平，而玩家**从不使用**那条亏模主动 ⇒ 超模的常驻部分是**净赚**的。
- **裁定 (A) 而不是 (B)**：在 (B) 下"常驻为正"就**有用**了（能替主动付一部分），
  和用户那句"**为正没有什么用**"当场矛盾 ⇒ 只有 (A) 自洽。
- **判据只放一处**（`school.ts`）是这个项目最硬的一条纪律：两份判据迟早漂移，
  而漂移的表现是**报价 / 血契 / 界面各按各的算、一处都不报错**（日志 64 那次的现形）。
  本片的"是不是常驻序列"直接复用 `hasConstantWrapper`，同样没有第二份。

## 待裁定（**6 条**，一条都不自己定）

1. ⚠⚠ **`bloodPactCostOf` 要不要改成读 `threeSection.bloodPact`**（裁定 (A) 的落点）。
   今天它读 `|合计|`：对**全部出厂内容**两者一致（都是 0），但表里明说
   "纯常驻**不能吃**血契" ⇒ 构造出的反例里它**多收 18 点**。
   改它 = 改引擎行为（`CompiledTechnique.bloodPactCost` → `cast.ts` 扣费）。
2. **混合术式 + 常驻那半为负**：本片只报**警告**（`CONSTANT_SIDE_NEGATIVE`），
   而**纯常驻**同情形报**错误**。⚠ 定稿表里"混合"那一行写的是"⚠ 只有常驻那一边受约束"、
   没说报错还是警告；我按"混合术式的主动那半照旧自由、不至于判死"选了告警。
   要一刀切（混合也报错）就改**一个 `if`**（判据只有那一处）。
3. **主动那半为正**要不要也报黄条：定稿明说"**可以按警告处理，也可以只提示不报警**，
   别为了这一格卡住实现" ⇒ 本片**不报**。要报就是一条 `warn`。
4. **只有常驻技能、没有序列**的术式（`skills` 里全是常驻技能、`sequences` 空）
   算不算"纯常驻"？本片判 `false`（**不是**）—— 因为没有序列**可切**，
   `threeSection` 两半都是 0，而"技能挂在术式层"那半边按**主动**算（玩家按那个键）。
5. **空术式**（`skills` 空、`sequences` 空）：校验器**先**报 `EMPTY_TECHNIQUE` 并**不再算账**
   （`priceable` 为假）⇒ 它**拿不到** `threeSection`。所以"空术式的账卡显示什么"
   今天由那条错误管着 —— 要不要给它一个"无账"的显示，待裁。
6. **"常驻为正"的可见性**：本片只在**校验器**出声（警告）。
   编辑器那三处取账（`web/src/**`）**一个字节没动** —— 账卡 / 合计那一行
   **不会**显示"常驻 +2 是白给的"。要不要在界面上也说出来，以及**这一层冻结什么时候解**。
