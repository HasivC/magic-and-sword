## 一、范围单独计价（第二条交易轴）

上一轮我把 `area` / `aura` 的半径排除在外，理由是"那是范围不是射程，该不该收钱还没定"。
玩家定了：**应该**。于是现在有两条轴：

| 轴 | 量什么 | 标准值 | 汇率 |
|---|---|---|---|
| **射程** | 打得多远 —— 扇形半径 / 突刺长度 / 光束长度 | 2.5 / 4 / 8 米 | 0.257 点/米 |
| **范围** | 打得有多广 —— `area` / `aura` 的半径 | 6 / 4 米 | 0.067 点/米 |

两条轴都是**相对**的：只有偏离标准的部分才计价，长了扣点、短了补贴。
界线靠"哪个载体归哪张表"划 —— 一个载体只有一个 `radius`，两个函数各管各的字段，
互不串门（测试里有一条专门钉这个）。

### 顺带修掉一个我自己猜错的数

标准值必须**从出厂内容里量出来**，不能拍脑袋。上一轮我给突刺猜了个 6 米，
实际内容是 **4 米**（破军突刺）—— 结果是它凭白拿到 2 米的补贴。

写了个小工具干这件事：`.scratch/delivery-values.mjs` 把每种载体的几何值
按 kind 列出来。量出来的结果：

```
area.radius       2.5 / 2.5 / 6 / 12 / 12   → 标准 6
aura.radius       4（只有圣光术）              → 标准 4
beam.length       8 / 12                      → 标准 8
capsule.length    4（只有破军突刺）             → 标准 4   ← 我原来猜的 6 是错的
meleeArc.radius   2.5 / 4                     → 标准 2.5
```

## 二、"拖了没反应的滑块"—— 玩家给的原则

> 如果改变技能的某种属性不会改变技能的效果（或非常不明显），
> 那这个属性可以固定而不进入编辑器供玩家修改。

这条我按两个方向落实了。

### ① 引擎一处都不读的字段 → 删掉

跑 `.scratch/audit-fields.mjs`（上一轮建的），报出 `EntityDef.baseZ` ——
注释写着"视觉 z 偏移的基准（击飞、浮空用）"，**引擎里出现 0 次**。

它比"编辑器里的死滑块"更糟：连编辑器都进不去，纯粹是一张空头支票。
内容作者照着写，然后发现击飞高度一点没变。删掉了。

删完再跑一次审计，"引擎一处都不读的字段"那一栏是**空的**。

### ② 写了但**这个载体不读**的字段 → 报警告

引擎对每种载体只读固定的几个字段（`src/sim/targeting.ts` 里那几个分支）：

```
meleeArc    radius / angle          beam       length / width
area, aura  radius                  capsule    length / width
projectile  speed / lifetime / radius
```

别的字段写上去是**静默失效**的 —— 而编辑器又照着 JSON 里有什么就给什么配滑块。
于是玩家拖着一个"半径"，拖半天发现打出去的宽度没变。

新增校验 `DELIVERY_FIELD_UNUSED`。出厂内容里一条都没有，所以
`npm run validate` 上看不见它 —— **正因为它现在是 0，才更需要一条测试盯着**
（`tests/smoke.ts` 里放了一个合成的光束术式，故意写 `radius`）。
不然以后谁写错了，表现就是"这个滑块拖了没反应"，而没有任何地方会响。

## 三、一个还没定的取舍：范围几乎是免费的

标定出来的 `areaRadiusPerMeter` 只有 **0.067** —— 12 米的扫描圈比 6 米标准
只贵 0.4 点。这条轴**存在但几乎是装饰**。

原因不是汇率算错了，是**出厂内容本身**：那 22 个技能是在"范围免费"的前提下
调的数值，标定器只能拟合出一个接近 0 的汇率。

要让它真的疼，得二选一：
- **给这条轴一个下限**（比如至少 0.2 点/米），代价是标定残差会涨、
  而且几个范围的技能要重新调数值
- **接受它便宜**，等做新内容时按"范围要钱"来设计

这是个设计取舍，不该我自己定 —— 留给玩家。

## 欠账

- **范围的汇率待定**（见上）。
- **投射物的飞行距离**仍然不在任何一条轴上。它是 `速度 × 存在时间` 算出来的，
  不是玩家直接拖的一个数 —— 该不该折算成"射程"要另说。
- **`StatusDef.visibility` 零内容**（熔岩护甲那条 `visibility: 1` 是空操作），
  和 `baseZ` 是同一类问题，但它至少是**被读的**，只是没人写。
  该不该进编辑器、还是干脆删掉，也要定。
- **Electron 外壳**：玩家同意"先把界面做好看、再套外壳"的顺序，
  所以下一步是**定界面**（配色 / 素材 / HUD 结构），不是套壳。
