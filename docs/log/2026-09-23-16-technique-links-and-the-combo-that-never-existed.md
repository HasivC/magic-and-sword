# 术式真的能"编程"了 —— 以及一个从来就不该存在的概念

- **日期**：2026-09-21
- **触发**：玩家看到上一轮的东西之后，重申了一遍模型：
  > 重申，没有组合技这个概念，分享码是术式的。术式由若干技能进行编程组合得到。
  > 术式例子：向指向方向位移（技能），若触碰到敌人则释放冲击（技能）
- **动了哪些文件**：
  `schema/skill-schema.ts`、`schema/PLANNED.md`、`schema/README.md`、
  `src/sim/{types,cast,compile,conditions,pipeline,targeting}.ts`、
  `src/validator/{checks,index}.ts`、
  `content/skills/{charge-dash,impact-burst}.json`、`content/techniques/charge-impact.json`、
  `content/scenarios/arena.json`、`tests/{scenario,web}.ts`、
  `docs/{STRUCTURE,framework-audit}.md`、`docs/log/…`

## 一、被纠正的地方：没有"组合技"

我上一轮把 `Combo`（"可保存、可分享的技能组 ≈ 函数"）当成一个**计划中的类型**
从 schema 搬进了 `PLANNED.md`。玩家的意思是：**这个类型不用搬家，它不该存在。**

想清楚之后这很明显：

- **术式** = 若干技能**用条件连起来的程序**。它本身就已经是"组合"了。
- 在它上面再叠一层"组合技"，等于给同一个东西起两个名字。
- 而且第二层一旦存在，会误导人以为"术式只是把技能排成一列、组合技才是带逻辑的那种"——
  正好反了：**带逻辑的那个就是术式**。
- 将来分享码发的是一份**术式**（外加它引用到的技能和状态），不需要额外的容器。

所以 `Combo` **删除**（不是搬家），`Technique.combos` 一并删掉，
`PLANNED.md` 里那一节改成"零、已经删掉的"讲清为什么。

## 二、真正的活：`links` —— 把"编程"落到引擎里

玩家给的例子是这句话的结构：

```
向指向方向位移（技能） → 若触碰到敌人 → 释放冲击（技能）
```

以前这条写不出来。`skills: string[]` 只能表达"一串按顺序执行的技能"，
**段与段之间没有门**。加的东西是：

```ts
export interface SkillLink {
  if?: Condition[]     // 满足才进下一段
  note?: string
  elseTo?: number      // 不满足跳哪儿（只能往后跳）
}

export interface Technique {
  skills: string[]
  links?: SkillLink[]  // ⚠ 平行数组：links[i] 管的是 skills[i+1]
}
```

### 三条设计决定

**1. 条件不成立 = 跳过那一段，不是"释放失败"。**
这是最关键的一条。如果没碰到就整个施法失败，那"位移过去、没碰到就白冲一次"
会变成一个纯惩罚，作者没有任何办法表达"没碰到也把位移走完"。
写成"跳过"，那么：

- 没碰到 → 位移照跑，第二段不跑，施法正常结束
- 碰到了 → 两段都跑

**同一个机制覆盖两种情况**，不用再分叉。`elseTo` 也留着，将来要写
"没碰到就走另一条分支"时不用改引擎。

**2. `links[i]` 管 `skills[i+1]`，第 0 个技能永远执行。**
总要有个起点。所以 `links` 的长度是 `skills.length - 1`，校验器盯着这一条。

**3. 编译之后下标必须重新对齐。**
`compileTechnique` 会把多个技能的阶段接成一条时间轴，`links` 也得跟着搬。
我第一版按**编译后阶段的下标**找门，错了 —— 一个技能可能有三个阶段，
`links[0]` 会被安到"第 1 个阶段之后"而不是"第 1 个技能之后"。
现在的做法是编译时按下标 `i > 0` 逐个 push，运行时按 `skillIds.indexOf(skill)` 找门。
下标错一格，"冲到了才炸"就会变成"炸完了才判断"。

## 三、"碰到了"这个条件从哪来

`prevHit` 问的是"**上一段技能碰到了人没有**"。这里有个陷阱：

**纯位移技能不作用于任何人。** 它只是把自己挪过去，一个动作都没有。
如果"碰到"只能由"动作命中"来记，那玩家给的例子根本写不出来 ——
位移段永远算没碰到。

而这个游戏里**本来就没有实体碰撞**（人会互相穿过去）。
所以补了一个最小版本的接触检测（`markContactHit`）：
施法期间每个 tick 看一眼，施法者和某个**合法目标**（按术式的 `targeting.valid` 判）
挨得足够近（双方半径 + 0.15m 余量）就算碰到了。

只在**有施法在进行**时跑，所以"站在敌人旁边"不会凭空算数 ——
得是某一段技能正在执行的那段时间里挨上的。

于是 `hitSkills` 有两个来源，缺一不可：

| 来源 | 什么时候算"碰到" |
|---|---|
| `markSkillHit`（在 `pickActionTargets` 里） | 这一段技能的**动作**作用到了除自己以外的单位 |
| `markContactHit`（每 tick） | 这一段技能**执行期间**挨上了合法目标 |

### 踩了三个坑

- **`prevHit` 一开始恒为 false。** `previousSkillOf` 往回找一个**不同 owner** 的阶段，
  可是判定发生时 `phaseIndex` 还停在上一段（它的所有阶段 owner 都一样），
  于是往回找永远返回 `undefined`。改成读**当前阶段**的 owner 就对了。
  这个是验收测试抓出来的，不是我看出来的。
- **`impact-burst` 第一版写的是"身周 2.5 米炸一圈"（`area`）。**
  测试当场红：等第二段跑起来的时候人已经冲出去 6 米，敌人被甩在身后 4.8 米，
  自己脚下那圈**根本炸不到它**。改成不带载体、直接打锁定目标。
  这是"位移 + 后续"这类组合的通病：第二段的载体中心是**位移之后**的位置，
  不是撞上的那个位置。**现在没有"记住撞上那一点"的机制**（见欠账）。
- **投射物没法被 `prevHit` 门控。** 投射物落地时施法早就结束了，
  `cast` 已经不在，门也就不用过了。所以玩家那个例子的第二段必须是**瞬发**的。

## 四、顺带修掉的两个"承诺了但没做"

### 投射物以前只能是 `damage`

`pipeline.ts` 里投射物分支写在 `switch (payload.kind)` **里面**，
只有 `damage` 那一支会走到。也就是说：

```json
{ "delivery": { "kind": "projectile", … }, "payload": { "kind": "status", … } }
```

**会被静默地就地生效** —— 作者以为扔出去一个会飞的状态，实际当场挂在锁定目标身上。
把投射物分支提到 switch **之前**（`spawnProjectileFrom(ctx, action)`），
现在**任何载荷都能当投射物**。

### 校验器的 `NO_DELIVERY` 警告一开始全是假警报

加了一条警告：伤害/治疗动作**没有载体**时，打的是"锁定的目标"，
什么都没锁定时会退化成打自己。第一版报出 4 条，其中 3 条是错的。

问题在于**检查必须知道语境**：

| 挂在 | 无载体的伤害打谁 | 该不该警告 |
|---|---|---|
| `onHit` / `onKill` / `onDamaged` … | 这次命中的那个单位 | **不该**，这是正确用法 |
| 状态钩子里（任何时机） | 状态持有者或这次命中的另一方 | **不该**，一定是合理的对象 |
| `phaseComplete` 这类 | 锁定目标，可能没有 → 打自己 | **该** |

所以 `LocatedAction` 现在带上了 `when` 和 `inHook` 两个语境字段。
改完从 10 条警告降到 7 条，剩下的 `NO_DELIVERY` 只有 `impact-burst` 那一条 ——
而它正是**故意不带载体**的，警告说的就是实话。

## 五、出厂内容

新增两个技能 + 一个术式，就是玩家那句话的字面翻译：

| | |
|---|---|
| `skill.charge-dash` 突进 | 纯自我位移 6 米，`energy 10 + cooldown 8`。**一个动作都没有** |
| `skill.impact-burst` 冲击波 | `energy 20`，**故意不带载体**，对锁定目标 25 点物理 |
| `tech.charge-impact` 冲撞冲击 | `skills: [突进, 冲击波]`，`links: [{ if: [prevHit], note: '冲到了才炸' }]` |

它现在挂在 `arena.json` 的技能栏上，可以直接按键试。

## 欠账

- **没有"接触点"记忆。** "位移 + 后续冲击"的第二段只能打**锁定目标**，
  打不到"撞上那一下的坐标"。要做得给 cast 存一个 contact point，
  或者在接触判定命中时推一个事件。玩家给的例子现在能跑，是因为它打的是"撞上的那个人"。
- **投射物不能过门。** 见上面第三节。要支持的话得让"门"在投射物落地时也能判，
  而那时 cast 已经结束 —— 等于要给门一个独立的生命周期。
- **`elseTo` 零内容。** 字段实现了、校验器认它、能往后跳，但没有内容用。
  等真需要"没碰到走另一条分支"的时候再验。
- **定价还没管 `links`。** 一个带条件的段和一段无条件的段现在**同价**，
  但"碰到了才生效"显然比"一定生效"弱。这是下一个该补的计价项。
- **`Combo` 的删除还留了个尾巴**：`docs/log/2026-09-23-15` 那篇里
  它仍记在"搬到 PLANNED 的类型"表里，我加了划线说明，
  但更早的日志就保持原样了 —— 日志是当时的记录，不改。
