## 一、先说最要紧的那条：左键为什么放出蓄斩

**代码里有一条重复的旧路径。**

`applyInput()` 里还留着"左键 = 技能栏第 1 格"时代的写法：

```ts
if (pointerDown) { pointerDown = false; pressCast(loadout[0]) }   // ← 旧路径
```

上一轮我加了"左键 = 手上武器的普攻"（`pressWeapon`），**但没有删掉这一段**。
于是按一下左键会同时做两件事：放武器普攻 + 放第 1 格的术式（arena 里是蓄斩）。

现在左键只有一条路。`pointerDown` 这个标志整个删了 —— 它只剩那一个用处。

⚠ 顺带说第 2 条：**蓄斩本来就是术式**（`tech.charge-and-slash`，
由 魔法飞弹 → 裂地斩 两个技能组成），引擎里从来没有把它当技能。
玩家之所以会这么问，是因为**界面上没有任何东西说明哪一栏是什么**：
技能栏没有标题，而底下那行提示写的是「1~5 放技能」。
现在 HUD 上写着「**术式栏**（1~0 按顺序）· 左键 是手上武器那套」，
技能编辑器的页签也从「技能（零件）/ 术式（成品）」改成了「技能 / 术式」。

## 二、整理：所有描述相关的错误（一共 9 类）

| # | 症状 | 根因 | 现在 |
| --- | --- | --- | --- |
| 1 | 技能编辑器没有"这个技能是干什么的" | 页面只有点数条和滑块 | 顶部加了**技能介绍**：一句人话 + 时间线（前摇 0.5 秒（花 30 能量）→ …） |
| 2 | 左键放出 1 号键的术式 | `applyInput` 里旧的 `pointerDown → loadout[0]` | 删掉，左键只有一条路 |
| 3 | 看不出哪一栏是技能、哪一栏是术式 | 技能栏没标题、提示写"放技能" | HUD「术式栏」+ 页签「技能 / 术式」+ 帮助行写明左键/F/1~0 |
| 4 | 阶段名故弄玄虚（编织/成形/沉腰/布火…） | 内容里的 `phases[].name` 是文学化的 | 全部改成 **前摇 / 命中 / 后摇 / 蓄力 / 常驻**（25 个文件） |
| 5 | 滑块标题是 `note · #0 · 值` | ① 手写 note 当标题 ② 数组下标漏出来 ③ `const` 兜底叫"值" | 三段式 **`时机 · 效果 · 数值名`**：`命中 · 击退 · 距离` |
| 6 | 说明里出现 `status.shield` / `entity.skeleton` | id 没被翻成人话 | `DescribeNames`（状态库 + **内联状态** + 实体预设） |
| 7 | 说明里出现 `char.bloodPact.current` | `describeAttribute` 的兜底打了路径原文 | 血契 / 能量 / 生命…；认不出来的写「某个属性」，**不打路径** |
| 8 | 说明里出现 `pipeline.cancelled 1` | 伪属性没名字 | `pipeline.*` 有了人话表（取消这一下 / 这一下的数值…） |
| 9 | 曲线被念成坐标：`蓄力量（0→20，3→150）` | 把数据原样搬进句子 | 说成**范围**：`按蓄力量 20~150 造成伤害` |

外加两条小的：
- 「前摇」这种阶段名以前带书名号（`「前摇」结束时`），两层括号像代码 → 现在是 `前摇结束`
- 挂状态里的修饰符标题是 `挂状态 · 状态数值 0.5`（不知道改的是什么）→ 现在从 `path` 推：`挂状态 · 移速`；管线阶段名也从 `modify 阶段` 改成「修正阶段」

## 三、为什么标题是这三段

玩家点名的那条 `捅中的人被挑飞出去 · #0 · 值` 拆开看是三个毛病，
所以新格式对应三段，**每一段都必须是数据推出来的**：

| 段 | 来源 | 例 |
| --- | --- | --- |
| 时机 | `describeWhen`（和规则那一行**同一个函数**） | `命中` / `未命中时` / `每 0.5 秒` |
| 效果 | `effectName(payload)` | `伤害` / `治疗` / `击退` / `挂状态` |
| 数值名 | 字段名 + 效果类型 + 属性路径 | `距离` / `长度` / `时长` / `移速` |

结果：

```
命中 · 伤害 · 长度        4 m
命中 · 伤害 · 宽度        0.6 m
命中 · 伤害               30 点
命中 · 击退 · 距离        2
未命中时 · 位移 · 距离    2
```

⚠ **手写的 `note` 不进标题**：它是设计意图（"捅中的人被挑飞出去"），
仍然显示在规则那一行的小字里 —— 那是它该在的地方。

⚠ 数组下标（`#0`）现在**只在认不出来的时候出现**，而且改成「第 2 项」；
认不出来的数组项干脆不占标题位置 —— 宁短一点，不要噪声。

## 补：技能介绍字段（玩家当场定的）

日志写完的当天，玩家回了三句：

> 1 加，不必一句话，要介绍清楚。
> 2 不必。（指 `_comment` 不进界面）
> 3 （两个新技能的点子 —— 见 `docs/skill-ideas.md` 第六节）

**第 1 条已经做了**：

- `Skill.note` 这个字段**本来就在 schema 里**，但**零内容使用、零代码读取** ——
  又一张空头支票。现在它有了明确身份：**技能介绍，显示在编辑器最上面**，
  而且**允许手写**（唯一一处）。
- ⚠ 手写的代价是老问题：数字会和数值脱节。所以校验器加了
  `NOTE_WITH_NUMBER`（介绍里出现数字就警告），而"造成 30 点伤害"那类
  仍然由 `describeRule` 生成、显示在介绍下面。
- 编辑器里它是**可编辑的 textarea**（写回 `Skill.note`）——
  面板上看得见的每一件东西都该能改，不然它就变成"藏在代码里的字"。
- **29 个技能的介绍全写上了**（27 个技能 + 2 个武器技能模板）。
  测试盯着：每个技能都有、不含数字、不是敷衍的一句、不含 ASCII 引号。

**第 2 条**：`_comment` 不进界面，只在内容文件里给作者看。

## 欠账

- **技能介绍是手写的**，所以它和"改了数值说明跟着变"那条规矩是**例外** ——
  这是有意的（玩家要的就是"介绍清楚"，生成不出来），代价靠
  `NOTE_WITH_NUMBER` 警告兜住。⚠ 如果哪天发现介绍里的说法和数值对不上，
  先看那条警告是不是被忽略了。
- **两个新点子（屏障 / 标记瞬移）只做了"逐块核过"，没有实现** ——
  结论写在 `docs/skill-ideas.md` 第六节：屏障走"召唤一个不会动的单位"
  今天就能做，要做长墙得补积木；标记瞬移差两块积木
  （**以目标为锚的落点** + **按状态选目标**）和一个小补丁
  （`sequenceLinks` 的条件运行时没读）。
- **`_comment` 仍然只是给作者看的**（玩家明确说不必进界面）。
- **英文键名还有漏网的**：`payload.mode` 的一些取值（比如 `setVisibility`）
  在别处可能还有没翻译的，见到就补。
