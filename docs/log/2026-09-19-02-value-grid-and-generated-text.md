# 滑块改成点表 + 说明改成生成的

- **日期**：2026-09-19
- **触发**：玩家报的两件事 ——
  「数值选择的滑条不必有那么多取值，大部分用三五个取值就够了，最多也不要超过 10 个」
  「『命中时回复 8 点生命』，在调整数值之后这个 8 应该改变，但它没有」
- **动了哪些文件**：`web/src/leaves.ts`、`web/src/editor.ts`、`src/describe.ts`(新)、`src/validator/checks.ts`、`src/cli/run.ts`、`content/skills/*`（18 处数值）、`tests/describe.ts`(新)、`tests/editor.ts`

## 改了什么

### 1. 滑块从「区间」改成「点表」

原来 `min/max/step`：0~300 的伤害滑块有 300 个取值，拖一格差 1 点 ——
**既调不准，也没有"选择"的感觉。**

现在每个字段一张点表：

```
伤害      10 / 15 / 25 / 30 / 50 / 200
阶段时长  -1 / 0.1 / 0.2 / 0.3 / 0.5 / 1
状态时长  -1 / 0.5 / 1.5 / 3 / 5 / 10 / 25
冷却      1 / 2 / 3 / 8 / 20
```

实测 **平均 5.6 档、中位 5 档、85% 在 6 档以内、最多 7 档**。

三处必须分开的表：**倍率**（`op:'mul'` 的格子在 1 附近）、
**阶段时长 vs 状态时长**（零点几秒的节奏 vs 几秒到半分钟）。

### 2. 数值说明从「手写」改成「生成的」

`Rule.note` 里的数字和真实数值是**两份会漂移的东西** —— 和"点数手写"是同一个错误。
新增 `src/describe.ts`：

```
JSON：{ "when": "onHit", "then": [{ "target": "self",
         "payload": { "kind": "heal", "amount": { "const": 10 } } }] }
面板： 命中时 回复 10 点生命（自己）
```

拖成 20，那句话当场就是 20（`refreshLive()` 就地更新，不整块重画 ——
重画会让正在拖的 `<input>` 被换掉，浏览器立刻停发 `input` 事件）。

`note` 保留但只写**设计意图**，校验器加 `NOTE_WITH_NUMBER` 拦手写数字。

### 3. 每个数值带单位（同批）

时长 `s`、距离 `m`、速度 `m/s`、张角 `°`。距离尺度是**自洽**的：
场地半径 18 m、人 0.5 m、挥砍 2.5 m、跑速 6 m/s。

## 为什么

- 玩家要的是"选择"而不是"微调"。档位之间必须有可感知的差别。
- 说明和点数一样，**必须是内容的函数**。手写就一定会脱节。
- 出厂内容全部落在格子上是**硬要求**：格子外的值会被临时插进来、面板上标黄点，
  那等于给某一个技能开后门。为此挪了 18 处次要参数（最多动 25%）。

## 验证

`typecheck` 0 错 · `npm test` 362 个断言全绿（新增 `tests/describe.ts` 36 条，
第一条断言就是玩家报的那个 bug）· 滑块分布作为断言钉住 ·
改名刀、熔岩护甲的反伤等 18 处后重新标定，残差 1.47。

## 欠账

- 挪了 18 个数值，**手感会变**（裂地斩总时长 0.6→0.5s，飞弹射程 14→18m），
  要等玩家试过才知道合不合适
- 贯日光束还没有特效（`beam` 是瞬时线段判定，不生成实体，
  客户端得反查朝向补一条线）
