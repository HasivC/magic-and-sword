# 日志 60a · 全量点表：每个技能 × 每个可调变量 × 每个取值 → 一个整数点数

> **这一片只有一件事：把表造出来。** ⚠ 不改引擎（`src/**`）、✗ 不改编辑器 UI（`web/src/**`）、
> ✗ 不改内容里现有数值、✗ 不改测试 —— 那四件事都在**下一片**（改定价：查表 + 相加）。
> ⚠ 上一支代理就是把「生成器 + 引擎 + 校验 + 测试 + 文档」一起做才挂掉的，
> 所以这一片按用户的要求**切成纯数据**：只造表 + 报告。

## 0. 用户定的规格（原话）

> 这个表是描述了每个技能的每个变量的每个取值对应的点数，**定下来玩家改不了**，
> 玩家能做的只有**选择**一个技能的一个变量的某个取值，一个技能的所有变量的取值
> 对应点数的**和（即线性叠加）**就是最终的技能点数……**因此它必须是实际值。**

用词：**用户** = 下这条设计指令、定表的人；**玩家** = 玩游戏的人，只能"选"，改不了表。

## 1. 表住在哪

**`technique-system/content/balance.json` 的新一栏 `lookupTable`。**

形状（技能分区，试点那一份的格式，一个字没改）：

```
lookupTable
  "_这是什么" / "_口径"                    ← `_` 开头的键是文案（本项目惯例）
  "skill.aegis"                            ← 技能分区
      "phases.0.duration"  ← 变量（数值叶子 = 字段路径）
          "-1": 3, "0.1": -1, …, "0.5": 0    ← 取值 → 整数点
      "ruleSlots"
      "@冷却时机"          ← 编辑器里没有字段路径的控件用 @ 开头
          "前摇": 0, "命中": 0, "后摇": 0, "没有冷却": -18
      "@打断等级.0" / "@占用施法者.0"          ← N = 阶段下标
  "skill.armor-pierce" …                    ← 32 份，按 id 排序
```

**为什么住 `balance.json` 而不是新开一个内容文件**（这是判断项，列在第 8 节第 3 条）：

1. **日志 59 已经定过这条**（原话："表住内容侧 = `content/balance.json` 的新一栏，
   ⚠ **不能新开内容文件** —— `validate` 数的就是内容文件个数"）。`tierTables` 就是这么放的。
2. **下一片改引擎时一行加载代码都不用写**：`priceOptionsFor(balance, …)` 已经拿到 `balance` 了。
   要是新开 `content/lookup-table.json`，就得动那三处 `PriceOptions` 装配线去把表传进来 ——
   而用户明说了**这一片不许动它们**。
3. 这张表和 `tierTables` 是**同一种东西**：一张"档位 → 整数点"、一张"技能 × 变量 × 取值 → 整数点"，
   都是**人填的价格表**，都不是内容实体（技能 / 术式 / 状态 / 实体）。

⚠ **`validate` 的文件数因此仍然是 57**（不是 58）：新增的是 `balance.json` 里的**一栏**，
不是一个文件；而那个"新开内容文件"的方案（如果放在 `content/**` 的扫描目录里）
会让校验器把它当成一份技能去校验、当场报错。报告里已写清这一点。

### 1.1 键怎么写（下一片要对齐的口径）

## 2. 每一格怎么起草的（口径）

用户指定的方法，一个字都不改：

> 把该变量设成该取值、**其余变量钉在出厂值** → 用**今天已经算得出来的定价结果**填进去 → 取整

落成一行代码：

```
rowPoints = skillLedger(只改了这一片的那一份, 出厂那一份, opts).total     // src/pricing.ts:2548
```

* **变量清单的权威来源** = `web/src/editor.ts` 今天**真的画出来的控件**：
  数值滑块（调 `leaves.ts:557` 的 `collectLeaves`）、冷却时机（`data-cd-at`）、
  冷却秒数（`leaves.ts:553` 的 `gridOf`）、打断等级（`data-interrupt`）、占用施法者（`data-flag=occupiesCaster`）。
  ⚠ 冷却秒数虽然**不在通用滑块列表里**（`editor.ts:826` 的 `isCooldownLeaf` 把它摘出去了），
  但它由「冷却时机」那一块画 —— 编辑器真的能让玩家改它 ⇒ **它是一个变量**（试点也是这么算的）。
* **取值清单的权威来源** = `web/src/leaves.ts:114` 的 `VALUE_SETS` + `:263` 的 `STATUS_DURATIONS`
  （`duration` 按"在不在 `phases` 里"分两张表）；「没有冷却」和三个打断等级住在 `editor.ts` 自己。
* **整数**：账的出口本来就是整数（日志 57：逐条取整 + 最大余数法 + 每个非零条目至少 1 点），
  所以**起草值 = 今天真的算出来的那个数** —— 没有第二套算法（那正是本项目最恨的漂移）。
* ⚠ **每一格都钉死一个前提：其余变量一个字不动**。这条前提**不能去掉** —— 见第 8 节第 7 条。

   ⚠ 本片选"有"的理由：编辑器对**每一份有阶段的技能**都画那一块，
   点一下"前摇"就真的加上了 3 秒冷却、账上真的变 ⇒ 玩家能做这个选择，表里就必须有这一格。
   **要用户点头。**
5. **哪些变量算"可调"**：本表算了 377 个 = 数值叶子 229 + 冷却时机 32 + 打断等级 58 + 占用施法者 58。
   **没进表**：① 编辑器调色板 `TEMPLATES`（6 个"加一条规则"模板 —— 可以**反复加**、
   条数不设上限 ⇒ 变量个数本身不固定；而且模板数值住在 `editor.ts` 的代码里、**没有导出**，
   `web/src/**` 冻结 ⇒ 脚本读不到）② 技能名字 / 技能介绍（自由文本，无价）
   ③ `curve` / `targeting` / `tags` / 位置（编辑器**故意跳过**：`SKIP_SUBTREES` / `SKIP_KEYS`）
   ④ **阶段的增删**（编辑器没有这个控件 —— 但定价里"删掉一段"是**有价**的）
   ⑤ 修饰零件参数与武器属性（住在术式副本 / 武器里，连续取值）。**这五样要不要进表，请用户裁。**
6. **一整列都是 0 的变量**：377 个变量实例里有 **93 个**的整列取值（含出厂格）**全是 0** ——
   也就是"编辑器让它可调、但今天的定价函数一个数都不动它"。
   典型：`effect.0.then.0.delivery.width`（命中 · 伤害 · 宽度）、三个 `@占用施法者.N`、
   状态持续、召唤数量、投射物速度 / 存在时间 / 半径、张角、血契额度……
   是要给它们定价，还是承认"它们不参与定价"？**请用户裁。**
7. **打断等级的三档在整数账上被压平**：`control` 和 `none` 的原料差一倍
   （`uninterruptiblePhase × 0.5` vs `× 1`），但"每个非零条目至少 1 点"把两档都印成 ±1
   ⇒ 用户看不出差别。要不要拉开？**这是判断，我没动。**
8. **表里的数全是"今天算出来的"**，而今天这份引擎**只对"单改动"有意义**。
   如果用户要的是"表是定义值、玩家选完就按加法算"，那**下一片**要做的事是
   （a）定价改成查表 + 相加、（b）把所有能力（`skillLedger` 那一套）接到表上、
   （c）`@冷却时机` / 打断等级 / 占用施法者 这几个 `@` 变量在引擎里的读法要对齐第 1.1 节那张表。
   ⚠ 这一片**没做**，也**不该做**。

## 9. 坑（⚠ 留给下一个人）

* **`@冷却时机` 的"没有冷却"那一档很贵**（破军突刺：−18 点）—— 因为账上那一行
  **还减掉了这一段自己的价**（`pricing.ts:2531` 那段说明），它比 0 档本身的价更负。
  别以为是算错了。
* **采集 `battle` 的哈希一定要 "文件非空 + 哈希" 一起看**，而且要说清编码
  （`Out-File -Encoding utf8` 在 PS 5.1 下是 **BOM + CRLF**）。
* **别用 `JSON.stringify(balance)` 重写 `balance.json`**：整数键会被重排（见第 7 节那段）。
* ⚠ **表里一个变量的"取值顺序"不是编辑器滑块的顺序**：JSON / JS 会把**整数字样的键**
  排到前面（`phases.0.duration` 的 `"1"` 跑到 `"-1"` / `"0.1"` 前面）。**顺序要从
  `leaves.ts` 的 `VALUE_SETS` / `collectLeaves` 取**（那是权威），**别从表里读顺序**。
  键本身（`"-1"` / `"0.1"`）不受影响，查表是按键查的。
* **`npm` 不能用 `npm.ps1`**（这台机器禁止运行脚本）⇒ 用 `npm.cmd`。
* 脚本住在 `.scratch/pt60/` 下（`gen.mjs` / `check-diff.mjs` / `verify-untouched.mjs` /
  `count.mjs` / `cmp-validate.mjs`），**不参与**任何测试 / 校验 / 打包。
