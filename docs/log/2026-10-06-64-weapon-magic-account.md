## 改了什么

### 1. 判据落在**一处**：`src/school.ts` 的 `techniquePaysPoints(tech)`

```ts
export function techniquePaysPoints(tech: { kind?: unknown }): boolean {
  return tech.kind !== 'weapon'
}
```

⚠⚠ 它**只读 `kind`** —— 也就是 `deriveTechniqueKind` 的产物（"目录 → 系别"这条规则本来
就只有 `school.ts` 一处：`schoolOfSkillFile` / `deriveTechniqueKind` / `hasValidKind`，
内容 JSON 里 `kind` 是显式字段，校验器再拿技能自己的系别核对它）。
**没有新写第二份判据**（用户硬命令）。

| 术式 | 账 | 为什么 |
| --- | --- | --- |
| **武器术式** | **不算账** | 数字来自**武器本身**（`weapon.damage` / `reach` / `windup` 由装上的那把武器代入），定价器看不见那把武器 |
| **魔法术式 · 主动** | **算账** | 效果花额度、代价给额度 |
| **魔法术式 · 常驻** | **算账** | 常驻 = "不响应按键"，**不是免费** |

### 2. `src/pricing.ts`

- `priceTechnique` 开头按判据分流：**武器 ⇒ 直接返回一本空账**（`entries: []` / `total: 0`）。
  ⚠ 空账 **≠** "0 点免费"：前者是"根本没有这本账"，后者是"真的算过、刚好平"。
- `bloodPactCostOf` **删掉** `if (isWeaponSide(tech, lookup)) return 0` ——
  血契从此**只从账里读**（账空 ⇒ `kind` 是 `normal` ⇒ 自然 0）⇒
  "校验器说它不算账、绑上键却扣血契"这类漂移**在形状上不可能**。
- **旧的 `isWeaponSide` 整个删掉**（并在原处留一段"这里原来有什么、为什么删"）。
  它是**第二份**判据（"引用了 `readonly` 的技能吗"，看**技能**），和新的这份（看**术式**的系别）
  在**合法内容**上永远一致，但在**没写 `kind` 的老数据 / 系别写错的坏内容**上会分叉 ——
  而分叉的后果就是这个项目最恨的那类静默不一致。

### 3. `src/validator/index.ts` 那条 `priceless`

- **判据**：旧的 `hasSkills && isWeaponSide(tech, …)`（看有没有**序列**那句话在下面）⇒
  换成 `!techniquePaysPoints(tech)`（看**系别**）。
- **文案**：旧的"序列术式不算账 —— 它的技能内联在每一条序列里，而序列段**不进点数账**"
  ⇒ 换成"**武器术式不算账** —— 它的数字来自**武器本身**…
  ⚠ **"不算账"不等于"0 点免费"**：它的强度体现在**装到哪把武器上**"。
- `priceable` **去掉 `hasSkills` 那道闸**（改成 `(hasSkills || hasSequences)`）：魔法术式
  **不论技能挂在自己这一层、还是在段里**都要算账（空的术式仍然不算 —— 那句老注释保住了）。

### 4. `web/src/technique-editor.ts`（**只有取账 / 显示**）

- 术式库那一行：武器术式写 **「不算账」**，不写"0 点"。
- 账卡：判语改说"武器术式不算账 … ⚠ 这不是'0 点免费'"，"合计"那一行的说明同步改。
- ⚠ **布局 / CSS / 控件 / 结构一个字节没动**；判据用的还是文件里**本来就有**的 `kindOf(t)`
  （读 `Technique.kind`）。
- ⚠ **为什么这一页会自动跟着变**：术式页那本账读的**就是** `src/pricing.ts` 的
  `priceTechnique`（该文件里 5 处调用：`ledgerCache` / `pointsByPath` / `patchLedger` /
  `ledgerCardHtml` / 屏 3 那一处）—— 一片都没有另立算法 ⇒ 数字自己就对了，
  补的只是"说出来"的那一半。

## 为什么

1. **旧规矩跟真相脱节，而且两头都说反了、一声不吭**：
   - 一份**魔法**术式只要挂了序列（内联之后几乎人人都挂）就被说成"不算账"，
     而它的账**一直在算**（段上的修饰进账）、血契也照扣；
   - 一份**武器**术式反倒拿不到"武器侧"那句话 —— 它自己那一层没有 `skills`，
     旧判据（`hasSkills && …`）根本走不进去。
   ⚠ 出厂实测：被旧规矩误判的是 `tech.last-stand`（**常驻**）与 `tech.mark-blink`（**主动**）
   那两行 —— **都是魔法术式**。
2. **同一份术式两本账**（探针实测，见"验证"）：武器术式 + 多重释放 ×10 ⇒
   **编辑器那本显示 −18 点、校验器说"不算账"**，两边都不报错。
3. **判据只有一处**：项目最恨"两份判据漂移"，所以把"是武器术式吗"这个问题
   收进 `school.ts` 一处，账 / 血契 / 校验器 / 界面全部读它。
