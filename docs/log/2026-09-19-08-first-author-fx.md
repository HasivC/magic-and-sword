## 先查了一下素材（结果：导出做对了）

写了个 `tools/check-fx.ts`，**解码 PNG 逐像素看**，而不是靠眼睛：

```
12 帧  ·  256×256  ·  带 alpha
内容中心 (127.5,127.5) = 画布中心  ✓ 居中
完全透明的像素 平均 68.2%      完全不透明的像素 平均 2.7%
! 有 2 张空帧（_00000 和 _00011）
```

结论：**背景是透明的、内容居中** —— `blend: "add"` 和 `anchor: [0.5,0.5]` 都成立。
唯二值得说的一处：**光刺顶到了画布边缘**（有几帧 bbox 到 0 和 255），
可能被切掉了一点。空帧是 AE 补零的正常现象。

**这个检查器值得单独说**：它查的四件事（背景没透明、画面被裁、空帧、命名对不上）
**全都不会报错**，只会让特效"看着不对"。所以要有工具看一眼。

## 接的时候发现两个必须补的洞

### 1. 玩家用的是 `00000` 起编号，我写死了从 1 开始

`frameUrl` 原来是 `String(index + 1).padStart(pad)`。
AE 默认从 **0** 开始编号，所以整条特效会 404 —— 而报错只说"读不到图片"。

加了 `start` 字段（默认 1）。这不是为了迁就一个人，
而是**导出的编号起点是作者的自由，不能猜**。

### 2. 命中火花**根本触发不了** —— 投射物不发特效事件

上一轮我明确让投射物**不**发 `deliveryFired`（它自己是实体，客户端已经在画了）。
但命中是**另一件事**：火花得打在目标身上。

所以：
- `ProjectileSpec.vfx` / `damageType` 跟着子弹带出去
- `projectile.ts` 在**落地**时发 `deliveryFired`，坐标是**目标位置**
- 客户端：投射物命中**没有素材时什么都不画**（命中本来就有粒子、飘字、顿帧，
  再叠一层是噪声）；有素材才画

现有内容一条都不受影响 —— 没写 `vfx` 就不发这条事件，测试盯着。

## 顺手整理的

- **`FxDef` / `frameUrl` 从 `assets.ts` 搬到 `fx.ts`**：定义和命名是**纯数据**，
  能离线测；`assets.ts` 碰 `fetch` / `new Image()`，只有浏览器能跑。
  分开的直接好处是 `frameUrl` 这种最容易拼错的地方**能被测试盯住**了。
- `tests/fx.ts` 加了「定义里的帧数必须等于磁盘上的 PNG 数量」「从 start 拼出来的每一帧都要真的存在」。

## 为什么

- 玩家说"我自己做"，那**工具得配得上**：素材进不来、进来了触发不了，
  等于白做。
- 检查器不是锦上添花：那四类问题**全都不报错**，
  没有工具就只能等玩家说"怎么不对劲"。
