# 框架三件事：目标选择真的做了、状态有了视觉、计划层搬出 schema

- **日期**：2026-09-20
- **触发**：`docs/framework-audit.md` 末尾那三个待拍板的问题，玩家答：
  **「1，真的做出来。2要。3搬」**
- **动了哪些文件**：见每一节末尾

## 一、`targeting.mode` 真的做了（第 1 件）

### 之前为什么是空的

审计查出来：`TargetingMode` 的**五个取值全部惰性**。
它只出现在 schema、校验器白名单、和一个测试 fixture 里 ——
引擎**从不分支**。

根因不是"忘了写 switch"，而是**架构上没给它留位置**：
目标选择是**调用方**做的（客户端自己算"射程内最近的敌人"再传 `targetId`，
AI 自己挑 `targetId`），引擎只负责"按形状找谁"。
调用方已经决定完了，`mode` 读不读都一样。

### 所以做法是：把"解析"从调用方收回到引擎

新增 `resolveAim(world, caster, targeting, intent)`（`src/sim/targeting.ts`）：

```
调用方给「原始意图」          引擎按 mode 解析
─────────────────────       ──────────────────────────
none / direction / point     → 从哪儿发、朝哪、锁了谁
/ entity
```

| mode | 怎么选 |
|---|---|
| `self` | 不用选，中心就是自己 |
| `directional` | 不锁朝向，朝意图给的方向；顺手记下"正对着的目标" |
| `locked` | 挑**最靠近瞄向**的合法目标，**朝向掰过去**；挑不到退回朝向 |
| `auto` | 挑**最近**的合法目标（不看瞄向），朝向掰过去 |
| `areapoint` | 中心落在**地上那个点**，超出射程**压回边缘** |

### 三个设计决定，都有理由

**（1）锁不到目标时退回朝向，而不是失败。**
"按了没反应"比"打空了"难受得多 —— 打空至少有特效和反馈。

**（2）超出射程压回边缘，不是拒绝释放。**
玩家对着屏幕边缘点很常见，因为这点误差就"按了没反应"会很恼人。

**（3）`directional` 也顺手记一个目标，但不改朝向。**
没有载体的动作（"只挂个状态"）判定走 `[ctx.target ?? ctx.actor]` ——
没有 target 会**打到自己**。以前这个活是客户端干的，而那正是两套逻辑的来源。

### 载体要支持"点"而不是"人"

`resolveTargets` 的 `AreaQuery` 加了 `originPoint`：
载体中心可以是**一个坐标**而不只是某个实体。火墙、暴风雪、传送门都要这个。
四种形状（扇形 / 圆形 / 光环 / 线段）共用同一套几何，只是中心不同。

### ⚠ 踩了一个真 bug，靠 `duel` 基准抓到的

第一版把 `resolveAim` 的 `point` 和 `facing` **无条件**喂给命中判定。
后果：前摇 0.3 秒里人已经走开了，而挥砍还砍在**施法那一刻的坐标**上 ——
`duel` 里的剑士当场**打出 0 伤害**（基准是 129）。

修法是给结果加两个**显式开关**：

| 开关 | 只有谁是真的 | 为什么 |
|---|---|---|
| `pointFixed` | `areapoint` | 火墙钉在地上；挥砍/光束要**跟着人走** |
| `facingLocked` | `locked` / `auto` | 锁定才有"掰朝向"这回事；directional 的挥砍要跟着人转 |

改完 `duel` **逐字节回到基准**（67.6 / 71 / 129 / 232.4 / 5 / 8）。
这两个开关现在有专门的测试盯着（`pointFixed` / `facingLocked` 各四条断言）。

### 客户端和 AI 都改成"只给意图"

- **客户端**：删掉了 `nearestEnemyInRange()` —— 那份"射程内最近的敌人"
  就是 `mode` 变成死字段的直接原因。现在只给鼠标方向，或者
  `areapoint` 时给鼠标那块地。
- **AI**：按 mode 给意图（点地面就把落点放目标脚下）。
  **"AI 会放地面技能"不需要另写一套** —— 这就是收回到引擎的好处。
- **瞄准指示**：手里那个技能是点地面时，画的是**落点圆圈 + 射程圈**，
  而不是方向线（方向线对地面技能没有意义）。超出射程的落点显示成红色，
  因为引擎会把它压回边缘，玩家得知道实际落在哪。

### 内容：`火墙`（第一个点地面技能）

`content/techniques/flame-wall.json` 用 `mode: 'areapoint'`, `range: 9`。
校验器新增一条：**`areapoint` 必须写 `range`** ——
那里的 range 不是"打得到多远"而是"落点最远放多远"，
不写的话可以隔着半张地图放火墙。

### 顺带修掉的一个真 bug：投射物只认 damage

改瞄准的时候，`battle.ts` 里一条"子弹命中后挂状态"的测试红了。
查下去发现：`executeAction` 里那行是

```ts
if (p.kind === 'damage' && action.delivery?.kind === 'projectile')
```

**只有 damage 载荷能被射出去**。一个 `status` 载荷写了 `projectile`，
那个 delivery 会被**静默忽略**，变成"立刻命中锁定目标" ——
技能照样能用、状态照样挂上，所以没人会发现箭根本没飞。

修法：把投射物分支提到 switch **之前**，对**所有载荷**通用
（唯一例外是管线伪属性 `pipeline.amount`，它改的是当前这次命中，必须当场生效）。
新增 `spawnProjectileFrom()` 承担这件事。

## 二、状态有了视觉（第 2 件）

`StatusDef.vfx` 以前是死字段：声明了、15 处内容写了它，
但（a）`ActiveStatus` 根本没抄它，（b）就算抄了也**没有素材**
（`fx.sunder` 这些名字一条 PNG 都没有）。

三处改动：

1. **`ActiveStatus.vfx`** —— `makeActiveStatus` 从定义里抄过来。
   客户端遍历 `entity.statuses` 就能知道"谁身上有什么"，
   不需要事件、不需要查表。
2. **`web/src/fx.ts` 的 `pickStatusStyle(tags)`** —— 按标签上色的**有序**表：
   `hardCC` → 冰蓝、`shield` → 金、`dot` → 绿、`debuff` → 红、`buff` → 绿。
   **顺序就是优先级**：一个"冻结"同时带 hardCC 和 debuff，
   "被冻住了"是玩家最需要一眼看见的，不该被"这是个 debuff"盖掉。
3. **客户端画两种东西**：
   - **常驻光环**：每个状态一圈，按序号往外错开（不错开的话三个状态完全重合，
     看起来只有一个）；跟着 `world.tick` 呼吸，暂停时也停。
   - **挂上那一下的爆闪**：颜色和光环**同一个来源**，不然"落上去"和
     "挂着"会是两种颜色，看起来像两个东西。

⚠ **没有素材也看得见** —— 这是有意的。和载具特效那条"两条路线并存"一个立场：
**程序化是保底，素材是加分项**。你以后做了 `fx.frozen` 的序列帧，
它就能叠在光环上面，而在此之前机制不是隐形的。

`validate` 的警告因此从 **17 条掉到 5 条**（15 条 `vfx` 警告全部消失，因为不再是死字段）。

### 顺便说一个我写砸又改回来的地方

画内盘（护盾、冻结那种"重"状态才画）的时候，我第一版写的是
`style.feel.startsWith('金色')` —— **拿给人看的文案当判断依据**。
改一个字就会静默改变画面。改成显式的 `heavy: boolean` 了。
文案是文案，行为是行为。

## 三、计划层搬出 schema（第 3 件）

新建 `schema/PLANNED.md`，把**引擎里出现 0 次**的类型搬了过去：

| 搬走的 | 原来在哪 |
|---|---|
| ~~`Combo`（可分享的技能组）+ `Technique.combos`~~ | §10 —— **第二天又整个删掉了**，见下一篇日志 |
| `ComboChain`（近战连段）+ `WeaponDef`（武器） | §11 |
| `SkillSource`（技能来源） | §12 |
| `Build`（构筑） | §13 |

**理由**：schema 是"技能作者照着填的东西"，照着填就会期待它生效。
一个没有任何引擎实现的类型留在里面就是一张空头支票。
文档标题写清了"**引擎还没实现**"，并给了它们回来的依赖顺序
（输入层 → 连段 → 武器 → 来源 → 构筑），每一步的判据都是
**引擎里真的有代码读它了**。

### 另外删了 `Cost.bloodPact` —— 这个不是"计划"，是**冗余**

它和**已经算出来的** `PriceResult.bloodPactPerUse`
（超模的那部分点数）是同一个东西，而那个手写字段**零引用、零内容**。
整份代码的立场是"点数全部是算出来的，一个字都不存进 JSON" ——
第一版手写的 `points` 就是这么被删的。手写的血契是同一个错误。
（"血契"这个机制本身仍是计划中的延申玩法，只是它不该有个手写字段。）

## 四、顺带修掉的工具问题

### `npm run typecheck` 从来没检查过浏览器客户端

加状态光环时我漏了 import，`npm run typecheck` **照样报绿**。
查下去：根 `tsconfig.json` 的 `include` 是
`["src/**", "tests/**", "../schema/**"]` —— **不含 `web/src`**。

`npm test` 第一步会编 `tsconfig.web.json`，所以测试能抓到；
但"只跑 typecheck"是个很自然的动作，那时候就是**假绿灯**。

改成链式：`tsc --noEmit && tsc -p tsconfig.web.json`。

### 点表又剪了四格

加火墙之后中位数被顶到 6 档，撞上玩家定的"大部分三五个"。
**没有放宽断言**（它编码的是玩家的原话），改成剪没人用的格子：

- `energy` 去掉 **5**（和 10 没手感差别，都是"很便宜"）
- `cooldown` 去掉 **1**（1 秒冷却等于没有冷却，2 秒才是真下限）
- 兜底表去掉 **-15**（没人用，而且"减 15"这种通用档位本身就很怪）
- `areaRadius` 去掉 **8**（夹在 6 和 12 中间，"6 还是 8"不是决策）

剪完中位数回到 5，平均值 5.9 → 5.6。

## 欠账

- **`locked` / `auto` 还没有出厂内容用**。引擎做了、测试覆盖了，
  但玩家手上没有这两个模式的技能 —— 和"写了没内容"是同一类问题的镜像。
  做一个"自动瞄准最近的敌人"的飞弹，或者一个"锁定"的引导技就补上了。
- `areapoint` 的火墙目前是"落下就伤一次"，**没有留在地上的持续区域**。
  真火墙应该烧一段时间 —— 那需要 `area` 载体变成会持续存在的实体
  （`EntityKind: 'area'` 在 types 里声明了，但没人用）。
- 状态光环**不区分层数**（挂 3 层和 1 层长得一样）。
- `pull` / `teleport` 两种位移模式仍然零内容。
- `self` 和 `spawn` 两种载体仍然零内容。
- 六个触发时机仍然零内容（`onNonCrit` / `onExpire` / `onRemoved` /
  `onEnter` / `onLeave` / `phaseEnter` / `phaseInterrupt`）。
- `priceRule` 那条启发式和引擎矛盾（连着三轮记了）。
