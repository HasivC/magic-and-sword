## 上一轮我在日志里写错了一件事，先更正

上一轮我写「`pricing.ts` 给 displacement / perception / spawn 定价」。
**这是错的。** 它是这么写的：

```ts
default:
  // 位移 / 感知 / 生成还没实现，也就无从定价
  return 0
```

定价器是诚实的，它明确说了"没实现所以不算"。撒谎的是
`pipeline.ts` 那个 `default: throw`：schema 认、校验器认、describe 写得出人话，
只有真正执行的那一步会炸。当时的 grep 只看了文件名没看行，把 `pipeline.ts`
的命中记成了 `pricing.ts` 的。**这也说明"扫一遍关键词"不能代替读代码。**

## 这一轮做的事

### 1. 位移载荷真的能用了（`displacement`）

四种模式，**分两族**——这不是约定俗成，是语义本身：

| 模式 | 谁动 | 怎么动 |
|---|---|---|
| `knockback` | 目标 | 冲量，从施法者指向目标 |
| `pull` | 目标 | 冲量，方向反过来 |
| `dash` | 施法者自己 | 冲量，沿面向 |
| `teleport` | 施法者自己 | 直接改坐标，不经过中间帧 |

**"写了 3 米就该移动 3 米"**是这一节的核心契约。实现上位移是冲量
（每 tick 按 0.85 衰减），而载荷写的是米，中间那次换算：

```
Σ p₀·dᵏ·dt = p₀·dt/(1−d)   →   p₀ = distance·(1−d)/dt
```

⚠ `dt` 是这里唯一出现的地方，漏掉的话冲量小 60 倍（60Hz），
表现是"写了 3 米实际推了 5 厘米"。不会报错，只会让手感悄悄变错 ——
所以 `tests/pipeline.ts` 里专门钉了"击退正好推远 3 米"。

顺带补了两张点表：`distance`（位移距离）和上一轮的 `perStack` 一样，
之前压根不在任何表里，落到通用兜底 `[-15,-4,-3,0,1]` 上，
**想写"击退 2.5 米"就只能在格子外插值**。

### 2. 暴击终于存在了（`onCrit` 的前提）

`CRIT_TAG` 一直**有人读、没人写**：`matchWhen` 拿它判断 `onCrit`，
`isCrit` 条件拿它判断暴击 —— 但引擎里没有任何地方往 `hit.tags` 里放过 'crit'。
所以 `onCrit` / `onNonCrit` / `isCrit` 三个时机**永远不成立**。

补上了 `char.critRate` / `char.critDamage` 两个属性，在 `resolveHit` 的
最开头掷骰（必须在收集钩子之前，否则钩子会按"没暴击"收进来）。

⚠ **`critRate` 是 0 的时候一次骰子都不掷。**
rng 是全局有状态的，多掷一次就会把整个随机序列推后一格 ——
于是"没开暴击的内容"也会因为这次改动而重放结果不同。
`tests/pipeline.ts` 里有一条断言直接盯 `world.rngState` 没变。

**证据**：`duel` 跑 12 秒，战果和改动前逐字节一样（67.6 / 71 / 5 / 8）。

### 3. `onLowHp` 真的会触发了

声明在 schema 里、`describe.ts` 里有中文、校验器认它 —— 但**没有任何东西触发过它**。

语义是**跨过**低血线的那一瞬间（`LOW_HP_PCT = 0.3`），**不是**"低于就一直触发"。
写成后者的话，"残血获得护盾"会变成"每次挨打都白送一个护盾"。

跑的是**挨打那个人自己**的常驻术式 —— `onLowHp` 问的是"我快死了"，
主语只能是被打到快死的那个。

### 4. 四个新技能，把剩下的零内容机制补上

| 技能 | 补的是 | 备注 |
|---|---|---|
| 破军突刺 | `capsule` 载体 + 位移 + `onMiss` | 一个技能覆盖四样 |
| 圣光术 | `aura` 载体 + 治疗 | 光环 4 米 |
| 亡灵诅咒 | `hitKindIs`（亡灵反转） | 挂在**敌人**身上 |
| 背水 | `onLowHp` | toggle，不是被动 —— 见下 |
| 猎手直觉 | `onCrit` | 常驻被动 |

**被动的代价只能怎么付。** 第一版把"残血给 100 点盾"塞进被动，
账上直接花超 7.89 点。当时的直觉是"把盾调小"，但真正的答案是
**换一种激活方式**：

常驻技能没有"按一下"这一刻，所以它既没有真能量消耗，也没有真冷却 ——
挂在 `onCrit` / `onLowHp` 上的钩子不需要任何冷却就会触发。
在 `cost` 里写 cooldown 只会在账上多出点数，**却拦不住任何东西**，那是假代价。

名刀司命定下的办法是用一条 `onCast` 规则挂**永久负重**（它在技能挂上时跑一次）。
但那条路只够付得起小效果；100 点的盾得换成 `toggle`，这样能量和冷却才是真的。
于是拆成两个技能：**猎手直觉**（被动，暴击回血 + 负重）和**背水**（toggle，残血自动盾）。

### 5. 又补了两项定价漏掉的东西

和上一轮的 `immuneTags` 同一个病：**效果在账上值 0 点，代价照常扣**。

**（a）位移之前是免费的。** 定价器对不认识的载荷返回 0。
一个纯击退技能会算出"还剩一大截"，看起来像数值没调好，实际是效果没进账。
补上 `displacementPerMeter`，自己位移打对折（`selfMoveShare`）——
冲刺买到的不是"能到那儿"（那段路本来就能走过去），是"这一瞬间就到"。

**（b）"把一次命中掉头"之前也是 0 点。** 亡灵诅咒算出来 +3.66，全是阶段的代价。
补上 `pipelineReversePerSecond`（0.8/秒），诅咒变成 −0.34。

⚠ 只认 `reverse`，**没认 `cancelled`**（名刀司命的拦截）。
`cancelled` 同样没被定价，但名刀靠它那条负重正好配平，
现在补会把已经调好的名刀推歪。这是**已知欠账**，不是"cancelled 不值钱"。

**证据**：补完之后**所有旧技能的点数一分没变**（贯日 0.42、裂地斩 −1.30、
无下限 1.76、熔岩护甲 −0.72、魔法飞弹 −0.20、名刀 0.83、裂魂 −5.89…）。

### 6. 发现一处引擎和定价器**互相矛盾**

`priceRule` 有一条启发式：

> `payload.kind === 'status'` 且没写 `target`、时机不是 `onHit` → 默认落在**自己**身上

而 schema 和引擎的规矩是：不写 `target` 就是 `'hit'`（这次命中里"对面那个"）。
**两边不一致。**

亡灵诅咒正好撞上：`when: phaseComplete` + 没写 target。
引擎把诅咒挂在敌人身上（对的），定价器按"给自己上 debuff"算 ——
一个对敌人有害的效果被算成了**代价**，符号直接反了（−4 变成 +4）。

这一轮的处理是**让内容显式写 `"target": "hit"`**，两边就一致了。
根子在定价器那条启发式上：它当初是为了让熔岩护甲、无下限那些
"onCast 给自己挂架势"的内容能正确计价。要拆掉它，得先把那批内容
显式标上 `target: 'self'` —— 那会推动好几个已配平技能的点数，值得单独一轮。

**这是欠账，而且是个会静默算错账的欠账**，优先级不低。

## 欠账

- **`perception` 和 `spawn` 仍然会 throw。** 这一轮没动它们：
  - `perception` 要先定"可见性到底挂在哪"（现在是 `StatusDef` 的字段，
    载荷却想直接改实体）
  - `spawn` 要一个实体预设内容类型（`content/entities/`），那是新一层内容
- **`priceRule` 那条启发式和引擎矛盾**（见上），会静默算错账
- `pipeline.cancelled` 仍然没被定价
- 击飞只加了 z 冲量，**没有"空中不能行动"**，所以定价定得很低（0.3）
- 六个时机仍是零内容：`phaseEnter` / `phaseInterrupt` / `onExpire` /
  `onRemoved` / `onEnter` / `onLeave`
- `statusId` 的加载期校验还没做（L2）—— 现在引用不存在的状态仍然要等到
  运行期才 throw
- 血契仍未实现（玩家已明确它是延申机制）
