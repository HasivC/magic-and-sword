## 一、读表这条路怎么落的（形状 + 覆盖栏）

### 1.1 表的形状：**一张共享的四格默认 + 按技能覆盖**（用户点名的形状）

`content/balance.json` 的 `tierTables.phaseDurationPoints` 现在是：

```jsonc
"phaseDurationPoints": {
  "0": -6, "1": 0, "3": 2, "9": 4,        // ← 共享的四格默认（所有技能共用）
  "_0": "……", "_1": "……", "_3": "……", "_9": "……",
  "bySkill": {                            // ← 按技能覆盖：**今天一格都没填，但结构在**
    "_comment": "技能 id → 只写要改的那几档，其余走上面共享的四格",
    "_留空的意思": "bySkill 是空对象 = 所有技能都走共享那四格"
  }
}
```

- 键是**基础技能 id**（= `lookupTable` 的分区键）：变体（`basedOn`）对着**它的模板**查 ——
  和账本身取分区那句逐字相同。
- ⚠⚠ **覆盖是加法式，不是"整张换掉"**：覆盖里写一格就只换那一格，别的档位照旧走上面四行。
  整张换掉的话，玩家改一格会**静默地**把另外三档带回代码兜底值 ——
  "我改了它没生效"和"这一档本来就是这个价"在账面上长得一模一样。
- 代码侧：`TierTable` 多了一个可选的 `bySkill`（`TIER_BY_SKILL_KEY = 'bySkill'`），
  `readTierTable` 读它（顶层共享那段和每一段覆盖**共用同一个 `readTierRows`** ——
  抄两遍迟早漏掉"认不出的行不算数"）；取价用新函数 **`tierPointsForSkill(table, tier, skillId)`**
  —— **先覆盖、后默认**。定价的两个地方都改成走它（不是 `tierPointsOf`）。
- 校验器（`checkBalance`）补了两条**只针对覆盖**的检查：覆盖里把 `1`（中性档）写成非 0
  ⇒ `TIER_TABLE_NEUTRAL_NOT_ZERO`（错误）、覆盖里写小数 ⇒ `TIER_TABLE_NOT_INTEGER`（错误）。
  理由：这两处**写坏了是静的** —— 那一个技能的**每一样出厂内容**都会带上那一笔，
  "出厂全 0"（宗旨）当场破，而账上看起来很正常。

### 1.2 优先级：**倍数档走表、绝对秒数继续走老的**（用户批的那条）

新函数 **`phaseDurationTierPriceOf(wasDuration, nowDuration, o, skillId)`** 是唯一那句判据：

```
出厂 > 0 且 现在 >= 0，而且 现在 / 出厂 落在表里那几档 ⇒ 价 = 表里那一格（含按技能覆盖）
其余（表外取值 / 蓄力哨兵 / 出厂那一头就没有"固定秒数"）⇒ undefined ⇒ 交回绝对秒数那条老路
```

账本（`lookupEntriesOf`）里的优先级**写死**成：**先问它**，问不出来才查 `lookupTable` 那一行绝对格：

- ① **倍数档走表** —— 四档永远有价可查；改一个数（甚至只改某一个技能的覆盖），四档的价一起变；
- ② **绝对秒数继续走老的** —— 表外的取值（1.7× 那种）照旧按那一格收；
  一格都没有时照旧留一条 `⚠ 表外取值` 的 0 点记录（**不许静默当 0**）。

**为什么倍数档优先**：那四档是**用户亲口定的四个整数**（无 −6 / 1× 0 / 3× +2 / 9× +4），
而老格子里那几格是**跑出来的**近似值（60a 那一轮逐格量的"相对账"）。两张表打架时
**用户签的那个数必须赢** —— 否则会出现"表里写 +2、账上按 −1 扣"。
**为什么老路不删**：`lookupTable` 的那条是「绝对档滑块」那条路用的（用户硬命令：
"老路径先留着，两套并存"）；而且它是"表外取值"的唯一去处 —— 删了就等于把
"玩家拖到格子外"变成静默的 0 点。

### 1.3 语义一个字没改（用户第二条硬命令）

- `1×` 仍然 = **这个技能自己的**出厂时长；`3×` / `9×` 仍然是它的三倍 / 九倍；
- **`-1`（蓄力）仍然单独一档、不在倍数里** —— 它的价是 `rates.chargePhasePerPoint` 一笔定额，
  这一片照旧走 `lookupTable` 那一格 / `pricePhase` 的老算法（判据 `onDurationTierAxis` 把它挡在倍数轴外）；
- **出厂全 0 不变**：出厂技能每一段都是 `1×` ⇒ 表里那一格是 `0` ⇒ 那一笔**不留记录**
  （和 60b 的"0 格不留记录"同一条规矩），ⓑ 那两条常驻断言（合计 **和** 条目数都是 0）一个字没改。

### 1.4 编辑器那一半（⚠ 只改了「价格显示」）

`web/src/editor.ts` 的三处：`phaseTiers`（哪几档给点）、`phaseTierPrice`（这一档值多少点）、
`phaseTierHtml`（按钮上的价与悬停说明）—— **判据和账本同一个函数**。
⚠ **布局 / 样式 / CSS / 控件形状一个字节没动**；改的只有"这个按钮显不显示价格、给不给点"。
换了这一处之后：四档各自显示 **−6 / 0 / +2 / +4**（悬停写着"倍数档查表：3× → 2 点"），
蓄力那一档照旧显示"账上这一格（**绝对秒数**）：N 点" —— 那就是"两条路并存"的界面证据。

⚠ 顺带**补了装配线的一行**（`options` 那一段）：`tierTables: readTierTables(balance.tierTables)`。
不补的话编辑器会落到**代码兜底** `DEFAULT_TIER_TABLES` —— 那一份**只有共享的四格、没有 `bySkill` 覆盖**
⇒ 用户给某个技能填了覆盖之后，**编辑器显示共享那个价、命令行按覆盖扣**
（本项目最恨的那类静默漂移）。这一行只喂价格显示，兜底那份仍然留着（别的入口在用）。

## 五、待裁定项（⚠ 遇到判断的地方，一条都没自己定）

1. **要不要把四档那几个数也写进 `lookupTable`？**
   这一片**没写**（写进去就是两份来源、会漂移）。代价：*原始格子* 那一列还是 `3/16/0`，
   而"有价可查"靠的是代码那条新路。用户若想要"表里就看得见那四格"，说一声就补（那是一批数据改动）。
2. **覆盖栏填了之后，界面上要不要能看见/能改？**
   本片**只让编辑器"算得对"**（装配线补了 `tierTables` ⇒ 覆盖生效、显示跟着覆盖走，见 §1.4），
   但**编辑器里没有任何"改覆盖"的控件** —— 覆盖今天只能在 `content/balance.json` 里手写。
   要不要给它一个界面（或者至少把"这个技能有覆盖"标出来），是用户的事。
3. **四档的价要不要按技能自己的时长给不同的默认值？**（日志 59 就挂着的同一条）
   现在是"一段 0.1 秒的前摇和一段 1 秒的前摇，同一个档位同一个价" —— 那是"挨个填值"的代价。
4. **表外取值（1.7× 那种）到底该怎么处置**：今天照老规矩 = 走绝对格 / 留 `⚠ 表外取值` + 校验器报错。
   ⚠ 但**有了倍数档之后**，"1.7×"这种取值在编辑器里已经拖不出来了（控件就是四档）——
   要不要把它从"错误"降成"警告"？
5. **`bySkill` 的键该是基础技能 id 还是"玩家的自定义变体 id"**：今天按 `lookupTable` 的口径取
   **基础技能 id**（变体对着模板查）。若用户想给某一个变体单独定价，这是另一套东西（要新结构）。
6. **`DEFAULT_TIER_TABLES` 那份代码兜底还要不要留**：编辑器现在带了 `tierTables`（内容侧那份），
   所以兜底只剩"别的入口手工拼 `PriceOptions` 时不至于算不出价"这一个用途；
   `tests/pricing.ts` 钉着"兜底和内容侧的**共享四格**逐位相同"。
   真该做的是让所有入口都走 `priceOptionsFor`、然后**把兜底删掉**（"所有价格都是数据"）。
