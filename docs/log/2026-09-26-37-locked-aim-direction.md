# 攻击方向改成「施法那一刻锁死」

- **日期**：2026-09-21
- **触发**：日志 36 结尾我留了一段"没改的东西"，玩家问

  > 你没改的这个，是什么意思

  我解释完两种做法（按下时锁死 / 前摇结束时按当前朝向算），他就一个字：

  > 改吧

- **动了哪些文件**
  - 引擎：`src/sim/pipeline.ts`（投射物 + 瞬时载体 + 特效事件，三处方向）、
    `src/sim/cast.ts`、`src/sim/types.ts`（删掉 `CastInstance.aimFacingLocked`）
  - 测试：`tests/weapons.ts`（新加 4 条"前摇里转身也不改方向"）、`tests/pipeline.ts`（把那一节的注释改成新含义）

---

## 一、改的是什么

**以前**：`directional` 的载体（挥砍 / 光束那一类"朝哪打哪"）用的是**施法者当前朝向** ——
也就是客户端每一帧往 `facing` 里写的那个值。

**现在**：用**施法那一刻解算出来的方向**（`cast.facing`），之后谁改 `facing` 都不影响这一下。

一句话说清手感差别：

| | 方向在哪一刻定下来 | 前摇里甩鼠标 |
| --- | --- | --- |
| 以前 | 前摇结束、命中帧开始那一刻 | 会跟着改（铁剑那段窗口 ≈ 0.17 秒） |
| 现在 | **按下那一刻** | 不改 |

## 二、为什么值得改（不只是手感）

以前那个设计把"这一刀朝哪"和**客户端每帧写朝向**绑在了一起。那条链断掉的方式
**全是静默的**：

- 指针坐标没送到（只转发点击的环境，或者指针恰好落在画面正中）
- 算方向那一步凭空返回了一个默认值（`aimDirection()` 老代码干过，见日志 36）
- 别的地方覆盖了朝向

而表现都是同一句"这一刀砍在别处" —— 玩家 2026-09-21 报的
「左键的攻击始终朝向正右方」正是这一类。

改完之后：**"打哪儿"由施法那一刻的意图决定**，客户端每帧写 `facing` 只剩一个用途 ——
画角色朝哪（那本来就是它该管的）。少一条静默失败的路径。

**代价（明说）**：前摇里转身不再能微调这一下。想要"前摇里还能改方向"的话，
那是另一套输入（施法开始之后重新传意图），现在是按下即锁定。

## 三、顺手清掉一个死开关

`CastInstance.aimFacingLocked` 这个字段存在的唯一目的就是区分
"锁定/自动索敌用的是解算出来的方向，directional 用的是当前朝向"。
现在所有模式都用 `cast.facing`，它没有读者了 —— 删掉。

⚠ `ResolvedAim.facingLocked`（瞄准解算那边）**留着**，但含义收窄成
"方向是不是被选中的目标钉住的"（`locked` / `auto` 是，其余不是）。
`tests/pipeline.ts` 那一节的注释跟着改了 —— 免得下一个人以为它还决定载体用哪个朝向。

## 四、测试

`tests/weapons.ts` 新加 4 条（那一节本来就有一组"朝上挥就打上方"）：

1. `cast.facing` 在施法那一刻就是"朝上"
2. 前摇里把（客户端写的）朝向拧到右边 → **这一刀仍然打上方**
3. 而且右边那个**没**挨打（证明方向没有跟着当前朝向走）
4. 投射物那条路也一样：前摇里转身，飞弹仍然朝施法那一刻的方向飞
   （投射物是**另一行代码**，以前它和瞬时载体走的是两条不一样的规矩）

⚠ 这一组在旧代码上会红：方向跟着 `facing` 走的话，"上方那个挨打"永远不成立 ——
这一点日志 36 里那个探针（`.scratch/aim-probe.ts`）已经量过了：
朝向 (1,0) + 意图朝上 → 打的就是右边。

## 验证

| 检查 | 结果 |
| --- | --- |
| `npm test` | 16 个文件全绿 · **1114 个断言**（新加 4 条，`tests/pipeline.ts` 那 8 条只改了注释） |
| `npm run validate` | 51 个文件 · 51 通过 · 0 失败 · 9 警告 |
| `npm run typecheck` | 两个 tsconfig 都干净 |
| `npm run build:web` | 通过；线上 `sim/pipeline.js` 已确认是新规则 |

⚠ duel 的基准没动，说明这个改动**只影响"前摇里转了身"的那些情况**：
`duel` 里两个 AI 都是朝目标直着打的，施法瞬间和命中帧的朝向基本重合。
（30 秒那一档我没留过旧基准，所以不做对比 —— 只报了 12 秒这个一直在用的基准。）

## 欠账

- **前摇里不能微调**是这次取舍的直接代价。真觉得别扭的话，可以做"长前摇技能允许
  在施法期间重新传意图"（引擎侧已经有能力：`cast.facing` 是可写的，
  改它 + 重新解算是十几行）—— 但那是新功能，不是修 bug。
- 之前几轮的欠账还在（见日志 34 / 35 / 36）：`slash` 还是占位素材、技能修正、
  修饰技能、锚点表、阶段时长档位、血祭斩 / 裂魂的过时标签。
