## 一、我原来错在哪

上一轮我按"**每个术式各存一份技能快照**"做成了
`Technique.skillCopies` —— **术式私藏一份副本**。玩家一句话点破：

> 技能是玩家拥有的东西，存在两个库：**基础技能库**（我们写的出厂配平为 0 的那些）、
> **自定义技能库**（玩家进行编辑后的技能另存一份副本在这里）。
> 技能可以存在多个变体，玩家给它们取名字（不取就是默认"火球-副本1"这种名字）。
> 技能不是独属于一个术式的，应该影响所有用到它的术式，但要注意
> **基础技能和它的变体是两样东西**，并且玩家不只能从自定义技能库中组成术式，
> 也能从基础技能库中选择。**自定义技能是独立的，它不属于术式。**

我那套模型的每一处都错了：

| 我做的 | 应该是 |
| --- | --- |
| 副本**归术式**（一个字段，列不出来） | 变体是**玩家拥有的东西**，有自己的 id 和名字 |
| 同一个技能在 N 份术式里 = N 份互不相干的副本 | 变体是**全局**的，改它所有术式一起变 |
| 改技能 = 在技能页拖滑块（改的是"当前归属那份术式"） | **创造一个技能**（挑模板）→ 编辑 → **保存** |
| 每份术式**各存一份**副本 | 自定义技能库**一份**，术式按 id **引用**它 |
| 删掉术式会带走技能改动 | 技能改动跟着**技能**走，跟术式无关 |

**最要紧的是那句"基础技能和它的变体是两样东西"。** 我原来把"改过的技能"
当成"同一个技能的另一份数据"，所以才会想去"覆盖/还原"它。
玩家说的是：**它是另一个东西**（另一份技能），基础版永远原样在那儿。
于是"一份术式里一段用基础版、一段用我的变体"是完全正常的 ——
那两个 id 指向两样不同的东西。

## 二、改成了什么

### 1. 数据

```
Skill.basedOn?: string      // 这份变体是从哪个**基础技能**长出来的（= 账的基准）
Technique.skills: string[]  // 术式按 id 引用技能 —— 两个库里的都能引
SavedState.skills: Skill[]  // 自定义技能库（v2 新增）
```

`Technique.skillCopies` 和 `skillLookupFor` **删掉了**。
查找技能只剩一句话（`web/src/main.ts` 的 `findSkill`）：

```
自定义库优先、基础库兜底
```

比我那套"每份术式各自解析一遍"简单，而且**引擎和定价那边反而更省事**：
编译、定价、算血契三处都只查那一张合并后的表。

### 2. 账

变体的账 = `skillLedger(变体, 它的模板)` —— **对着最初那个基础技能算**。

⚠ 从一份**变体**再"另存为"出来的新变体，`basedOn` 仍然是**最初那个基础技能**
（不是上一份变体）：不然变体一旦成链，"出厂配平为 0"这条宗旨就断了
（A 偏离 +5、从 A 派生的 B 再 +5，而 B 只显示 +5、实际偏离出厂 +10）。

⚠ 变体是全局的，所以**同一个变体改一次，所有用到它的术式一起变** ——
它们的账当场就变了（甚至因此变得"没配平"）。这条现在在术式编辑器里看得见。

### 3. 界面（技能页重做）

```
基础技能库（出厂 · 只读）
  选中它 → 一整页只读（滑块 disabled），只有一颗「创造一个技能」
「创造一个技能」 → 拿它当模板开一份**草稿**（名字默认「火球-副本1」）
  草稿 → 可以改名、随便改数值 →「保存」才进库（不保存走开 = 什么都没发生）
「我的技能（自定义库）」
  选中它 → 「保存」「另存为」「删除」，还有名字输入框
  删除：**还有术式在用它就不给删**，并且明确列出是哪几份术式
```

术式编辑器那边：技能下拉按「基础技能库 / 我的技能」**分两组**，
"我的"标上「基于 火球」；每一段的点数从**绝对账**改成**相对模板的偏离**
（原来列表上写着"魔法飞弹 −0.7"，而账上根本没有这一笔 —— 两个数对不上）。

### 4. 存档与分享码

- 存档 **v2**：多了一个 `skills`（自定义技能库）。
- **v1 → v2 迁移**：v1 那种"术式私藏副本"会被搬进自定义技能库、
  给新 id（`custom.<模板短名>.<序号>`）和 `basedOn`，并**把引用它的术式改指过去**。
  玩家改过的东西不会丢。
- 分享码 **TS2**：**带着这份术式用到的变体**（玩家选的"带 —— 导进对方的自定义技能库"）。
  收码时冲突**问他**（"用我的" / "把码里的导入成一份新的副本"），不静默覆盖 ——
  他自己那份可能已经用在好几份术式上了。第 1 代老码仍然读得进来（当空技能包）。
- 新增校验器错误 `UNKNOWN_BASE`：变体的基础技能找不到了就说清楚
  （不然 `priceTechnique` 会**整段跳过**它，而跳过是不出声的）。

## 三、为什么

一句话：**"技能"是一个玩家能拥有、能命名、能复用的东西，不是某份术式的内部字段。**

我那套模型里，"技能"只存在于某份术式的肚子里 —— 列不出来、取不了名字、
删术式就没了、同一个技能在不同术式里还是两个不相干的东西。
那既不像"玩家获得技能并编辑它们"，也让"改一次、到处生效"这件很自然的事
变得做不到（而那恰恰是玩家要的）。

拆成两个库之后，很多东西**自动**变简单了：
定价不再需要"每份术式各自解析"、分享码只要打包用到的变体、
"另存为"就是复制一份、删除就查一下引用。

## 五、欠账

1. **技能修正**（技能编辑器里管数值和几何，改的是它自己所在的这个技能）。
2. **修饰技能**：术式里的连接卡 + 触发器卡（触发器要"同时激活"，
   需要 `cast.ts` 支持并行施法）。
3. **锚点表**（`content/anchors.json`）：`calibrate` 的拟合目标仍然不成立。
4. 阶段时长的 **无 / 1× / 3× / 9×** 四档。
5. 分享码导入时的冲突选择现在用 `window.confirm`（能用，但不如页内选择干净）。
6. 变体改名**没有查重**：两个变体可以同名（id 是权威的），列表上用「基于 X」区分。
   玩起来觉得乱的话再补。
7. 自定义技能库还不能**导出/导入单个技能**（只有术式能分享）。
