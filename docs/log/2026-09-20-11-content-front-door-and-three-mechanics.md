# 补充内容：先修四个"内容一多就爆"的底层陷阱

- **日期**：2026-09-20
- **触发**：玩家说「先不进行美术设计了，补充内容吧。另，血契不是核心机制，而是延申机制、
  特殊玩法。进行构建不必着急，**从底层往上建**。有条件的话我不想在浏览器里玩，而是独立窗口」
- **动了哪些文件**：见下面每一节末尾

## 一开始以为是"内容不够"，其实是"内容进不去"

玩家的要求是补充内容。动手之前先做了一轮审计，结论是**内容加不进去**，
而且已经做好的内容玩家也拿不到：

| 症状 | 后果 |
|---|---|
| `manifest.scenarios` 声明了，**没有任何代码读它** | 场景进不了游戏 |
| `web/src/main.ts` 的 `restart()` 把阵容**写死在代码里** | 每加一个技能都要改引擎代码 |
| 技能栏只有 5 个键（`CAST_KEYS`） | 裂魂、名刀司命**做完了却选不到** |
| `web` 只调 `registerTechnique`，不注册状态定义 | 术式内联状态在浏览器里查不到（命令行里查得到） |
| `onLowHp` 在 schema 里、在 `describe.ts` 里，**引擎从不触发它** | 写上去等于没写 |

其中"选了也拿不到"最要命：**做完了等于没做**。

## 又查出三个"机制在撒谎"的载荷

`displacement` / `perception` / `spawn` 三个载荷：

- schema 里声明了（`PAYLOAD_KINDS`）
- **校验器给它们写了详细的检查**（必填字段、枚举、警告）
- `pricing.ts` 给它们定价
- `describe.ts` 给它们生成了通顺的中文说明
- 然后 `pipeline.ts` 里 `default: throw new Error('动作类型「x」还没实现')`

也就是说：**编辑器会痛快地让你做一个击退技能，把说明写得漂漂亮亮，
算好点数，然后你一放就崩。** 整条链都在撒谎。

这一轮没来得及修它们（见欠账），但**查清楚了**，而且这是"补充内容"必须先解决的。

## 这一轮做了什么

### 1. 场景进 schema，装配层**只有一份**（L1）

- `schema/scenario-schema.ts`（新）：`Scenario` / `ScenarioEntity`，
  原先是 `src/cli/battle.ts` 里的一个私有 interface。
  `Faction` 也搬了过来（场景是内容，内容要能写它），`sim/types.ts` 转出一次。
- `src/scenario.ts`（新）：**纯函数** `lowerScenario()` + `applyScenario()`。
  命令行和浏览器共用同一份 —— 两边各写一份的话，
  "命令行里能跑的阵容在浏览器里装配不出来"，而且报错方式还不一样。
- `web/src/main.ts`：`restart()` 里**一行阵容硬编码都没有了**，
  一切从 `content/scenarios/arena.json` 来。
- `content/scenarios/arena.json`（新）：第一个给人玩的场景（`duel.json` 是给机器跑的）。
- 技能栏 5 → 8 个键。

### 2. 装配顺带修掉"浏览器查不到状态"（L5）

`applyScenario` 会为每个术式注册它内联的状态定义。
这同时修掉了 web 侧一直缺的那一步（`bridge.ts` 的 `installTechnique` 两样都做，
web 只做了 `registerTechnique`）。

### 3. 三个新技能，把三个零内容的机制跑通

| 技能 | 机制 | 之前的状态 |
|---|---|---|
| 铁布衫 | `immuneTags`（霸体） | 引擎实现了，**零内容** |
| 寒冰锁 | `disables`（冻结） | 引擎实现了，**零内容** |
| 灵光盾 | `absorb`（护盾） | 引擎实现了，**零内容** |

零内容 = 零验证。一个从没被跑过的机制，和没实现是一回事。
所以每加一个，就在 `tests/scenario.ts` 里留一条"它真的生效了"的断言：
盾吃掉 60 点伤害、冻结让 `canAct` 三项全假、霸体挡住冻结并发出 `statusImmune` 事件。

### 4. 裂魂那条死了很久的规则，修好了 —— 它其实坏了**三次**

`skill.soul-rend` 的 r2：「命中时驱散目标身上的护盾」。三个独立的毛病叠在一起：

1. **`status.shield` 这个名字哪儿都不存在。** 它只出现在 `tests/pipeline.ts` 里，
   出厂内容里没有任何东西定义它 —— `resolveStatusDef` 会返回 `undefined` 然后 **throw**。
2. **条件用错了谓词。** 写的是 `hasTag(target, 'shield')`，那是查**实体自身**的标签；
   护盾是**状态**的标签。条件恒为假，规则从来没触发过。
3. **`hasStatusTag()` 这个函数在 `status.ts` 里一直都有，但没有任何条件类型能调到它。**
   实现了却接不上线，等于没有。

修法：`status.shield` 由灵光盾内联定义（装配层注册）；新增 `hasStatusTag` 条件类型
（schema + 校验器 + `conditions.ts` + `describe.ts`）；r2 改用它。
现在它按**标签**匹配，所以以后新加的护盾类状态它一并驱散。

### 5. 定价漏了一整项：免疫控制是免费的

`statusStrength()` 只数 `modifiers` / `disables` / `hardCC` 标签，
**`immuneTags` 一个字都没提**。后果很具体：铁布衫只免疫控制的时候，账上还剩 +5.38。

当时的直觉是"把代价调低"—— **那是错的**。真正的原因是效果压根没被计价，
而代价在照常扣。补上 `immuneTagStrength`（默认 1.5，参照系是"禁用一项能力 = 1"）后，
铁布衫变成 −0.38，**其余九个技能的点数一分没变**。

这条也是配平器逼出来的：账不平衡时先问"这个技能到底该有多强"，
而不是把代价往下调。铁布衫最后加了一条 20% 减伤，
因为 20 能量 + 8 秒冷却这笔开销，光靠"免疫控制"撑不起来。

### 6. 点表剪掉两格没人用的

补内容之后 `tests/editor.ts` 的中位数从 5 档涨到 6 档，
撞上了玩家定的"大部分用三五个取值"。**没有放宽这条断言** ——
它编码的是玩家的原话。改成剪格子：

- `mul` 去掉 **×1**（空操作，不是选择，是陷阱）
- `amount` 去掉 **15**（夹在 10 和 25 中间，10→15 是 +50%、15→25 是 +67%，两边差别都比它大）

剪完中位数回到 5。审计脚本提升成了正式工具 `tools/grid-audit.ts`
（`npm run grids -- --unused`）：它把每一档的利用率打出来，照着它剪，
并且**列出一批"故意保留全部档位、不许按利用率剪"的表**（规则位 0..8、张角、可见性）。

同时加了 `tools/overview.ts`（`npm run overview`）：全部技能/术式一张表 +
末尾的**机制覆盖**统计。这一轮补的护盾/霸体/冻结就是这么找出来的，
以后再补内容先跑它。

### 7. 独立窗口

`tools/play.ts`：`npm run play` 用 Edge/Chrome 的 `--app=` 开一个独立窗口
（`--user-data-dir` 单独一份，不挂到你日常浏览器上）。

写的时候踩了两个坑，都留了注释：
- `ensureServer()` 返回的语义写错成"是我起的吗"，于是**服务已经在跑**（最常见的情况）
  反被判成失败直接退出。
- `stdio: 'ignore'` + `detached` 下 spawn 失败是**一声不吭**的：
  脚本照常打印"✓ 窗口应该已经开了"，然后什么都没发生。现在会等到 `spawn`/`error` 才往下走。

## 验证

- `npm test`：**558 个断言**（原 538）+ 7 个用例 + 纯净性（14 个文件）全绿
- 新增 `tests/scenario.ts`：73 个断言
- `tests/web.ts` 从 4 条加到 11 条，而且**改成真的启动一次客户端**：
  给 `fetch` / `Image` 装上"从磁盘读"的替身，让 `main.ts` 的 `boot()` 完整跑完
  （读 manifest → 技能 → 术式 → 编译 → 场景 → 装配 → 刷 HUD）。
  这是唯一能在 Node 里覆盖"浏览器开局"整条路径的办法 ——
  而这条路上出过的每一个错，在浏览器里的表现都是**白屏**。
- 并且**验证了这个测试能失败**：故意把 manifest 的 scenarios 指向不存在的文件，
  测试变红；`manifest.json` 原样还原。
- `npm run validate` 21 个文件 21 通过
- `npm run calibrate` 最大偏差 1.68 ≤ 容差 2
- **无头战斗逐字节没变**：`duel` 跑 12 秒，战果和重构前完全一样
  （剑士 67.6/300、法师 71/200、施法 5/8）—— 装配层换了一整份实现而语义不变
- 独立窗口：Edge 起来了（profile 里出现 `Apps_*` 会话文件）

## 欠账

- **`displacement` / `perception` / `spawn` 三个载荷仍然会 throw。**
  这一轮查清楚了但没修。它们是"补充内容"的下一道坎：
  击退、突进、隐身、标记、召唤，全都卡在这儿。
  要么实现，要么从 schema 里删掉 —— **不能继续这样撒谎**。
- `onLowHp` 仍然从不触发（L4，没做）
- `perception` 里的 `reveal` / `mark` 没实现，`visibility` 只有 1 处内容在用
- 用户侧还没有"选场景 / 选装"的界面：现在是 manifest 里排第一个的场景 +
  场景里写死 8 个键。换装要改 JSON（但这已经是"改内容"而不是"改代码"了）
- 状态时长表 7 档（`-1/0.5/1.5/3/5/10/25`）**每一档都有内容在用**，
  压不到玩家要的 3~5 档。要压就得动熔岩护甲和无下限的既有数值，那是他的手感，不该我改
- 血契仍未实现（玩家已明确它是延申机制，优先级下调）
