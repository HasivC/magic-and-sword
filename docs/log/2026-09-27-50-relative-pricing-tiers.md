## 二、档位是什么（玩家 2026-09-21 签字，定稿 §12）

`×` 相对的是**这个技能自己的出厂值** `D`，**不是**全局起点值：

| 档 | 值 | 账 |
| --- | --- | --- |
| **0** | `0`（取消这一段） | **消耗点数** = `−K × D × 汇率`，**非线性** |
| **1×** | `D` | **0 点**（中性点就是它自己） |
| **3×** | `3D` | **提供点数** = `+2 × D × 汇率`（相对 1× 的净额） |
| **9×** | `9D` | **提供点数** = `+8 × D × 汇率` |

**为什么 0 档必须非线性**：线性式下 `0 秒 × 任何汇率 = 0` ——
也就是"取消前摇"**免费**，而 `src/sim/cast.ts` 会把 0 秒阶段当**瞬发**处理
（`advancePhase` 一个 tick 走完整条术式）。玩家原话「**没有前摇很超标**」
在旧账上完全反映不出来，而且它比"慢三倍"（+0.52 点）还便宜。
**引擎给好处、账上不扣钱** —— 这一片就是来堵这个洞的。

**K = 9 的形状**：档位本身是几何级数（1 → 3 → 9，公比 3），
0 档与 9× 档各往回收/往外放**一格**，所以**同价反号**（§12.4）。

⚠ **K 必须是数据**：玩家原话"先按这个来、以后慢慢测试" ⇒ 三个乘数放在
`content/balance.json` 的 `rates` 里（`phaseZeroTierMultiplier` /
`energyZeroTierMultiplier` / `cooldownZeroTierMultiplier`），**代码里不许写死**。

## 三、实现（`src/pricing.ts`）

### 3.1 只在**相对账**里生效，绝对账一个数不动

| 函数 | 认不认档位 | 为什么 |
| --- | --- | --- |
| `priceSkill`（绝对账，`calibrate` 的输入） | **不认** | 玩家："绝对式本来就对"。它照旧报"这一段占用了多少秒 × 汇率" |
| `ledgerEntries`（相对账的"现在"那一头） | **认** | 只有它知道"这一段出厂是多少" ⇒ 只有它能算 0 档 |

分工的后果正是要的：**出厂技能自己减自己 = 空账**（两头用同一张档位表，
`1× 档 − 1× 档 = 0`），而 `npm run calibrate` 的输入没有变过半行。

### 3.2 0 档的账长什么样（这一片踩得最久的一处）

```
0 档的价（账上"现在"那一头） = −K ×（这条轴的 1× 档价）
账上那一行                    = 0 档的价 − 这一段现在的价
```

⚠ **两件事必须分开**，因为定稿 §12.5 那张表印的是**第一行**：

| 轴（举例） | 1× 档价 | 0 档的价 | 账上那一行 |
| --- | --- | --- | --- |
| 前摇 0.3 秒 | 0.26 | **−2.33** ← 表里印的就是它 | −2.59（还要减掉这一段自己的 0.26） |
| 8 秒冷却 | 1.6 | **−14.4** ← §12.6 印的就是它 | −16.0 |

**"账上那一行"减掉的是"这一段整段价"，不是"这条轴自己的价"** ——
一段里通常还挂着时长（0.2 秒 = 0.2 点）。这一处错一次**没有任何地方会报警**：
两个数看起来都正常，而且"取消一段"本来就是收益。

### 3.3 ⚠ 一个只有实测才会发现的浮点坑

```js
-(K + 1) * 0.3        // = -3.0000000000000000   ✓
-K * 0.3 - 0.3        // = -2.9999999999999996   ✗
```

两个式子在数学上相等，在浮点里**不等**；再和账上那个 `0.3` 相减、
`round` 到两位之后，净额会从手算的 `3.00` 变成 `3.30`。
**两个数各自都对，是表达式的问题** —— 这一处查了很久（因为
"账上印 0.3、手算 −3.0、程序给 −3.3"三个数互相矛盾，每一个都像是别人错了）。

⇒ 实现里写死成一步 `-(K + 1) * basePoints`，并在注释里写清楚**不许拆开**。

### 3.4 哪几条轴有 0 档

玩家裁定"**同一个 K = 9 套所有轴**"（起草时"K 只用于阶段时长"被否掉，§12.7）：

| 轴 | 基底 | 有没有 0 档 |
| --- | --- | --- |
| 阶段时长 | **这一段的**时长 | ✓（每一段各自有档位） |
| 能量 | **这一段自己的**能量 | ✓（记在它自己那一段上，不另起一行、不重复收钱） |
| 冷却 | 全技能**唯一那一段** | ✓（冷却是技能的唯一属性） |
| 生命 | —— | ✗（出厂内容没有任何一段付生命；"0 血代价"是"没写"的写法） |

⚠ **判据是"出厂真的付过这条轴"**（`basePoints > 0`）：
少了它，"出厂 0 拖到 0"会被当成一次改动，**宗旨（出厂全 0）当场破**，
而且不会有任何东西报警。

### 一条真实技能的档位账（裂地斩 `skill.cleave`，出厂 前摇 0.1 / 命中 0.2 / 后摇 0.2）

`.scratch/price50-tiers.mjs` 实测（把该段时长改成 `倍数 × 出厂时长`，其余一个字不动）：

| 阶段 | 档位 | 相对账（玩家看到的数） | 绝对账 |
| --- | --- | --- | --- |
| 命中 `swing` 0.2 秒 | **0 档** | **−0.17** | −0.90 |
| 命中 `swing` 0.2 秒 | **1×** | **0** | −0.73 |
| 命中 `swing` 0.2 秒 | **3×** | **+0.35** | −0.38 |

- **0 档一律是负的**，而且量级随"这一段出厂付了多少"走
  （只付时长的 0.17 点 → 付 3 秒冷却的 1.87 → 付 10 能量的 5.99）✓
- ⚠ **0 档那一行的数不等于定稿 §12.5 表里的数**，理由见 §3.2

## 六、三条裁定（✅ 玩家 2026-09-21 已裁，逐条落地）

### 6.1 ✅ 裁定一：账上那一行 = **净变化**（这才是对的）

玩家原话：**"账必须能加得起来"** ⇒ 账行是净变化 ✓；
定稿 §12.5 表里的 **−2.33** 是"**0 档本身的价**"（不含这一段自己的 1×）✓。

| 读法 | 数（前摇 0.3 秒） | 用在哪 |
| --- | --- | --- |
| **0 档本身的价** = `−K × D × 汇率` | **−2.33** | 定稿 §12.5 表（讲"这一档值多少"） |
| **账上那一行** = 0 档本身的价 − 这一段现在的价 | **−2.59** | `skillLedger` / 编辑器里玩家看到的数 |

**落地**：已在 [`standard-values-draft.md`](../standard-values-draft.md) §12.5 的表格下面
加了这段口径注解（表列 = 0 档本身的价 / 账行 = 净变化 / 差正好一个 1× 档 /
注明"玩家 2026-09-21 裁定：账用净变化"）。**实现不用改** —— 现在就是净变化。

### 6.2 ✅ 裁定二："取消前摇"要进编辑器的时长点表 —— **但不在这一片做**

⚠ **这一条是欠账，UI 那一片必须照这个形状做**（玩家定的形状，别自己发明 ✗）：

> **时长控件从线性滑块改成「无 / 1× / 3× / 9×」四档选择。**

细节（都是这一片已经定死、UI 那片要跟着走的）：

1. **四档**：`无`（0 秒）/ `1×`（= 这个技能自己的出厂时长）/ `3×` / `9×`。
   ⚠ **不是** `[-1, 0.1, 0.2, 0.3, 0.5, 1]` 那种线性秒数滑块 ——
   玩家要的是**换点数**的轴（"档位之间要拉得开"），不是微调。
2. **`1×` 那一档的标签要写"默认"**（它就是中性点，账上 0 点）。
3. ⚠ **`-1`（蓄力）不能和"无"混**：`-1` 是**哨兵值**（时长由玩家按住键控制，
   价是 `chargePhasePerPoint` 一笔定额），`无` 是**时长 0 秒**（走 0 档）。
   两档在数据上是两个不同的数（`-1` vs `0`），**控件里也得分开**。
4. ⚠ **`3×` / `9×` 的秒数按"这个技能自己的出厂时长"算**（不是全局起点值）
   ⇒ 同一个技能的四档秒数是固定的，但**不同技能的同名档位秒数不同**。
5. ⚠ **引擎侧已经能跑 0 秒了**（`advancePhase` 一个 tick 走完 = 瞬发），
   所以这一片只差"控件 + 点表"。

这条**没做**（brief：编辑器 UI 是另一片 ✗）。

### 6.3 ✅ 裁定三：`hp` 那条轴**先关着**（故意的，不是忘了）

`zeroTierK('hp')` 返回 **0** ⇒ 生命代价这条轴**没有 0 档**。
玩家 2026-09-21 裁定：**先关着** ✓，理由是**出厂内容没有任何一段付生命**。

⚠ 这是**故意关的**，不是漏了：
- 少了它，`hp: 0` 会被当成"一次改动"（出厂 0 → 现在 0 也报一笔），宗旨当场破；
- 要开它，**先得有那份内容**（有技能拿生命当代价，且玩家真的把它拖到 0）。
- 开关只有一处：`zeroTierK()` 里 `kind === 'hp'` 那一支（返回 0），
  开的时候顺手在 `Rates` 里加一个 `hpZeroTierMultiplier` 即可。

## 九、留给下一片的坑（顺手记下，免得再查一遍）

1. **0 档的"删段"路径**：删掉一整段时，它的时长 + 能量 + 冷却三笔 0 档
   都要补上（`.scratch` 里那两条断言盯着）。⚠ 冷却是**技能唯一属性**：
   它出厂扛在哪一段、玩家把那段删了，0 档要**退到现在的第一段**上，
   否则那一笔会**跟着一起消失**（实测：−88 掉到 −10）。
   ⇒ 代码注释已留（`ledgerEntries` 的"删段"那一段，⚠⚠ 那条）。
2. **`absoluteEntries` 里那条"0 点也要留下"的分支**
   （`if (points === 0 && !instant) return`）：是为了让 0 档那一行在账上有个落脚点。
   ⚠ 一条 0 档记录和"这一段还有 20 能量"的记录**必须合成一条**，
   否则它们在 `entryKey` 上撞车，相对账会算出一笔谁也没做过的交易。
   ⇒ 代码注释已留（`ledgerEntries` 里 `keep` 那条，⚠⚠ 那条）。
3. **`-(K+1)*B` 不许拆成 `-K*B-B`**（浮点不等，round 之后差 0.1 点）
   ⇒ 代码注释已留（`zeroTierValue()` 的文档注释）。
