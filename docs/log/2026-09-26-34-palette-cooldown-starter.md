# 调色板去掉重合项 + 开局只给一格术式 + 状态悬停说明

  > 目前编辑器的规则可以添加"代价：扣能量""加冷却""额外伤害"等，很明显它们与
  > 下方可调整的变量的功能重合了，多此一举，删掉这些规则的可选项。
  > 目前数字键1到0仍然是释放技能而不是术式，改成这样：初始只有一个术式释放某个技能，
  > 现有技能库不改，玩家可以自行创造术式。
  > 待办项："司命负重"这种状态应该有鼠标移动到其上显示说明的功能。
- **动了哪些文件**
  - 编辑器：`web/src/editor.ts`（删 3 条模板、冷却那一块只留一个控件）
  - 校验器：`src/validator/checks.ts`（新增 `COOLDOWN_TWO_PHASES`）
  - 页面：`web/src/main.ts`（空键提示、状态悬停说明）、`web/index.html`（浮层样式）
  - 说明：`src/describe.ts`（`describeStatusTip`）
  - 内容：`content/scenarios/arena.json`（开局只有一格术式 + 只留血契记账器）
  - 测试：`tests/{pricing,describe,scenario,web}.ts`

## 一、调色板：删掉 3 条和滑块重合的

删的是：

| 删掉的 | 为什么重合 |
| --- | --- |
| ＋命中额外伤害 | 和"把固有伤害调高"基本一回事（它只是多一条 onHit 伤害规则） |
| ＋代价：扣能量 | 就是阶段上的「能量」滑块 |
| ＋代价：加冷却 | 它**本来就是**直接去改阶段上的「冷却」滑块（冷却 +3 秒） |

留下 6 条（**机制类**，滑块里造不出来）：命中减速、命中持续伤害、命中吸血、
击杀重置冷却、代价：扣生命、代价：自己变慢。

玩家的话："机制类规则仍然保留，只是把重合的数值规则删掉而已。"

## 二、冷却：**技能唯一的属性**

玩家原话：

> **冷却是技能的唯一属性，不能在前后摇都有冷却**，编辑器内可以选择这个唯一的
> 冷却属性在前摇/后摇进入冷却。

编辑器里其实**早就有**那个控件（「进入冷却的时机」：前摇 / 释放 / 后摇 + 没有冷却 +
一个秒数滑块，换时机是把冷却**搬**过去）。真正的毛病是：**同一个数字出现两处** ——
专门控件一个滑块，通用「代价」组里又有一个 `冷却` 滑块。玩家看到的是"两个地方
各有一个冷却"。

所以这一轮做的是：

1. **冷却不再进通用滑块列表**（`isCooldownLeaf` 过滤掉）—— 那个数字只有一个控件。
2. 控件上的话说清楚了：**冷却是这个技能唯一的属性**、一个时机 + 一个秒数、
   而且明确写着"这一段数字不会再出现在下面的滑块列表里"。
3. **校验器新增 `COOLDOWN_TWO_PHASES`**：两个阶段都写了冷却 = 报错。
   这条的后果原本是**静默**的 —— 引擎取大值（只生效一个），而定价两笔都算，
   玩家付了两次钱、账面还看不出来。（扫过内容：现在没有技能违反它。）
4. 顺手修了一处**漂移**：那个控件没找到点表时的兜底写的是 `[1,2,3,8,20]`，
   而点表是 `[2,3,8,20]`（1 秒冷却早就剪掉了）。现在两处都走 `leaves.ts`
   新导出的 `gridOf('cooldown')`。

⚠ **数据仍然写在某个阶段的 `cost.cooldown` 上**，没有挪到技能层。理由：
"代价付在哪一段"**参与定价**（早付是风险、晚付是安全，见 schema/README 的
"代价时机的定价必须分开"一节），挪到技能层会把这个信息变成"一个额外的引用字段"。
"唯一"是靠**控件 + 校验器**保证的。玩家要是希望字段本身也只可能有一个，
那是一次 schema 迁移（30 个技能），说一声就做。

## 三、开局只有一格术式

代码一直放的就是**术式**（按键走 `library.get(loadout[i])`），但出厂场景给玩家排了
**10 个单技能术式**、名字和技能一模一样 —— 看起来就是一条技能栏。玩家的话：

> 初始只有一个术式释放某个技能，现有技能库不改，玩家可以自行创造术式。

所以 `content/scenarios/arena.json`：

```
techniques: ["tech.magic-bolt"]          ← 数字键 1 = 魔法飞弹（最基础的远程）
activeTechniques: ["tech.blood-pact"]    ← 只剩血契记账器
```

- **那 10 份出厂示范没有删** —— 还在 `content/techniques/` 里，术式编辑器里能复制、
  加技能、换键。
- **按空格子会说一句**：「N 这一格还没装术式 —— 按 Tab 自己拼一个」。
  不说的话"按下去没反应"看起来像键坏了。
- **名刀·司命 / 猎手直觉不再白送**。玩家的原话：
  > 血契记账器不是被动，它是一种**特殊机制**，不在被动栏显示。
  > 前两个被动，它们应该只有在玩家创造术式、术式中有它们并且术式被挂载时才激活。
  所以它们跟着技能留在内容里，玩家把它们编进自己的术式、挂上去，才生效。
  ⚠ 因此 scenario 测试里那三处（名刀 / 背水 / 猎手直觉）得**自己挂**，
  而"挂"要两步：先 `registerTechnique`（`applyScenario` 只注册场景里列出来的），
  再 `setTechniqueActive`（那一刻 onCast 才会跑）。测试里抽成了 `mount()`。

## 四、状态悬停说明（玩家记的那条待办）

HUD 上「身上：· 司命·负重 3.2s」现在鼠标移上去会弹一个浮层：

> **司命·负重：生命上限 -15%（最长 10 秒）**

- 文字是**生成的**（`describeStatusTip`），不是手写 —— 数值一改它跟着变。
- 放在 `src/describe.ts` 里是为了**能被测**（`tests/describe.ts` 直接喂状态定义，
  不用把客户端 boot 起来）。
- 浮层**纯 CSS `:hover`**（不是 JS 监听鼠标）：状态行是每帧更新的 DOM，
  挂 mouseenter/mouseleave 得每次重建都重挂，很容易漏。
- 同时写了 `title` 兜底（触屏 / 无障碍 / 浮层没出来的时候）。

## 六、欠账

1. **冷却是"一个字段"还是"技能唯一的属性"** —— 现在是"控件 + 校验器"保证唯一，
   字段仍挂在某个阶段上（理由见上）。想让它连字段都只有一个，说一声。
2. 技能修正（技能编辑器里管数值和几何）。
3. 修饰技能：术式的连接卡 + 触发器卡（触发器要引擎支持并行施法）。
4. 锚点表（`content/anchors.json`）：`calibrate` 的拟合目标仍然不成立。
5. 阶段时长的 无 / 1× / 3× / 9× 四档。
6. 血祭斩的名字 / 介绍 / 「负值」标签、裂魂的「超模」标签仍然和机制对不上
   （上一轮的欠账，玩家说先不动内容）。
