## 二、改了什么

### 1. 账 = 「现在的技能」−「内容里的那个技能」

新增 `skillLedger(cur, base, o)`：两边各按同一套汇率算出**逐条**贡献，
按 **id**（不是下标）对上之后**相减**。于是：

- 出厂技能自己减自己 = **空账**（0 点、一条明细都没有）。这是宗旨的机械表述，
  `tests/pricing.ts` 拿一条断言钉死了它。
- 机制不变的那部分在两边一模一样，相减就没了 ——
  这正是玩家说的"**位移的机制本身不该有代价，位移的距离有代价**"。
- 改强（伤害 25 → 50）= 负；改弱（冷却 2 秒 → 20 秒）= 正。

`priceSkill`（绝对账）**留着**，但它现在的身份是**内部强度标尺**：
`npm run validate` 打印它，让人一眼看出"这个技能站在汇率表的哪个位置"。
它**不再**是配平判据 —— 判据是相对账。

### 2. 技能副本归**术式**所有

`Technique.skillCopies?: Skill[]`：只存**改过的**那几个（完整的一份技能，不是 diff）。

为什么挂在术式上（而不是做成一个全局"我的技能库"）：
**分享码**。码里只装一份术式；副本挂在术式上就自动跟着走 ——
收码的人不需要先有那几个技能。挂全局的话，"我这份术式依赖我还改过的一个技能"
是一条隐形依赖，而码里根本装不下它。

三处必须**同时**走 `skillLookupFor`（编译 / 定价 / 算血契），漏一处的坏法都是静默的：
编译漏了 → 改了数值放出来还是老数值；定价漏了 → 改强了不花点数；
血契漏了 → 负值术式按出厂版本扣。

### 3. 「出厂就负债」是一件**显式**的事

`Skill.factoryDebt?: boolean`。

- 不写（绝大多数）：出厂数值下是 0 点。
- 写了：它在出厂数值下就是它**绝对账**的那个数，玩家改不掉这件事。

为什么是**布尔**而不是一个手写的点数：手写的数字会和内容漂移
（伤害 200 → 300，欠的点数纹丝不动）—— 那正是 `pricing.ts` 开头记着的那个坑。
这里只标"它是不是负债件"，**欠多少由同一套定价算出来**。

出厂内容里标了两个，就是原来那两个负值术式的来源：**裂魂**、**血祭斩**。
于是"一放就吃血契"这件事在出厂内容里真实存在，血契也就有出厂消费者了。

### 4. 技能编辑器变成"**这份术式的**技能表"

- 顶部一行「副本属于：<术式>」—— 没有归属时**只读**并说明原因
  （"改了没地方去"比"不让改"更坏）。
- 点数条改成报**相对出厂值的差**：出厂状态写"还是出厂版本：0 点"，
  改一下才出现数字。负债件额外标一句"出厂就欠着 N 点，一用就吃血契"。
- 改动写进归属那份术式的 `skillCopies`，**改回出厂值就把副本删掉**
  （不删的话一份"和出厂一模一样"的副本会跟着分享码发出去）。
- 列表里标「已改」/「出厂负债件」。

### 5. 顺手修掉一个真 bug：投射物朝向

`spawnProjectileFrom` 用的是 **`ctx.actor.facing`**，而瞬时载体
（扇形 / 光束 / 范围）早就用的是瞄准解算出来的 `ctx.cast.facing`。

后果**只有 AI 会中招**：玩家手动瞄准时"脸朝的方向"就是"要打的方向"，
所以看不出来；AI 用 `locked` / `auto` 时方向算得对、子弹却按脸朝的方向飞 ——
表现成"法师一直在朝空气放飞弹"，看起来像 AI 笨，不像 bug。

修完 `battle duel --duration 12` 的数字**一位没变**（剑士 67.6 / 法师 71）——
因为 duel 里双方本来就一直脸对着对手。新加的回归测试
（`tests/battle.ts` 的"方向听「瞄准」的，不听「脸」的"）验过：
把那一行改回去，两条断言当场红。

## 三、为什么

**因为"0 点"必须有一个可执行的定义，否则宗旨只是一句口号。**

上一轮把宗旨写进文件之后，它其实有三种互不相同的读法：
"每个**可调值**有个默认档"、"每个**技能**默认为 0"、"出厂**零件**可以歪"。
这三种读法在代码里对应三种完全不同的实现，而它们在文档上长得一模一样。

玩家选了第二+第三种合起来的那条：**每个技能自己的出厂数值就是它的 0 点**。
它的代价我当面算给他看过（"出厂内容会全部变成 0 点、血契会没有消费者"），
他选了"按这个做，并且这一轮就把技能编辑器做成真的" —— 因为一个全是 0
的经济系统只有在玩家能改东西之后才活。

结果是一个比自己预想的更干净的经济：

- **你拿到的东西是公平的**（0 点）。这句话现在在界面上是**看得见**的。
- 想变强就得在别处还债（改弱、加冷却、加能量）。
- 术式必须收支相抵；收不抵支就是负值术式，拿血契付。
- 少数几个"生来就不公平"的技能**写在内容里**，不是暗门。

还有一条副作用值得记下来：**"结算账"和"强度标尺"从此是两件事**。
`calibrate` 原来靠"出厂技能恰好都该是平的"来拟合汇率 ——
现在那句话不再成立了（出厂内容**按定义**就是平的），
所以汇率得由玩家**声明**（锚点表），而不是从内容里拟合出来。见欠账。

## 五、又一次自己造成的损坏（记下来）

改 `docs/default-values.md` 的两列表头时，我图快用了
`(Get-Content x -Raw) -replace ... | Set-Content x`。

**整个文件当场废了**：PowerShell 按系统 ANSI（GBK）读那个 UTF-8 文件，
读出来已经是乱码，`Set-Content -Encoding utf8` 再把乱码写成 UTF-8 ——
中文全变成「鍚勬満鍒剁殑」，而且换行也丢了（一百多行并成几十行）。

**规矩（这次要真的遵守）**：中文文本一律用 `edit` / `write` 工具改，
**永远不用 PowerShell 的 `Get-Content`/`Set-Content` 组合**。
上一次记的是"不要用内联 `node -e` 带引号"，这次是同一条教训的另一半。

文件已经按上下文里的原文重建（122 行，UTF-8，无乱码）。

   玩家已经确认：技能修正改的是**它自己所在的这个技能**。

   `calibrate` 现在的拟合目标（"出厂技能应当各自配平"）在宗旨下已经**不成立**，
   所以它跑出来的 1.47 不再是"平衡质量"，而只是一个历史数字。
   该做的是：把玩家认可的那组交换（1 点 ≈ 25 伤害 / 20 能量 / 5 秒冷却 /
   4 米射程 / 3 米位移 / 1.2 秒前摇）写成一张**可改的锚点表**，
   让 `calibrate` 按它推导汇率而不是从内容里拟合。
   在此之前**不要**用它 `--write`。
4. 阶段时长的**无 / 1× / 3× / 9×** 四档还没实现（`docs/default-values.md`）。
5. 技能编辑器还不能"从术式那一页直接跳过来改这一段的技能" ——
   现在要自己在「副本属于」那一行选。玩起来觉得别扭的话再改。
