## 1. ★ 先给用户点名要的那个落点：**现有深度上限在哪**

```
src/sim/pipeline.ts:126        export const MAX_ACTION_DEPTH = 4     ← 用户要的答案（改动前）
src/sim/pipeline.ts:339        注释：depth 用来限制触发链……
src/sim/pipeline.ts:902        if (ctx.depth > MAX_ACTION_DEPTH) return   ← 唯一的老消费者
```

grep 全仓（`src` / `tests` / `tools`）：**只有这三处**，也就是说它是"命中链"的唯一刹车，
`export` 着但**当时没有任何别的调用方**。

### 1.1 ⚠⚠ 为什么"弹射的上限"不能直接写在 `school.ts` 里（这一片唯一需要想清楚的结构问题）

弹射的次数上限**必须**和它是同一个数（用户硬命令）。可是那个数住在 `sim/` 里，而
**参数的夹取**住在 `src/school.ts` —— 而 `school.ts`：

- 是**纯函数模块**（当时的纪律：只 `import type`）；
- 被**编辑器**（`web/src/**`）import。

⇒ 让 `school.ts` 去 `import './sim/pipeline.ts'` 会同时带来两件坏事：
① `school → pipeline → compile → school` 的**环**；② 把整张 sim 图拖进每一个读 school 的地方。

### 1.2 做法：把**那一个数**搬到叶子模块（`src/limits.ts`）

| | 改前 | 改后 |
| --- | --- | --- |
| 定义处 | `sim/pipeline.ts:126` | **`src/limits.ts`**（⚠ **不 import 任何东西**的叶子模块） |
| `pipeline.ts` | `export const MAX_ACTION_DEPTH = 4` | `import { MAX_ACTION_DEPTH } from '../limits.ts'` + `export { MAX_ACTION_DEPTH }`（**原来的导出路径一个字都没改**） |
| 值 | `4` | `4`（**一个字节都没改** —— 这不是平衡改动） |
| 消费者 | `executeAction` 一处 | `executeAction`（**行为一字不变**）+ 弹射的发射那一刻 + `school.ts` 的夹取 + 校验器 + 账本 |

⚠ 也就是说：**这个数仍然只有一份**。弹射"最多弹几次"读的就是它 ——
数据里的 `params.maxBouncesCap` **可以存在**（编辑器要一个滑块范围），但它**说了不算**
（引擎取 `min(数据, MAX_ACTION_DEPTH)`），而数据写超过引擎上限时**校验器报错**
（`MODIFIER_BOUNCE_OVER_CAP` / `MODIFIER_PROTO_BAD_PARAMS`）⇒ **不是静默地夹住**。

⚠⚠ 为什么这件事真的会"绕过深度保护"（用户点名的那个自反馈）：弹射是一条**链**，
链上**每一段都是一颗新子弹**（`projectile.ts` 的 `bounceToNextTarget`）
⇒ `executeAction` 拿到的 `depth` **每一段都从 0 开始，不会自然累加**
⇒ 那个上限是这条链**唯一**的刹车。

## 2. 「弹射」做成了什么样

### 2.1 命中之后放一颗**新子弹**（不是把这一颗掉头）

`runProjectileHit`（`projectile.ts`）在"这一下该结算的都结算完了"之后调 `bounceToNextTarget`：

| 环节 | 落点 |
| --- | --- |
| 判定"弹给谁" | `nearestProjectileTarget(world, p, judge, spec, **Infinity**)` —— ⚠ 和追踪**同一个函数**（改名前的 `nearestHomingTarget`），跳过条件逐条共用 |
| 新子弹 | `spawnProjectile(pos = 命中点, dir = 朝下一个敌人, delivery = spec.flight)` |
| 次数 | `bounce.left - 1`（0 ⇒ 不弹，"就停在那儿"） |
| 衰减 | `bounce.amountScale × damageFalloff`（**连乘**，第 k 段 = `0.7^k`） |
| **不许弹回打过的** | `hitIds: [...spec.hitIds]` **照抄带过去**（拷贝，不是共享引用） |

⚠ 「掉头」为什么不行：那一颗的 `lifetime` 已经飞掉一半，第二段可能在半路**静默过期**
（表现是"我设了弹 2 次，它一次都没弹" —— 那正是这一整轮在清的静默失效）。
⇒ 新子弹出生时 `lifetime` 是全新的，而且它自己带"打过谁"。

⚠ **方向解算不用三角函数**：只要 `(目标位置 − 子弹位置)` 归一化（`Math.sqrt`）；
解算不出方向 ⇒ **不弹**（和"找不到下一个"同一条路，**不许凭空挑一个方向**）。
⚠ 衰减也是**连乘**而不是 `pow`（`Math.pow` 不在纯净性白名单里）⇒ 可重放。

### 2.2 ⚠ 衰减落在哪：`ActionContext.amountScale`

载荷里的 `amount` 是**未解算**的 `ValueSpec`（可能是 `{ ref: 'weapon.damage' }`），
编译期乘不了它（那时候还不知道施法者是谁）⇒ 只能在**结算那一刻**乘：

```
executeAction:  const amount = resolveValue(p.amount, ctx) * (ctx.amountScale ?? 1)
```

⚠ 缺省 `1` ⇒ 引擎里**没有任何一条别的路**写它，`x * 1` 在 IEEE754 里**逐位等于 x**
⇒ 老内容的行为一个字节都不变（`battle` 哈希逐位不变就是证据）。
⚠⚠ **第二版（用户 2026-09-30 裁定）：衰减只作用于伤害，`heal` 照原值** ——
用户原话："衰减只作用于伤害，不要乘 heal ✗ —— 用户原话只说'伤害' ✓
而且'会弹的治疗'是另一种机制 ✗"。
⇒ 一颗被弹射修饰的**治疗**弹丸，第二段治得和第一段一样多
（`tests/scenario.ts` 第 62c 节拿真的子弹打两次治疗钉着它；
落地是 `executeAction` 那一支 `p.kind === 'damage' ? raw * scale : raw`）。

### 2.3 ⚠⚠ 判据共用：`homingAppliesTo` → `carrierFliesInWorld`

| | 改前（日志 56） | 改后（日志 58） |
| --- | --- | --- |
| 名字 | `homingAppliesTo(kind)` | **`carrierFliesInWorld(kind)`** |
| 函数体 | `return kind === 'projectile'` | **一个字都没改** |
| 消费者 | 校验器那条警告 + 账本（不收钱） | 那两处 + **弹射的两处**（校验器 / 账本），共四处 |

⚠ **追踪的行为因此完全不变**（用户硬命令："不许改追踪的行为"）——
只是名字从"追踪专用的判据"变成了"这个载体会不会在世界上飞"，
而两个零件读的是**同一个函数**。测试里甚至有一条直接钉住这一点：
**同一束激光上同时装追踪 + 弹射 ⇒ 两条警告都报**（`tests/weapons.ts`）。

## 3. 点数：三条汇率（⚠ **只标"待签字"，这一片没有为任何容差压低它们**）

`balance.json` 的 `modifierRates`（⚠ **故意不放进 `rates`** —— 那会立刻改 `npm run calibrate` 的输出）：

| 键 | 建议值 | 它是什么 |
| --- | --- | --- |
| `bounceBasePerPoint` | **1.2** | 装上这个零件的底价（⚠ 不许是 0；和追踪同价 —— 两个零件**可以同时装**） |
| `bouncePerBouncePerPoint` | **0.7** | 每多弹一次（≈ 三分之一份；每一次都是**一次新的命中结算**） |
| `bouncePerFalloffPerPoint` | **0.8** | 衰减每少 1（账按 `damageFalloff − 原型下限` 收 ⇒ 全衰减不收这一项） |

公式（`pricing.ts` 的 `modifierPointsOf`）：
`点数 = −round(底价 + 次数 × 每次 + (衰减 − 下限) × 每点衰减)`
（**负** = 花额度，和份数类 / 排布 / 追踪同一个方向、和等待相反）。

- 默认那一档（2 次 / 0.7）= `1.2 + 1.4 + 0.48 = 3.08` ⇒ 印成 **−3 点**；
- 最贵那一档（4 次 / 1.0）= `1.2 + 2.8 + 0.72 = 4.72` ⇒ 印成 **−5 点**；
- ⚠⚠ **最贵那一档会跟着引擎的深度上限一起动**（次数上限就是 `MAX_ACTION_DEPTH`）——
  这是"上限只有一个数"在账本那一侧的自然结果，也是**故意**的。
