# 日志 52 · 修饰零件「等待 X 秒」

日期：2026-09-30 ｜ 切片：修饰技能（日志 48 那套原型 / 副本 / 执行器）的第三片

**一句话**：在序列里某一格**前面**插一段空档，让**后面的技能晚 X 秒才发生** ——
这 X 秒里施法者被占用（锁哪些能力由**这个零件的参数**说了算，默认"锁施法 + 攻击、但能走"），
而且**默认不可打断**；X 是 **0.2 ~ 3 秒**，点数**按秒数**提供额度
（汇率是 `content/balance.json` 里的可调常数，**建议值待玩家签字**）。

⚠ 这一片**没有动编辑器 UI、没有动瞄准、没有动 CD 名牌**，也**没有做后面的零件**
（排布类 / 弹射 / 轨迹环绕）。
⚠ 两个「份数」零件（多重释放 / 一分为 X）的语义**一个字都没改**，内容里现有数值也没改。

## 2. 怎么落地（编译期插一格，运行期零改动）

### 关键决定：**等待 = 时间轴上的一个真阶段**

玩家那条规格里的三件事，**引擎里全都已经存在**，而且都挂在**阶段**上：

| 规格那一句 | 引擎里现成的落点 |
| --- | --- |
| 期间施法者被占用，不能继续释放技能 / 术式 | `occupiesCaster` + `locks`（`canActivate` 的 `locked`） |
| 「锁哪些能力」四项可勾 | `Phase.locks`（`Capability` 的四个值，`applyPhaseLocks` 真的执行） |
| 默认不可打断 | `Phase.interrupt`（`InterruptLevel` 三档之一） |

⇒ 所以这一片**一行新引擎代码都没有**：编译期插一个 X 秒的阶段，
后面那些阶段**自然**被推后 X 秒（时间轴是**一条线**，`tickCast` 一段一段地走）。
这同时把"**它不是并行**"变成了结构上的事实 —— 它根本没有"并行"可以在哪儿发生。

### 插在哪一格

`at` 说的是"它修饰**这一段里第几个技能**"（和份数类同一套读法），
空档插在**那个技能的第一个阶段之前**：

```
[A的前摇, A的命中, B的前摇, B的命中] + 「等待，at: 1（管 B）」
  ⇒ [A的前摇, A的命中, **等待**, B的前摇, B的命中]
```

⚠⚠ **等待阶段的 id 故意不带技能前缀**（叫 `#wait0` / `#wait1`，不是 `B#wait`）。
`advancePhase` 判"要不要过 `links` 那道门"的**唯一判据是"换了技能了吗"**（比阶段 id 的
技能前缀）—— 挂上 B 的前缀的话，"从等待进 B 的第一个阶段"就**不过门**了，
`links` 的条件再也拦不住 B（表现是"条件没满足它照样放"）。挂在段级前缀上，
"进等待"和"等待 → B"各过一次门、两次算的都是 `links[B-1]`，和没有等待时**同一条判据**。

⚠ **它不像份数类零件那样只认 `at: 0`**：插阶段这件事对任何 `at` 都是同一个动作，
没有"一次激活里两条时间轴"的麻烦 ⇒ 份数那条 `MODIFIER_GROUP_AT_NOT_WIRED` 警告
**不适用于等待**（发那条警告等于告诉玩家一句假话）。

⚠ 还有两道**兜底**（都是"不许静默"）：编译期同一格只插第一个（手改存档里两个等待副本
叠一起时顺序仍然确定），插完**核对阶段总数**——对不上就**整段退回原样**
（宁可"等待不生效、校验器会报"，也不要悄悄少掉一个前摇）。

### 三个参数怎么读

和份数放在同一个位置、同一个理由（sim 里没有内容层，运行时"忘了读参数"是静默的）：

- **秒数**：副本优先、原型兜底，再**夹进 `[0.2, params.max]`**；夹了报一条 `CompileProblem`
  （手改的存档 / 老分享码绕过校验器 —— 不说的话玩家看到"我写了 12 秒，它只等了 3 秒"）；
- **锁**：只留 `Capability` 那四个值（认不出的丢掉，而校验器会**报出来** ——
  丢掉的表现是"我锁了它，它没锁上"）；
- **打断档**：认不出就按默认的 `'none'`。

### 账：**只有一把尺，而且只收一笔**

- `pricePhase` 见到 `Phase.wait` **直接返回 0** —— 等待的价 = `秒数 × waitSecondPerPoint`，
  记在 `modifierPointsOf` 里。
  ⚠ 为什么不让它走 `pricePhase`：那会把"**时长**"（`duration × phaseSecondPerPoint`）
  和"**扛打断**"（`uninterruptibleCredit`）各算一遍 ⇒ **同一件事收两次钱**，
  而且两次的汇率各自可调，账面会自相矛盾。这也让**一个旋钮管全部**。
- 符号和份数类**相反**：多一份是好处（花额度 = 负），空出一段时间是**代价**
  （提供额度 = 正）—— 玩家定稿 §八 ③："越长越亏"。
- 汇率 **故意不在 `rates` 里**（在 `modifierRates` 里）：`tools/calibrate.ts` 的拟合变量是
  `Object.keys(DEFAULT_RATES)`，加进去标定输出立刻变，而标定必须逐行不变。

## 3. 建议的点数汇率（⚠ **待玩家签字**）

| 旋钮 | 在哪 | 建议值 | 状态 |
| --- | --- | --- | --- |
| `modifierRates.waitSecondPerPoint` | `content/balance.json` | **0.6 点 / 秒** | ⚠ **待玩家签字** |

**理由（为什么是 0.6）**

1. **参照系 = "一段不可打断的阶段"的价**：`rates.uninterruptiblePhase` = **0.601 点**。
   玩家给这个零件的定位是"**一段可自由排的、挨打不会没的空档**" ——
   它买到的东西和"这一帧是霸体帧"是同一类，所以一把尺量到底：**1 秒等待 ≈ 0.6 点**。
   ⚠ 玩家定的另外两条（"默认不可打断" / "占用施法者"）**故意不另收钱**：
   它们不是这个零件买来的好处，而是它的**定义**（能打断的话"晚 X 秒"当场消失），
   再说它们今天在引擎里本来就执行得到，收钱会和上面那条"一段不可打断阶段的价"撞车。
2. **它必须小到"最长那一档也不炸账"**：玩家定的上限是 **3 秒** ⇒ 一笔最多
   `3 × 0.6 =` **1.8 点**，正好落在配平容差（`balanceTolerance` = 2）之内。
   这不是审美：容差是这本账的**分辨率**，一笔修饰比容差还大的话，
   "要不要放这个零件"就不再是容差内的小调整，而是**整门术式的配平结果**。
3. **最短那一档老实交代**：下限 0.2 秒 ⇒ `0.12 点`，**低于容差** —— 也就是说
   "最短的等待"在账面上几乎看不见。这是**故意的取舍**（0.2~3 秒是一根**连续旋钮**，
   不是三档离散档位；旋钮的短头便宜、长头贵），写在这里让玩家裁定：
   想让每一档都看得见就得把汇率提到 2 点/秒左右，而那时 3 秒 = 6 点、第 2 条当场不成立。

**收钱的口径**：一秒一笔，记在**术式**的账上（`from: 'technique'`），
一条明细（`修饰「等待 X 秒」· 空出 1.5s`）。
秒数取**夹过之后**的那个 —— 账和引擎必须是同一个数（和份数那条规矩同源）。

## 6. 待裁定项（⚠ 我没有自己定，除非写明"我定了"）

### 6.1 ⚠ **我顺手改了两句"已经变成假话"的显示文本**（cli 层，不是 UI）

`npm run validate` 打印修饰原型时，标签是「**技能**」，而下面那句 `priceless` 写着
"修饰技能的点数怎么算**还没有定**（玩家未给规则）"。**第二句从日志 51 起就不成立了**
（份数类已经进账），这一片又加了一个进账的零件 ⇒ 留着它等于让读者以为"等待是白送的"。

- 标签改成「修饰原型」（判据：既不是术式、也不是武器、也没有 `skill` 记录）；
- 那句话改成"修饰零件本身不算账（原型没有 `points` 字段）—— 它只在序列里改写别的技能，
  所以账记在**术式**上"，并把两个汇率（含本片的）点名。

⚠ 这**不在**"不要动编辑器 UI"那条红线里（动的是命令行校验器的输出文本，
`web/src/**` 一个字节没动），但**它是我自己判断要改的**，写在这里待玩家裁定。

### 6.2 ⚠ **等待期间"能不能被别人打断自己的别的什么东西"** —— 玩家没写

规格里只说了"这段空档自己不被中断"。**没有规定**的是：
等待期间施法者身上挂着的东西（持续状态、引导中的别的术式、光环…）会不会因为这段等待而变。
这一片**一个字都没碰**（等待是一个普通阶段，它不主动改任何状态）——
但"要等 X 秒"和"这 X 秒里我的状态还在不在"是两件事，**没有自己定**。

### 6.3 ⚠ **等待要不要进 HUD 的预判** —— 玩家没写

- 现状：等待阶段**是**编译产物里的真阶段，所以"这份术式总共多长"那种读数**自动**包含它
  （`describe.ts` / HUD 的时间轴读数都看得见）；
- 但 HUD 会不会**单独**画出"第 0.3~1.8 秒是一段等待"（比如一格灰色的进度）、
  以及按下去之前会不会提示"这一下要等 1.5 秒"，**没有规定**。
这一片**没动 HUD**（红线里那条"不要动编辑器 UI"是编辑器；HUD 是另一处，
而这也**不是**本片的验收项）。

### 6.4 ⚠ **`cancellable: false` 是我按先例取的**（唯一一处"我自己定的"）

等待阶段的 `cancellable` 写成 **false**（不可被玩家主动取消）。理由和"默认不可打断"同向：
"排好的等待被自己取消掉"的后果和"被打断"同构（后面那个技能**提前**打出来）。
⚠ 但玩家**没说**这一条；而且 `cancellable` 这个字段**引擎今天一处都不读**
（只在 schema 和编辑器里活着）。所以：写 `false` 是**保险**（将来编辑器接上主动取消时，
默认行为不会突然变成"等待可以被吞掉"），**待玩家裁定**。

### 6.5 ⚠ **不锁施法时，等待期间能插别的招、而且两段施法同时在跑**

玩家定的默认是"锁施法 + 攻击"，所以默认配置下这个问题不存在。
但**参数可以改成不锁施法**（玩家明说"默认只是建议初值、可改"），
那时引擎今天的实际行为是：别的术式**能**插进来，而且原来那段等待**不会**被打断
（`activate` 里**没有**"新施法打断自己正在放的"这条路 —— 打断只发生在挨打 / 被控 / 人死了那几处）
⇒ **两段施法同时在跑**，等于"这段时间可以一心二用"。

⚠ 玩家没说过这段空档里能不能插招，所以这一片**没有拦、也没有改**，
只在 `tests/scenario.ts` 第 49 节把这个行为**钉住**（免得它悄悄漂成别的样子），
并在这里记成待裁定项。

### 6.6 ⚠ **等待和份数类零件叠在同一个技能前面** —— 没有规定

`kind` 不同 ⇒ "一条序列里不叠同类"**放行**（和份数那两种之间的关系一样）。
但**叠加怎么算没有规定**：等待是"往后推 X 秒"，一分为 X 是"同一个技能打 X 份"——
"先等再一起打"和"每一份各自等"是两种读法。这一片**没有自己定**（插阶段是按位置插的，
所以引擎今天的行为是"等完再一起打"），记在这里。

### 6.7 ⚠ **`at > 0` 的等待在"前面那个技能被跳过"时仍然会等**

连接门（`links`）跳掉一个技能时，**等待不跟着跳**（插阶段是按位置插的，
运行时的跳过逻辑认的是技能）。也就是说："A 没打到人 → B 被跳过，但那段空档照样等完"。
⚠ 玩家没规定这一条；**没有自己定**（改成"门没过就跳过等待"要动 `advancePhase`，
那是另一件事）。

### 6.8 ⚠ 武器侧术式上的等待**不进账**（和份数那条同源）

账记在**术式**上，而"武器侧术式不算账"是现行规矩（`priceless`，日志 46 的欠账）
⇒ 一把武器上普攻挂了「等待」，今天账上看不见。这不是这一片引入的。
