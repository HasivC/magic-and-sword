## 一、"游戏没有识别出来" —— 根因是一条**静默的丢弃**

`recompileAll()` 里本来就有这条（而且注释写得挺得意）：

```ts
// ⚠ 空术式不编译 …… 所以它**不进 library**：技能栏里也不会出现一格按不出东西的键
if (skillCount === 0 && sequenceCount === 0) { library.delete(t.id); continue }
```

"不进 library"这件事本身没错（空草案是编辑器的正常中间状态，编译它只会刷一屏红字），
**错的是没人说出来**。连着三条静默链：

1. 空术式不进 `library`
2. `restart()` 里 `loadout = techniqueIds.filter(id => library.has(id))` —— 它被过滤掉
3. 技能栏是按 **`loadout`** 画的 —— 于是那一格**凭空消失**

玩家看到的：编辑器说"装到 键2"、toast 说"技能栏换了，这局已重开"、
游戏里那一格根本不存在、按下去连一句提示都没有。他的原话"游戏没有识别出来"精准得可怕。

**改法（失败必须可见）**：

| 位置 | 现在 |
| --- | --- |
| 技能栏 | 按**玩家排的**（`savedLoadout`）画 —— 绑了什么就画什么；放不出来的那一格后面写**原因**（红字 + tooltip） |
| 按键 | `loadout` 里没有但存档里有 → 按**存档那一格**查出真正的原因说出来（"一个技能都还没加" / "编译不出来：…"），而不是笼统的"这一格还没装术式" |
| 编译出来了但有问题的 | 按下去之前先提示一句（悬空的技能引用会让它"能按但什么都不发生"） |
| 术式编辑器 | 空术式**不给**装键的下拉框，换成一句"先加一段技能，才能装到按键上"；有编译问题的术式在账那一块**红字写出来** |

⚠ 顺带说清一个区别：**"编译出来了"不等于"能用"**。
悬空的技能引用、坏掉的载荷都会让一份术式"能按但什么都没有" ——
所以 `techniqueProblems` 是**按术式**记的，给技能栏、按键提示、编辑器三处共用。

## 二、序列在冷却 → 放下一条（玩家定的规则）

玩家原话：

> 如果释放某条序列时其中的某个技能在 cd，则释放下一条序列。

实现放在 `pressSequence()`：按 `nextIndex()` 选出来的那一段激活失败、
而且原因是 `cooldown` 时，**绕到下一条序列再试**；绕一圈（最多 `count` 次）都不行，
报**第一个**原因（那才是玩家按下时轮到的那个）。

⚠ **只有冷却会跳**，其它原因一律原样失败，而且这是刻意的：

- 能量不够 / 血契不够 = "这一下打不出来" —— 换一段打出去会让人以为按键自己乱放技能
- 被控 / 正在施法 = "整个人现在动不了" —— 跳段没有意义

想让它也跳是一个**明确的取舍**，不是这里漏了。

## 欠账（下一轮）

- **序列层在编辑器里还没有** —— 玩家说的"重大的错误"：
  > 在术式编辑器中我没看到序列，我设想的是术式中有若干条序列，每条序列放若干技能，
  > 按下按键就按顺序激活序列

  引擎那边**是有的**（`sequences` + `sequenceLinks` + 上面的冷却跳段），
  缺的是编辑器那一块 UI。⚠ 动手前要玩家拍一个模型：
  **序列 = 引用另一份术式**（现模型，每段有自己的 CD、可复用）还是
  **序列 = 内联在这个术式里**（改数据模型，编译/存档/分享码都要动）。
- **"施法中改朝向"那个技能**（玩家这一轮的第 4 条）：
  > 应该有一个"在另一个技能施法时改变角色朝向"的技能，这样就能重新瞄准，而且考验技术，
  > 这要求施法时锁死的是角色面朝方向。

  读法：方向仍然在施法那一刻锁死（日志 37），但要有一个**载荷**能**改写进行中施法的朝向** ——
  那是一个新载荷（schema + 执行器 + 定价 + 描述 + 校验 + 测试，六处），
  再加一份内容（技能 + 术式）。
- 其余按玩家说的"按顺序做"：技能修正 + 修饰技能（触发器）→ 锚点表 → 定价表缺项 → …
