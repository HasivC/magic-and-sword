# 命中特效：放大 + 落点改到怪物表面

- **日期**：2026-09-19
- **触发**：玩家试玩后报的两条 ——
  「火花大小有点小」「播放位置应该在命中怪物的位置而不是怪物中心（大体型 Boss 会像自爆）」
- **动了哪些文件**：`src/sim/projectile.ts`（落点）、`tools/preview-sprite.ts`（新）、
  `tools/png.ts`（抽出解码器）、`tools/check-fx.ts`、`content/fx/magic-bolt-hit.json`、
  `tests/battle.ts`、`docs/fx-authoring.md`

## 改了什么

### 1. 落点：目标中心 → **目标表面**

原来事件里的坐标是 `target.pos`（中心）。改成**接触点**：

```
从目标中心朝子弹来的方向，退到目标表面
from = target.pos + normalize(projectile.pos - target.pos) * target.radius
```

玩家说得对：半径越大，中心点和表面点差得越远，**"自爆"的观感越明显**。
半径 3 米的 Boss 差整整 3 米。

⚠ 为什么不直接用子弹当前位置：碰撞判定是"距离 ≤ 子弹半径 + 目标半径"，
判中的那一刻子弹停在**目标表面外一个子弹半径**的地方 ——
小怪（0.5）配 0.5 的子弹，火花会飘在离身体半米的空气里。**投影到表面才对**。

### 2. 大小：2 米 → 3.5 米

`meters` 从 2 改到 3.5。判断依据是**拿怪物直径当尺子**：

| 比例 | 观感 |
|---|---|
| 比怪物小 | 像没打中 |
| 跟怪物差不多 | 像轻轻碰了一下 |
| **1.5~3 倍怪物直径** | 有力度 ← 命中火花该在这档 |
| 大过 4 倍 | 盖住怪物，看不清打的是谁 |

小怪直径 1 米，所以 2~3.5 米是舒服的范围。

### 3. 新增：序列帧预览器

```bash
node tools/preview-sprite.ts magic-bolt-hit --meters 4
```

把素材按世界尺寸合成到一张画布上，**三栏并排**：

```
[小怪 半径0.5米]      [Boss 半径3米]        [Boss 半径3米]
 接触点                接触点                目标中心 ← 旧行为
```

**这一轮的结论是看图看出来的，不是算出来的。** 上面那两个数字
（3.5 米、"表面 vs 中心"）都是先渲染三栏对比、再看一眼定的。

为此把 PNG 解码器从 `check-fx.ts` 抽到 `tools/png.ts`（编码和解码住一起），
两个工具共用。

## 为什么

- 玩家两条意见都对，而且第二条是**我的 bug 不是品味问题**：
  事件带的是"目标中心"，那个坐标从一开始就选错了。
- 尺寸是品味问题，但**品味问题也不该靠猜** ——
  所以做了预览器：把"多大合适"变成可以看的事，而不是来回开浏览器。

## 验证

`typecheck` 0 错 · `npm test` **538 个断言**全绿
（`tests/battle.ts` 80，新增「落点离目标中心的距离 = 目标半径」和
「Boss 身上差整整 3 米」两条）· `validate` 15/15 · `build:web` ·
纯净性 14 文件。

写测试时踩到一个坑值得记：**命中会击退目标**，所以跑完 40 tick 再读 `b.pos`
去比落点，会差出一个击退距离（实测 0.03 米）——
看起来像"落点算错了"。现在改成**在事件发生的那一 tick 记下目标坐标**。
（同一 tick 里坐标还没变：击退只是冲量，`integrate` 在投射物碰撞之前跑。）

## 欠账

- 落点是按"目标是个圆"算的。以后有非圆形碰撞体（胶囊、多边形），这里要跟着改
- 预览器用最近邻缩放（看强度会偏硬），真机是双线性
- `fps` 还是猜的 60，等玩家确认 AE 合成的帧率
