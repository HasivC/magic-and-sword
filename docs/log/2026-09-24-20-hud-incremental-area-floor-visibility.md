## 一、HUD：从"每帧重建"改成"只更新变化的部分"

这是玩家选的下一步，而且是**界面能不能变好看的前提**。

以前 `updateHud()` 每帧两次：

```ts
statsEl.innerHTML = `HP ${hp} / ${hpMax}　能量 ${en} ...`
skillsEl.innerHTML = rows.join('')
```

等于**每秒把整个 HUD 的 DOM 删掉重建 120 次**。后果是一整张清单，
而且每一条都不是审美问题：

| 想做 | 为什么做不了 |
|---|---|
| 血条平滑过渡 | 元素每帧都是新的，CSS transition 永远从零开始 |
| 技能格上加按钮 / hover | 鼠标还没移上去，元素已经被换掉了 |
| 冷却数字滚动 | 同上 |
| 状态图标上的倒计时环 | 同上 |

现在：**结构只建一次，之后只改变化的那几个字段。**

- 状态面板：骨架一次拼好（只放固定的字），血 / 能量 / 血契 / 敌人数 / tick
  全部就地改 `textContent`、`style.color`
- 技能栏：按 **`loadout` 签名**判断要不要重建（换技能栏、换场景才重建）；
  每帧只改冷却读秒、"还差多少血契"、和那一格的 `dim` class
- 身上那串状态：按**状态集合的签名**判断（剩余时长每帧在变，**不进签名**），
  时长就地改

⚠ **外观一个字都没变。** 这一步的意义是"以后才有得变"。

### 怎么证明它真的改对了

这是最难测的一类改动 —— 外观不变，功能也没多，怎么知道"每帧重建"真的没了？

给假 DOM 的 `stats` / `skills` 装了一个 **innerHTML 写计数器**
（getter/setter，`innerHTML` 是客户端唯一的写入入口）。
跑几帧之后断言写次数 **≤ 1**。

以前每帧写一次的话，跑 3 帧就数到 3 次以上，当场红灯。这条断言是
"结构只建一次"的**唯一可测证据**，没有它，哪天有人改回去也没人知道。

顺带在假 DOM 里补了两个字段，都是为了这一节：
- `style`（颜色现在是就地改的，以前是拼字符串，不需要）
- `removeEventListener`

## 二、范围收钱了（玩家选了"给它一个下限"）

标定出来的 `areaRadiusPerMeter` 只有 0.067 —— 12 米的扫描圈只比 6 米标准
贵 0.4 点，这条轴等于装饰。原因是**出厂内容本身**：那 22 个技能是在
"范围免费"的前提下调的数值，标定器只能拟合出一个接近 0 的汇率。

玩家定了："给它一个下限，让范围真的疼。" 所以 `tools/calibrate.ts` 里加了
`RATE_FLOOR`：

```ts
const RATE_FLOOR: Partial<Rates> = { areaRadiusPerMeter: 0.2 }
```

⚠ 这是**设计约束，不是数值约束** —— 注释里写清了：
标定器只会找"让出厂内容最平"的汇率，而"平"不等于"对"。
地板钉上之后 `areaRadiusPerMeter = 0.2`（12 米的圈贵 1.2 点，是原来的三倍）。

意外的好消息：**残差几乎没涨**（1.51 → 1.56），因为别的汇率替它让了路。
所以这次不用动任何内容数值。

## 三、`visibility`：查下来它**已经实现了**

玩家选了"补上实现"。但我先查了一遍，发现：

```ts
// src/sim/status.ts
export function visibilityOf(entity: Entity): number {
  let v = 1
  for (const s of entity.statuses) {
    if (s.visibility !== undefined && s.visibility < v) v = s.visibility
  }
  return v
}
```

**它是被读的**，而且 `findHostile` 会跳过看不见的目标（潜行就靠它）。
真正缺的是两样，我补的是这两样：

**① 一个防呆。** `visibility: 1` 是**空操作** —— `visibilityOf` 的起点就是 1，
取最小值永远取不到它。熔岩护甲里曾经躺着这么一行，看上去像在设置什么。
新增 `VISIBILITY_NO_OP` 警告（`> 1` 或 `< 0` 是错误 `BAD_VISIBILITY`）。
这正是玩家那条原则："改了不生效的属性不该出现在界面上让人拖。"

**② 一条测试。** 隐形有**两条路**，而只有一条被测过：
- 载荷 `perception setVisibility` —— 引擎在运行期造状态（潜行走这条，第 23 节测过）
- 状态 `StatusDef.visibility` —— 作者**直接在状态定义里写**（**没人测过**）

新增第 37 节：声明 `visibility: 0.5` → `visibilityOf` 是 0.5 而且**还能被锁定**
（判据是 `< 0.5` 严格小于，"半透明但还在"和"完全看不见"是两件事）；
再挂一个 `0` → 取最小值变完全隐形、锁定不到；摘掉一个 → 回到 0.5（不是直接回 1，
说明取的是当前集合的最小值）。
