## 这一轮只做了调研，没动代码

玩家在**考虑**自己设计 UI，还没定。这时候动 UI 代码有浪费的风险 ——
所以这一轮的产出是**给他设计用的底稿**：现状清单、缺什么、技术约束、成本分档。

## 核实出来的三件事（都不是审美问题）

### 1. HUD 每帧被整个重建

`updateHud()` 在渲染循环里每帧跑，里面是 `statsEl.innerHTML = ...` 拼字符串。
**等于每秒把 HUD 的 DOM 删掉重建 120 次。**

后果很具体：**不能有 CSS 过渡**（元素每帧都是新的，transition 永远从零开始）、
**不能有按钮和 hover**（鼠标还没移上去元素就没了）、不能做冷却转圈。

> **不是"画得不好看"，是"结构上做不了"。** 这个前提不修，任何设计稿都落不了地。

### 2. 配色散在 99 处

`main.ts` 22 处 + `editor.ts` 10 处 + `index.html` 的 CSS 67 处。
同一个蓝 `#58a6ff` 写了三遍（TS 常量表、TS 字符串、CSS）。
画布上的颜色在一张表里，HUD 的在 TS 字符串里，编辑器的在 CSS 里。

### 3. 画布和 HTML 两套视觉语言

怪物血条是 canvas 画的（硬边圆角矩形），玩家 HP 和状态是 HTML（GitHub 深色主题），
两套东西放在同一个屏幕上。

## 为什么

- 玩家问"还有其他问题吗"，我手上有从日志攒下来的一堆欠账，
  加上这一轮**新核实的三个结构性问题** —— 得一次说清楚，别挤牙膏。

## 我的建议

**下一步只做一件事：把 HUD 从"每帧重建"改成"只更新变化的部分"。**

- 它是唯一一件**不管玩家怎么设计都必须做**的事
- 它**不改变外观**，所以不会和设计稿冲突
- 不做它，设计得再好也实现不了

做完让玩家看一版"结构对了但还很素"的界面，再定设计到什么程度。
