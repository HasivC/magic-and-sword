# 拆成「技能 / 术式」两层 + 点数改成算出来的

- **日期**：2026-09-19
- **触发**：玩家重申了需求 —— 「**释放的是术式，修改的是技能**；术式由若干技能组成」
- **动了哪些文件**：`schema/skill-schema.ts`、`src/pricing.ts`(新)、`src/sim/compile.ts`(新)、`src/bridge.ts`、`src/validator/*`、`src/cli/*`、`web/src/*`、`content/`（全部 15 个文件）、`tools/calibrate.ts`(新)

## 改了什么

### 1. 数据模型拆成两层

```
技能 Skill        零件（阶段 + 规则 + 代价）   ← 玩家编辑的是它
   ↓ 被引用
术式 Technique    编排（哪几个技能、什么顺序、绑哪个键） ← 释放的是它
   ↓ 编译
编译产物          一条接起来的时间轴            ← 引擎唯一认的形态
```

`Technique` 不再自带 `phases` / `rules` —— 那等于每个术式只能有一个技能，
"术式由若干技能组成"在数据结构上根本不成立。

阶段 id 加 `技能id#` 前缀（两个技能都可能有个叫 `cast` 的阶段），
规则里的 `phaseId` 一起改写。**因此 `cast.ts` / `ai.ts` / `pipeline.ts` 一行没改。**

### 2. 点数从「手写」改成「算出来的」

删掉 `Rule.points` / `Phase.points` / `StatusDef.points`。
新增 `src/pricing.ts`：点数 = 内容的函数，改数值点数自己跟着变。

理由很直接：玩家在编辑器里把「30 伤害」拖成「300 伤害」，**点数纹丝不动** ——
等于可以白嫖。手写的价格表和数值是两份会漂移的东西。

### 3. 顺手修掉两个符号错误

- 状态强度用了 `Math.abs()` → **自我减益被算成收益**，"牺牲 X 换 Y"整个循环是反的
- 规则位买卖两边符号都反 → "复杂度税"变成了"鼓励复杂"

### 4. 新增 `tools/calibrate.ts`

汇率原来是拍脑袋定的，七个技能一个个配不平。标定器把 pricing 当黑盒，
用梯度下降 + 坐标下降拟合：**最大偏差 6.85 → 1.8，均方根 4.71 → 1.0**。
加了 `balanceTolerance`（±2）作为模型的"分辨率"，因为这张表还不认射程/投射物/频率。

## 为什么

- 玩家说得对：术式是编排，技能是零件。**改的是零件，放的是编排。**
- 点数手写是**原理性错误**（价格表和数值会漂移），不是实现 bug。
- 符号错误三次都是"玩家一试就发现、代码全绿" —— 所以补了 `tests/pricing.ts`
  把这些方向钉住。

## 验证

`validate` 15/15 · `run` / `battle` 实跑 OK。
