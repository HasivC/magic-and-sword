# 59 · 阶段时长改成**查表定价**（`档位 → 整数点数`）

- **日期**：2026-09-30
- **触发**：用户下的规格 —— **"不必有汇率这种线性关系，档位很少，挨个填值就行"**（确认后："可以"）
- **改了什么**：
  `content/balance.json`（新一栏 `tierTables` + 删掉 `rates.phaseZeroTierMultiplier`）
  + `src/pricing.ts`（查表机制 + 相对账改成查表 + 那份保险）
  + `src/validator/types.ts` / `checks.ts` / `index.ts`（`tierTables` 进类型、三条形状检查、`PHASE_TIER_NOT_IN_TABLE`）
  + `src/cli/validate.ts`（技能表提前建，变体的档位检查要用它）
  + `tests/pricing.ts`（那一节整个重写）
  + 文档（本文件 / 日志 README / `technique-system/README.md` / `STRUCTURE.md`）
- **没改什么**：编辑器 UI（`web/src/**`）**一个字节没动** ✗、别的旋钮的定价（追踪 / 排布 / 弹射 / 等待 / 伤害 / 冷却 / 能量）**一个都没动** ✗、
  内容里任何数值**一个都没改** ✗、瞄准 / CD 名牌 ✗
- **一句话**：阶段时长的价从 **`公式`**（`−(K+1) × 这一段价`，K = 9 住在 `rates` 里）换成
  **`查表`**（`0 / 1× / 3× / 9×` 四档，**挨个填一个整数**）；**K = 9 删干净了**，
  而**出厂内容仍然是全 0**（32 技能 + 14 术式逐个打印）。

---

## 一、这一片只做两件事

1. **机制**：把"查表定价"做出来 —— 一张**数据表**：`档位 → 整数点数`，住在**内容侧**，**可被校验器读**；
   ⚠ **不许硬编码成 `if` / `switch`**（档位集合本身也是数据，见 §三）。
2. **第一个用例**：**阶段时长**的四档 `无 / 1× / 3× / 9×`（日志 50 定的档位）—— 现在它是公式算的，
   **改成填表**。

## 二、机制落在哪（报告第 1 节）

| 问题 | 答案 |
| --- | --- |
| 表住在哪个文件 | **`content/balance.json` 的新一栏 `tierTables`** —— `tierTables.phaseDurationPoints`。⚠ **不能新开一个内容文件**：`npm run validate` 数的是内容文件个数（57），多一个文件那一栏就变了；而 `balance.json` 本来就是"**所有价格都是数据**"的家 |
| 表的形状 | `档位（倍数字符串键）→ 整数点数`；`_` 开头的键是**文案**（逐条理由），和 `rates` / `modifierRates` 同一个惯例 |
| 谁读它 | `src/pricing.ts` 的 `readTierTable` / `tierTableOf` / `tierOf` / `tierPointsOf`；`priceOptionsFor` 把整栏塞进 `PriceOptions.tierTables` ⇒ **命令行 / 校验器 / 标定器读的是同一份**（这是"可被校验器读"的机械含义）。校验器另有三条形状检查（`checkBalance`）：表在不在 / 中性档是不是 0 / 是不是整数 |
| 怎么可复用 | **加第二条轴只要在 `tierTables` 里添一个键**（表名 → 档位表）：机制（读表 / 认档位 / 查值）一行代码都不用改。`tests/pricing.ts` 里有一条断言就是钉它的：**往表里添一档 27× ⇒ `tierOf` 当场认得出来**（档位集合是**数据**，不是代码里的 `[0, 1, 3, 9]`） |
| 账怎么算 | 相对账里"这一段的时间"那一项**被换成表里的整数**：`账上这一头 = 这一段现在的价 − 现在那一项 + 出厂那一项 + 表[档位]`（加回"出厂那一项"是为了让出厂那一头一个字都不用改）。⚠ **绝对账没动**（`phaseSecondPerPoint` 那套公式留给 `priceSkill` / 标定器，理由见 §五） |
| K = 9 呢 | **删干净了**：`Rates.phaseZeroTierMultiplier` / `DEFAULT_RATES` / `balance.json` 的键与说明 / 老那两条断言一起删。`TierAxisKind` 里 `'phase'` 那一支也删了（剩下能量 / 冷却两条，**它们一个字没动**）。文档里写清了：**9× 档的价现在是"人填出来的"**（表里那一行旁边就是理由） |

## 三、建议的点表（⚠ **待用户签字**）

`content/balance.json` 的 `tierTables.phaseDurationPoints`（值 = **账上那一行的净额**，相对 `1×`）：

| 档位 | 值 | 理由（表里的 `_<键>` 也各写了一份） |
| --- | --- | --- |
| **0（无）** | **−6** | 用户原话「**没有前摇很超标**」⇒ 它必须是全表最贵的一档（是 9× 档那笔额度的 1.5 倍、3× 档的 3 倍）。取 −6 的参照：① 旧公式的**中间量级**（中位那一段 0.2 秒约 −1.9、0.5 秒 −4.75、1 秒 −9.49）；② 一个出厂技能的净值量级是 2~4 点 ⇒ 一笔 −6 点**足够压得动整门术式**，又不像旧的 8 秒冷却 0 档（−14.4）那样一笔见底；③ 6 = 3 个"多打一份"（2 点），一档一格看得见 |
| **1×（出厂本身）** | **0** | **定义**，不是价格：账算的是"你改了多少"，出厂值自己减自己 = 0（"出厂全 0"的地基；校验器 `TIER_TABLE_NEUTRAL_NOT_ZERO` 盯着） |
| **3×** | **+2** | 拉成三倍长是**代价** ⇒ 提供额度。参照"**多打一份**"= 2 点（`modifierRates.extraCopyPerPoint`，那个注释写的是"多一份 ≈ 半个技能"）；旧公式在中位那一段只给 +0.35 点（整数账上就是 0，等于这一档白给）⇒ 取 2 是往旧公式的**上沿**靠（1 秒那一段 +1.73）。同时满足：≥1 点、比 1× 大、比 9× 小 |
| **9×** | **+4** | 比 3× 档**再翻一倍**（旧公式 3× : 9× 是 1 : 4，但整数表里 3× 那格被"至少 1 点"垫高过）。⚠ **这个价现在是"人填出来的"**：它以前是 `+8 × 出厂时长 × 汇率`（1 秒那一段 +6.90）—— 4 取的是**中间量级**，故意的：表**不随时长变**，免得"拿一条 0.1 秒的段拉到 9× 就白拿 7 点" |

⚠⚠ **两条不变式**（`tests/pricing.ts` 逐条钉着）：**0 档比 9× 档贵**（不许倒挂）、**|0 档| ≥ 2 × 3× 档**（"贵得多"）。

⚠ **这一片**一个已有数据都没改（用户硬命令：别的旋钮的定价留在后面几步）。

## 四、两道保险（用户刚定的，都必须做）

### 4.1 内容里出现的取值必须在表里 ⇒ **报错**（不许静默当 0 点）

- 判据只有一处：`pricing.ts` 的 **`phaseTierProblems(cur, base, o)`**（`tierOf` 认不出档位 = 表外取值）。
- 校验器把它接在 **`validateSkill`** 里（错误码 **`PHASE_TIER_NOT_IN_TABLE`**，路径指到 `phases[<段>].duration`）：
  ⚠ **基准只能是变体的 `basedOn` 那份基础技能** —— 出厂技能（没有 `basedOn`）的基准就是它自己 ⇒ 恒为 `1×` ⇒
  **对出厂内容一个错都不报**（这正是"出厂全 0"那条常驻断言不受影响的原因）。
- ⚠ **落不到档位上时，账上仍然跟着内容动**（退回"两条绝对账相减"的老行为），**同时**报错 ——
  两件事一起才叫"不静默"：数字会动 + 明说这个取值不在表里。
  如果把它实现成"指不出来 ⇒ 那就是 0 点"，就**正好复刻**了本项目当年删掉手写 `points` 的那个病
  （"把 30 改成 300，点数纹丝不动"）。
- ⚠ **蓄力段（`duration: -1`）不在档位轴上**（哨兵值，价是 `chargePhasePerPoint` 一笔定额）：
  出厂就是蓄力、或者把一段固定时长改成蓄力，**都不报**这一条（那是另一根轴，误报就是假警报）。

### 4.2 出厂值锚定 0（那条常驻断言继续绿）

- **中性档必须是 0**：它现在是**数据**（表里那一行），校验器 `checkBalance` 会给它一条 **`TIER_TABLE_NEUTRAL_NOT_ZERO`**（错误）。
- 证据（逐个打印，见 §六）：**32 技能 + 14 术式，合计与条目数两个都是 0**。

## 五、为什么绝对账一个数都没动（⚠ 待裁定项之一）

`phaseSecondPerPoint`（阶段时长每秒多少点）**留着**，它现在只服务**绝对账**（`priceSkill` / `npm run calibrate` 的输入）。
理由：绝对账**没有"出厂值"这个参照**（`priceSkill` 手里只有一个技能），档位在那里无从谈起 ——
而日志 50 §3.1 那条"绝对账一个数不动"是玩家当场纠正过的一条规矩。

后果：`npm run calibrate` 只变了**一行**（建议的 `rates` JSON 里少了 `"phaseZeroTierMultiplier": 9`），
**最大偏差 7 / 均方根 8.117 → 2.735 一个字没变** —— 因为 K 本来就只进相对账（标定器拿 `priceSkill` 当目标函数）。

⚠ **如果用户要的是"阶段时长彻底不再有秒单价"**（连绝对账也不用 `phaseSecondPerPoint`，
也就是"0.1 秒的前摇和 1 秒的前摇在绝对强度上等价"），那是**另一片**：
它会动标定器的拟合输入，面比这一片大得多。**这一片没做，列为待裁定项**。

## 七、测试（这一片新加/改写的）

`tests/pricing.ts` 的「档位」那一节**整个重写**成「查表定价」（+17 条），断的是**四件不同的事**：

1. **表本身**：读得到 / 中性档 = 0 / 都是整数 / 单调 / 不倒挂 / **|0 档| ≥ 2 × 3× 档**；
   ⚠ **代码兜底 `DEFAULT_TIER_TABLES` 和内容侧那张表逐位相同**（理由见下）。
2. **逐档**：`0 / 1× / 3× / 9×` 四档各自的账 **= 表里的那个整数**（一个近似都不用）；
   `1×` 连一条明细都没有；删掉一整段 = 拖到 0 秒（**同一个 0 档价**）。
3. **数据驱动**：表里每档翻倍 ⇒ 账翻倍；**往表里添一档 27× ⇒ `tierOf` 当场认得**（档位集合是数据）。
4. **那道保险**：1.7× / ×10 ⇒ `phaseTierProblems` 报出来；**四个档位一个都不报**；
   **变体 + 校验器 ⇒ `PHASE_TIER_NOT_IN_TABLE`**；表外取值时账上**不是 0**；蓄力段不报。

### ⚠ 为什么代码里还有一份表（`DEFAULT_TIER_TABLES`）

`web/src/**`（编辑器 UI）**当轮冻结**，而它自己手工拼 `PriceOptions`（不带表）⇒ 没有这份兜底，
编辑器里那条点数条会**退回老的线性式**，于是"编辑器显示 +2、命令行按 +1 扣" —— 这个项目最恨的那类漂移。
所以：**内容侧那份是真相，代码那份是兜底**，而 `tests/pricing.ts` 钉着**两份逐位相同**（改一边不改另一边，测试当场红）。
⚠ **能动 `web/src/**` 的那一轮**：让编辑器走 `priceOptionsFor`，然后**把兜底那份删掉**（连 `PriceOptions.tierTables` 的兜底一起）。

## 八、⚠ 待裁定项（用户签字之前，这些都算"起草"）

1. **点表本身**（§三那四个数）：`0 → −6 / 1 → 0 / 3 → +2 / 9 → +4`。全部是**建议值**，理由逐条写在表里。
2. ⚠⚠ **表不随时长变**（这是"挨个填值"的直接后果，用户签的规格里就有"不必有汇率这种线性关系"）：
   0.1 秒的段和 1 秒的段，**同一个档位同一个价**。两个具体后果：
   - 「取消一个 0.1 秒的前摇」和「取消一个 1 秒的前摇」**一样贵**（旧公式是 −0.95 / −9.49，差 10 倍）；
   - 反过来，**短段拉长更划算**：一条 0.1 秒的段拉到 9× 现在给 **+4**（旧公式 +0.69）——
     也就是"拿小段刷额度"这条路以后是存在的。
   ⇒ 要堵它就得让价跟着时长走（那就**不是查表**了），或者干脆接受（用户的规格就是"挨个填值"）。**请用户裁**。
3. **`phaseSecondPerPoint` 的归宿**（§五）：绝对账要不要也摆脱秒单价？（这一片**没动**。）
4. **表里多余的档位（内容用不到）要不要报** —— **我判断：不报**，理由：这张表是**一份价格表**，
   不是一个"内容普查"：`0 / 3 / 9` 今天确实没有任何出厂内容停在上面（出厂内容全是 `1×`），
   而它们存在的理由就是**编辑器那个四档选择**（日志 50 §6.2 的欠账）。
   报它的话，`npm run validate` 会在**没有任何缺陷**的情况下天天红/黄一条 ——
   那种报警最后会训练人忽略校验器（本项目已经把好几条这种假警报删掉过）。
   ⚠ 真要报，就报成**一行提示**（不是 warning），而且得等 UI 那一轮做完再决定。
5. **表外取值是"报错"还是"警告"** —— 这一片按用户原话**报错**（`PHASE_TIER_NOT_IN_TABLE`，错误级）。
   ⚠ 后果要说清楚：**编辑器今天的时长控件还是线性秒数滑块**（四档选择是日志 50 §6.2 的欠账、还没做），
   所以玩家现在**真的能**拖出一个表外值来 ⇒ 他会看到一条错误。这是**故意的**（宁可吵，也不要静默当 0 点），
   但 UI 那一轮做完之前，这一条会一直吵。
