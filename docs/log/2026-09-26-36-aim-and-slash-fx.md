# 左键那一刀：瞄准方向和刀光特效

- **日期**：2026-09-21
- **触发**：玩家报的 bug，一句话：

  > 使用铁剑时鼠标左键的攻击始终朝向正右方而不是鼠标方向

  以及我第一次修完之后他的复测：**攻击跟着鼠标了，但特效没有**。

- **动了哪些文件**
  - 客户端：`web/src/aim.ts`（**新**：算方向的纯函数）、`web/src/main.ts`（指针状态、`pointerdown` 也记坐标、`getBoundingClientRect`）
  - 内容：`content/fx/slash.json`（`rotate: "none"` → `"facing"`）
  - 测试：`tests/web.ts`（瞄准 9 条）、`tests/weapons.ts`（挥砍方向 4 条）、`tests/smoke.ts`（跨文件查特效素材 2 条）

---

## 一、这句话里有**两个**问题，不是一个

玩家说的是"攻击始终朝正右方"，但"攻击"和"看着像攻击的东西"是两码事：

| | 是什么 | 表现 |
| --- | --- | --- |
| **命中方向** | 引擎里扇形判定朝哪边 | 打不打得中鼠标指着的人 |
| **刀光特效** | `content/fx/slash` 那套素材画在哪儿 | 看着像往哪边挥 |

他自己分得出来（第二次复测直接说了"攻击跟着鼠标了，但特效没有"），
所以这两条都修了 —— 而且它们**各自都能独立造成"永远朝正右方"**。

## 二、命中方向：`aimDirection()` 会凭空造一个"正右方"

老代码：

```ts
const len = Math.sqrt(dx * dx + dy * dy)
if (len < 1e-6) return { x: 1, y: 0 }   // ← "算不出来"被写成了"朝右"
```

`len` 为 0 有几种完全正常的情况：

- 一次 `pointermove` 都还没收到（`mouse` 还是初始的 (0,0)，而画面尺寸也是 0）
- 指针**正好落在画面正中**（那一刻"方向"确实没有意义）
- 画布尺寸读出来是 0

这几种情况全都变成了"朝正右方"，然后**每一次**攻击都朝右 ——
而且没有任何地方会报错：`resolveAim` 拿到的是一个合法的单位向量。

改法（`web/src/aim.ts`，纯函数，浏览器之外也能测）：

1. 算不出来就**用调用方给的 fallback**（= 角色当前朝向，也就是上一 tick 算出来的瞄准方向）——
   **不猜**。
2. 用 `getBoundingClientRect()` 减掉画布左上角，而不是假设"画布贴在视口左上角"
   （以前是 `position: fixed; inset: 0`，所以当时它成立；布局一变就会静默地偏）。
3. `pointerdown` **也记指针位置**：一个只转发点击、不转发移动的环境里，
   老代码永远收不到指针 —— 而点击本身带着坐标。
   （玩家是单独开的 Chrome，两个事件都有；这条是给别的环境兜底。）

## 三、刀光特效：素材的 `rotate` 写成了 `none`

这一条是**看着**不对的根源，而且我一开始没往这儿想 —— 因为上一轮
我觉得"引擎方向错了"，直到玩家复测说"特效没有"，才去查素材。

`content/fx/slash.json` 是 `tools/make-sample-fx.ts` 生成的**占位素材**：

```
24 帧 · 384×384 · 无 alpha（黑底）        ← tools/check-fx.ts 报的
亮内容（>25% 亮度）横向跨度 x 233~380     ← 那条刀光画在**画布右半边**
"rotate": "none"                       ← 所以它永远朝右
```

`meters: 6` + `anchor: [0.5, 0.5]`：这张 6 米的图以角色为中心铺开，
刀光落在角色的**右边** —— 不管往哪挥。和玩家描述的"始终朝向正右方"一模一样。

改成 `"rotate": "facing"` 之后，客户端会按事件的 `dir` 旋转它
（`spawnSprite()`：偏移也跟着转，不然往左挥时特效会跑到身后）。

⚠ **漏写这一条不会报任何错**：素材照常加载、照常播放，只是永远朝一个方向。
所以顺手在 `tests/smoke.ts` 里加了一条**跨文件检查**：

```
方向性载体（meleeArc / beam / capsule）+ 写了 vfx 的动作
  → 那份素材必须 rotate: "facing"
  → 素材 id 必须真的存在（不存在会静默退回程序化，作者素材白做）
```

并且验证了它**真的会红**：把 `rotate` 改回 `none` 跑一遍 → 报错；
改回来 → 绿。范围 / 光环 / 投射物命中是放射状的，不受这条管。

## 四、为什么以前没测出来

`tests/weapons.ts` 里那一整批序列测试，所有 `intent` 都写 `dir: {x:1,y:0}`（正右），
而角色默认朝向也是正右 —— **方向写错了照样是绿的**。

所以新加的两组断言都刻意反过来：

- `tests/weapons.ts`：**朝上挥**（角色 `facing` 朝上）→ 上方那个挨打、右边那个不挨打；
  再朝右挥一遍做对照。⚠ 这一条钉的是引擎的契约：
  瞬时载体的方向取自**施法者当前朝向**（`pipeline.ts`），不是调用方给的 `intent.dir` ——
  客户端必须每帧把鼠标方向写进 `player.facing`，写不进去的表现就是"这一刀砍在别处"。
- `tests/web.ts`：`aimFromPointer` 的纯函数测试 —— 鼠标在上边就是朝上、
  指针正好在正中 / 一次都没收到 → **用 fallback，不许凭空朝右**、
  画布有偏移时也仍然对。

## 五、没改的东西（写下来免得下次又查一遍）

`directional` 的载体用的是**施法者当前朝向**（跟着人转），只有 `locked` / `auto`
才把方向钉死在施法那一刻 —— 这是 `pipeline.ts` 里写明的取舍
（"前摇里转个身，飞弹不该朝转身前的方向出去"）。

代价是：**攻击方向依赖客户端每帧写 `player.facing`**。
这正是这个 bug 能发生的原因，所以引擎那边也考虑过改成"用施法瞬间解算出来的朝向"，
但那样 `duel` 的回归基准会变（AI 在蓄力期间还在转），而这一轮的目标是修 bug 不是改手感 ——
**先不动**。要改的话是一个明确的取舍，不是修 bug。

## 欠账

- **`slash` 还是占位素材**：`tools/check-fx.ts` 一直在报"无 alpha（黑底）/
  内容顶到画布边缘"。换成真素材时按 `docs/fx-authoring.md` 导出（要 RGB+Alpha），
  这个 def 不用改。刀光现在至少**方向对了**，但它仍然是占位。
- 上面第五节那条引擎取舍（`directional` 跟朝向 vs 跟施法瞬间）没动。
- 之前几轮的欠账还在（见日志 34 / 35）：技能修正、修饰技能、锚点表、阶段时长档位、
  血祭斩 / 裂魂的过时标签。
