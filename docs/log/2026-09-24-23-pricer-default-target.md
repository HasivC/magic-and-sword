# 定价器：不再猜"效果落在谁身上"

- **日期**：2026-09-21
- **触发**：玩家说「处理定价器」——
  指我在前几篇日志里反复记下的那条欠账：
  > 定价器那条启发式（"没写 `target` 且时机不是 `onHit` ⇒ 当成给自己"）
  > 已经咬了我四次。它和引擎判据不一致，持续制造"账算反了但没人知道"。
- **动了哪些文件**：
  `src/pricing.ts`、`src/validator/{index,checks}.ts`、
  `content/skills/{armor-pierce,infinity,iron-shirt,lava-armor,named-blade}.json`、
  `tests/pricing.ts`

## 一、那条启发式原来长什么样

```ts
// 旧代码
const toSelfDefault = r.when !== 'onHit'
```

一句话概括它的世界观：**除了 `onHit`，别的时机都当成"给自己"**。
它和引擎的实际行为不一致，而症状是最难查的那一种：

> **同一个动作，引擎打敌人、账上按打自己算。**
> 于是这条规则的符号整个反了 —— 本该 -3 的收益，账上是 +3 的代价。
> 而**没有任何地方会报警**。

它咬了四次，每次的表现都是"数值明明没动，点数却不对劲"。

## 二、改法：不是"修得准一点"，是**照抄引擎的调用点**

我没有去推"设计上应该是怎样"，而是把引擎里所有会触发规则的调用点列出来，
一条一条看它**传没传 `target`**：

| 时机 | 引擎传了什么 | 结论 |
|---|---|---|
| `onHit` | `fireCastRules(…, t)` / 投射物 `{target}` / 管线钩子 | **对面那个** |
| `onKill` | `fireCastRules(…, t)` / 投射物 | **对面那个** |
| `onEnter` / `onLeave` | 区域重叠判定，带"走进来的那个人" | **对面那个** |
| `onDamaged` / `onLethalDamage` / `onCrit` / `onNonCrit` | 管线 `buildValueContext` 给的"另一方" | **对面那个** |
| `onLowHp` | `runTechniqueRules(w, tech, target, …)`，target 就是血量跨线的人 | **自己** |
| `onStatusApplied` | 触发者是挂上状态的那个人 | **自己** |
| **钩子里的** `onTick` | `tickStatusHooks` 的 ctx **只有 actor、没有 target** | **自己** |
| `onCast` / `phaseEnter` / `phaseComplete` / `phaseInterrupt` / 规则级 `onTick` | **不传** → 落到 `selfOnly ? caster : lockedTarget` | **取决于术式** |
| `onMiss` | 两条路：有目标时带、**一个都没打中时不带** | **取决于术式** |

这张表就是 `defaultTargetOf(when, inHook)`，直接写进 `pricing.ts`。

### 三个值得单独说的点

**① 钩子和规则级必须分开判。** 状态钩子的 `onTick`（持续伤害）落回**持有者自己**，
而规则级的 `onTick` 落回"锁定目标"。混起来的话，
soul-rend 那条 DoT 的账会反 —— 而它看上去完全正常。

**② `onMiss` 是引擎自己不一致的地方。** `fireCastRules(ctx,'onMiss')`
有一处**不传 target**（"一个目标都没打中"，那时确实没有单位可传），
另一处传。所以它只能算"取决于术式"。这不是我偷懒，是**引擎有两条路**。

**③ `'depends'` 是真·不确定，所以必须报出来。**
同一个技能放进"自愈术式"和"攻击术式"里，账是不一样的。
定价按技能算，那时候根本不知道它会进哪个术式 ——
所以缺省取"对面那个"（schema 里写明「不写就是 `'hit'`」），
而**把这份不确定交给校验器报**：

| 检查 | 在哪一层 | 说什么 |
|---|---|---|
| `TARGET_DEPENDS_ON_TECHNIQUE` | 技能层（警告） | "这条动作没写 target，落在谁身上取决于它所在的术式；账现在按打对面算" |
| `TARGET_CONTRADICTS_TECHNIQUE` | **术式层（错误）** | "这个术式只对自己有效，但这条动作没写 target —— **引擎会打自己，而账是按打敌人算的**，符号是错的" |

第二条是**只有术式层报得出来**的，因为只有那里知道 `valid`。
它是这一轮最值钱的东西：把"悄悄猜错"变成了"红字"。

## 三、被这条修复照出来的旧账

改动一落地，校验器立刻点出 **14 条规则**处在"猜"的状态。逐条查下来，
其中真正**方向反了**的是这几条（都是自愈/架势/代价类术式里的动作）：

| 技能 | 规则 | 原来被当成 | 实际是 |
|---|---|---|---|
| `iron-shirt` | 运功后硬吃控制 | 打敌人 | **给自己**（术式 `valid: ['self']`） |
| `lava-armor` | 挂护甲 / 烧能量 / 沉重 / 焦灼（4 条） | 打敌人 | **给自己** |
| `named-blade` | 刀带着它一直压着你 | 打敌人 | **给自己** |
| `infinity` | 烧自己的能量 / 透支身体（2 条） | 打敌人 | **给自己** |
| `armor-pierce` | 把人挑飞 | 自己 | **打敌人**（术式不是 selfOnly） |

`iron-shirt` 的账当场从配平变成 **+4.99**（一条自我增益被当成"给敌人上状态"，
方向反了）。全部显式写上 `target` 之后回到配平。

**这就是那"四次事故"的真身** —— 它们一直躺在出厂内容里，
只是账刚好还在容差内，没人发现。

## 四、顺带把警告的条件收紧了

第一版 `TARGET_DEPENDS_ON_TECHNIQUE` 报了 27 条，其中大半是噪音。收紧后只看：

- 动作**没有** `delivery` —— 有载体时目标由几何 + `valid` 决定，和 `ctx.target` 无关
- 动作**没有**自己写 `valid` —— 同理（无下限的光环就写了 `valid: ['enemy']`）
- 载荷是"打谁符号会变"的那几种（`attribute` / `status` / `perception` / `displacement`）
  —— `damage` 和 `heal` 打谁都一样，**定价根本不看目标**，报了是噪音
- `attribute` 改的不是 `pipeline.*` —— 那改的是**这次命中**本身，不是某个人的属性

## 欠账

- **`AFFECTS_OTHERS` / `SIGN_CHANGING` 两张表写了同样的内容**
  （`checks.ts` 和 `validator/index.ts`）。它们必须一起改，但没有任何东西盯着。
  该合成一份导出。
- **`onMiss` 引擎自己那两条路**仍然不一致（一条传 target、一条不传）。
  我把它标成"不确定"绕过去了，但那是个该修的引擎不一致。
- **术式层的检查只覆盖它自己用到的技能**。一个技能被两个术式用、
  一个是自愈一个是攻击，两条账里必有一条错 —— 现在只能查出"自愈那条错"，
  而攻击那条是对的。**换个角度想：这其实是对的，因为错的那条正是自愈那条。**
  但如果一个技能同时被"全 self"和"全 enemy"的术式用，它就会报一次错 ——
  那时作者该做的是**拆成两个技能**，而不是给动作写死 target。这条没写进提示里。
- **`heal` 的"给谁"仍然不参与定价**。治疗敌人和治疗自己同价，明显不对，
  但要定价它得先有"给敌人治疗是负收益"的模型。记着。
