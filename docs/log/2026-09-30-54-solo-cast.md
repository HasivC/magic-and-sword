## 1. 两条硬规矩落在哪一行

### 1.1 施法独占（引擎判据）

改的是 `src/sim/cast.ts` 的 `canActivate()` 里**一行**：

```ts
// 老（bug）：只挡"这一门术式有占人阶段 且 那一段占着人"
if (!same && technique.phases.some(p => p.occupiesCaster) && isBusy(world, caster.id)) return 'busy'

// 新（硬规矩）：手上还有没有"没放完的那一段"
if (!same && hasRunningCast(world, caster.id)) return 'busy'
```

新函数（同一个文件）：

```ts
export function hasRunningCast(world: World, casterId: number): boolean {
  for (const c of world.casts) {
    if (c.casterId !== casterId) continue
    if (c.finished || c.interrupted) continue   // 等 pruneCasts 的"上一刀"不该挡住"下一刀"
    return true
  }
  return false
}
```

**为什么老那一行是 bug**：出厂技能**多数没写 `occupiesCaster`**，于是 `technique.phases.some(...)` 对它们是 `false` —— **一整类术式（瞬发 / 脱手）完全不受"忙"的约束**，能从一段正在跑的施法中间插进去，**两段施法同时在跑**。

四条边界，都是**刻意**的：

| 边界 | 怎么落的 |
| --- | --- |
| **和 `locks` 无关** | 判据**根本不读** `locks`。把 `cast` 从锁里拿掉也不许并行（"能不能并行"不是可配项） |
| **武器攻击也是施法** | 左键 = `pressSequence` ⇒ `activate` ⇒ 同一个 `canActivate`。"边等边砍"同样被拒 |
| **不堵死脱手技** | 脱手技的"施法动作很快就结束"⇒ `finishCast` ⇒ `pruneCasts` 把它移出 `world.casts` ⇒ **放完立刻能放别的**（钉在 tests 里） |
| **份数类修饰仍然放行** | `sameActivation: true`（多重释放 / 一分为 X 的**第 2..N 份**）—— 那是玩家签过字的机制，"一次激活好几段"就是它的定义，全拦掉等于删掉那个零件 |
| ⚠⚠ **引擎内部的延续 / 反射也放行** | **`engineInternal: true`**（玩家裁定，见下）—— 只有 `sim/trigger.ts` 的 `fireModifier` 会填 |

⚠ **顺序**：`locked`（内容作者写在阶段上的 `locks: ['cast']`）判在**施法独占之前** —— 两件事同时成立时它更具体（说的是**这一段**的性质）。所以 `tests/cast.ts` 那条"原因是 `locked`（不是笼统的 `busy`）"**一个字都没改**。

⚠ **原因沿用 `busy`**（不新造取值）：客户端 `blockReason` 已经把它翻成"**正在施法**"（`web/src/main.ts`）—— 正好是要说的那一句，而且**不用碰客户端**。

#### ⚠⚠ 1.1.1 「**只管玩家的手指**」—— 玩家裁定（第二轮）补上的那条边界

玩家原话：

> "施法独占"管的是**玩家的手指**，不是**引擎内部的延续**。

⇒ `ActivateOptions` 新增 **`engineInternal?: boolean`**，判据那一行变成：

```ts
if (!same && !internal && hasRunningCast(world, caster.id)) return 'busy'
```

填它的**只有一处**：`sim/trigger.ts` 的 `fireModifier`（触发器 / 监测器真正把技能放出去的那一下）。豁免的两类：

| 类 | 走哪个记号 | 例子 |
| --- | --- | --- |
| **同一次施法的延续** | `sameActivation`（份数类，日志 51 就有） | 多重释放 / 一分为 X 的第 2..N 份 |
| **引擎内部的延续 / 反射** | **`engineInternal`**（日志 54 新加） | 触发器链条（挂上常驻 → 它的 `onCast` 触发）、监测器的被动反射（施法途中跨低血线 → 撑盾） |
| **玩家按出来的新一次施法** | ⚠ **两个记号都不给** ⇒ 被拒 | 客户端按键 / AI / 命令行（一律不填） |

⚠ **不豁免的后果是静默的**（这一片的第一次实现就踩了）：玩家在施法中途跨过危险线，撑盾那一下被 `busy` 吞掉、**盾永远不挂**，而且既没有 `modifierTriggered` 也没有 `modifierBlocked` —— 等于把日志 48 那一整套机制废掉，**玩家报不出这个 bug**。
⚠ **防滥用不在这儿**：被触发的技能照旧付自己的代价（能量 / 血契）、照旧记自己的冷却 —— `activate` 里那几道**资源与生死**的门一份都不跳。
⚠ **这一条不改战斗节奏**：`battle` 的哈希在加上它之后**一个字都没变**（还是 `44C782A4…`）—— 出厂那两个单位的被动在这 12 秒里没有撞上"自己正在施法"。

### 1.2 「等待」的锁收窄到 `move` / `turn`，默认**一个都不锁**

| 层 | 老 | 新 |
| --- | --- | --- |
| `content/modifiers/wait.json` 的 `params.locks` | `["cast","attack"]` | **`[]`** |
| 同文件的 `paramsTemplate.locks`（默认值 / 可勾项 / 标签） | 默认 `["cast","attack"]`、四项 | 默认 **`[]`**、**两项**（`move` / `turn`） |
| `school.ts` 的 `MODIFIER_LOCK_VALUES` | `['move','attack','cast','turn']` | **`['move','turn']`** |
| `school.ts` 的 `MODIFIER_LOCKS_DEFAULT` | `['cast','attack']` | **`[]`** |
| `school.ts` 的 `MODIFIER_LOCK_ENGINE_RESERVED` | —（新） | **`['cast','attack']`** |
| 校验器 | `cast` / `attack` 混在里面**不报** | 出现就报 **`MODIFIER_LOCK_ENGINE_RESERVED`**（说清"施法独占是引擎硬规矩，不是可配项"），**副本**（`validator/index.ts`）和**原型**（`validator/checks.ts` 的 `validateModifierProto`）**两层都拦** |

⚠⚠ **默认值 = `[]`（能走、能转身）**，依据是玩家原话"**锁「施法 + 攻击」，但能走**"：
- "锁施法 + 攻击"这两条**现在已经是引擎硬规矩**（不靠这个参数生效）⇒ 这个参数只剩**移动 / 转身**两样可配；
- 既然如此，那句"**但能走**"落到的就是"**都不锁**"。
- ⚠ 中间我一度取过 `["move"]`（"站住"）—— 那是**我猜的**，玩家 2026-09-30 当场裁掉（"那是你自己的猜测 ✗ 不是玩家要的"）。要"站住"就**显式**配 `['move']`。

⚠ **`Phase.locks` 那四个 `Capability` 一个都没删**：技能内容里的 `locks: ['cast']` / `['turn']`（贯日）照旧生效，被收窄的只是**修饰零件的参数表**（⚠ 技能侧那个 `locks: ['cast']` 和硬规矩**重叠**了，玩家裁定"先留着"—— 记在欠账里）。

## 4. ⚠ 动手时踩的一个坑（留给下一个人）

改 `content/modifiers/wait.json` 那一段长 `_comment` 时，我用脚本**按锚点切片替换**（因为那行里带着 `[\"cast\", …]` 这种**转义过的引号**，手抄必错）。**连踩两次**，症状都是"`npm run validate` 说 JSON 解析失败"：

1. **真换行**被写进了 JSON 字符串里 —— 字符串里必须是 `\n` **两个字符**（`.scratch/fix-wait-comment.mjs`）；
2. 行文里的**直角引号 `"…"`** 没有转义 —— 在 JSON 里它就是**字符串结束符**（`.scratch/fix-wait-quotes.mjs` 用 `(?<!\\)"` 补，**跳过已经转义过的**那几处）。

⇒ 教训：**改中文 JSON 走 `edit` 工具或 Node 脚本，改完立刻 `JSON.parse` 一遍**（别只看 diff 顺眼）。
⚠ 第三轮又踩了一次同一类（把 `"载体消失"` 这种**裸 ASCII 引号**写进了字符串）——
所以之后的脚本里都加了一道保险：`if (/(?<!\\)"/.test(text)) throw`（裸引号 = 字符串结束符）。

## 4.5 ⚠ 复核者踩过的坑（写下来省下一个人的时间）

一支**独立复核**的支线在同一批文件上踩了三个坑、并因此得出过**三次假结论**。
我逐条**实测**过（`.scratch/solo54-review-claims.ts`），准的写下来、不准的**校正**掉：

| # | 说法 | 实测结论 |
| --- | --- | --- |
| 1 | 「`activate()` 不会把这一**段**放进 `world.casts`（那是 `stepWorld` 干的）⇒ 起手后马上查永远是 0 段」 | ⚠ **不成立**（当规矩记会害人）：`activate()` 里就有 `world.casts.push(cast)` —— 实测 `activate(没有序列的术式)` 之后立刻查 = **1**。⚠ 但**他看到的现象是真的**，真因是下面第 2 条 |
| 2 | 「`activate()` 只能放**没有序列**的术式：给带 `sequences` 的容器直接 `activate`，拿到的是**段级空产物**（`phases: []`）⇒ 立刻 `finishCast`」 | ✅ **完全成立**（实测：铁剑容器自己的 `phases` = **0**、段里 = 3；`activate(容器)` 之后 `world.casts` = **0**；同一个容器走 `pressSequence` = **1**）。**走序列必须用 `pressSequence`** |
| 3 | 「`skill.charged-laser` 在无玩家输入的世界里当 tick 就结束 ⇒ 不能当"不会结束的施法"用」 | ⚠ **在 quiet 世界里不成立**（实测：`pressSequence` 之后推 1 / 10 / 30 / 60 / 120 tick，`world.casts` **一直是 1** —— `duration: -1` 的蓄力段不会自己结束）。⚠ **但那个观测也可能是真的**：只要世界里**有人打你**，它就会被**打断**（它的阶段默认 `interrupt: 'damage'`）。⇒ 要一个**绝对稳定**的"不会结束的施法"，复核者推荐的替代是 **`skill.soul-rend`**（charge 1 秒真的跑满 60 tick） |

⚠ 一句话版：**"起手后查不到那一段"的锅在 `activate` + 带序列的容器，不在 `activate` 本身。**
⚠ 还有一条通用的（我自己也栽过一次）：`world.events` **每 tick 被清空**（`stepWorld` 第一步）——
用全局游标去数事件会**只数到一两 tick**（探针第一版打出 `{剑士: 1, 法师: 1}`，真值是 3 / 6）。

## 5. 「等待」现在的语义（改后）

- 挨打**不打断**（`interrupt: none`，玩家日志 52 定的，没动）。

### ⚠⚠ 第三轮：「应声触发」的默认条件恒假 —— **已裁定并修**（**有意的行为变更**）

**出场零件「应声触发」（`content/modifiers/trigger-on-cast.json`）原来是死的**（我查出来的既有问题）：

- 它的 `params.condition` 写的是 **`{}`**（空对象）。`sim/conditions.ts` 的 `evaluateCondition` 按 `type` 分派，`{}` 走到 `switch` 的 **`default: return false`** ⇒ **恒不成立**；
- 而 `{}` **能过校验器**：`checks.ts` 那条只要求"是对象**或者不写**"（`{}` 是对象 ✓）；
- ⇒ 结果是：**副本不写条件时，这个零件永不触发**，而且**一声不吭**
  （既没有 `modifierTriggered`，也没有 `modifierBlocked`）—— 正是这个项目列为最危险的那一类静默失败。
- **证据**（第 58 节② 的第一次尝试）：同一份探针、同一个时机，`params: { origin: 'caster' }`（= 用原型默认条件）
  ⇒ 事件里**什么都没有**；把条件显式写成 `{ type: 'hpBelow', who: 'self', value: 1 }` ⇒ 当场触发。

**玩家裁定：修**。⚠⚠ 而且**语义纠正过一次**（我按"不写 = 无条件"改了一半，玩家当场否掉）：

> **无条件的触发似乎并无意义，它的默认值应该是「载体（前一个魔法）消失」。**

- 为什么他对：**无条件触发 = "前一个技能放完就直接放下一个"** ⇒ 那在序列里**直接摆两个技能**就行，
  触发器一点用都没有；而「**载体消失**」才是真机制 —— 火球飞出去、**它消失 / 炸了那一刻**
  再触发后面那个（Noita 那种**引信**）。
- ⚠⚠ **但它的默认值今天实现不出来**：引擎真接线的时机**只有三个**
  （`onLowHp` / `onTick` / `onCast`），而"载体消失"要的是 **`onExpire` / `onRemoved`** ——
  **那档没接线**（缺"**施法结果上下文**"：引擎不知道"上一次施法放出去的东西后来怎么样了"）。
- ⇒ **短期处理**（**不许留一个"今天根本不触发"的默认值** —— 那只是换一种方式的静默 ✗）：

| 落点 | 现在的行为 |
| --- | --- |
| **内容** | `trigger-on-cast.json` 的 `params.condition = {}` **删掉**（不是换成别的条件）；`paramsTemplate` 里那个 `condition` 旋钮也拿掉（它的 `default: {}` 正是那颗雷）；`_comment` 写清"默认值 = 载体消失，而它今天没接线" |
| **求值** | 确认"`evaluateAll` 对**不写 / 空数组**返回真"这条路是通的（`conditions.ts` 第 155 行）—— ⚠ 但**今天不允许靠它**：见下 |
| **校验器（两层）** | `MODIFIER_EMPTY_CONDITION`（显式 `{}` ⇒ 恒不成立）+ `MODIFIER_CONDITION_REQUIRED`（**副本和原型都没有条件** ⇒ 等于永不触发）。⚠ 原型那一层还从"必填三键"里拿掉了 `condition`（它今天**没有**可用的默认值），**但**副本**必须凑得出一个真的条件** |
| **`if: [{}]`（规则 / 连接 / 序列门）** | 同一个坑，同一套判据：`EMPTY_CONDITION`（⚠ **`if: []` / 不写 `if` 仍然合法** —— 那是"没有门"，两条对照都钉在测试里） |
| **测试** | ① 不写条件 → **报错**；② 写了真条件 → **照常触发**（`scenario` 第 58 节② 那条端到端）；③ 显式 `{}` → **报错**；④ 副本省略、**原型上有** → **合法**（「背水」那条路，别被新判据判死） |

⚠ **这是一次有意的行为变更**（一个"今天死的"零件不再被当成正常内容放过去），
但 ⚠ **`battle` 的哈希一个字都没变**（还是 `44C782A4…`）—— 出厂内容里**一个触发器副本都没有**，
所以这条改动只影响"将来有人用它的时候"。

### ⚠⚠ 单独一笔引擎工作：**「载体消失」这个时机要接线**

> **这是玩家点名的默认值，今天缺机制。**（不要让它淹没在别的欠账里。）

- **要什么**：`onExpire` / `onRemoved` 那一档 —— "**上一次施法放出去的那个东西**（投射物 / 区域 / 屏障）
  消失了 / 炸了"的那一刻，触发后面那个技能。
- **缺什么**：**「施法结果上下文」** —— 引擎今天不知道"上一次施法放出去的东西后来怎么样了"
  （`sim/trigger.ts` 的 `WIRED_TRIGGER_EVENTS` 只有三个；`origin` 的 `prevHitPoint` / `prevEndPoint`
  也只能读"上一次触发留下的那个点"）。
- **接上之后**：`trigger-on-cast.json` 就能有一个**真的默认条件**，
  `MODIFIER_CONDITION_REQUIRED` 那条判据可以松掉（改成"用默认值"）。
- ⚠ 相关的既有缺口（日志 48 就记着）：`onHit` / `onMiss` / `onStatusApplied` 也**没接线**。

⚠ 另一条**仍然开着**的：技能内容里的 `locks: ['cast']`（`Phase.locks`）和引擎硬规矩**重叠** ——
它今天仍然有用（给的是更具体的提示 `locked`），但读者容易以为是它在拦。
