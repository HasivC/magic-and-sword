# 施法形态（`Skill.form`）：技能自己声明"要不要一条时间轴"

- **日期**：2026-09-21
- **触发**：`docs/sequence-and-modifier-model.md` **定稿之后的第一片实现**。玩家把规矩逐条定下来了，
  这一轮只落地**形态那一格**：
  > 施法形态**相对施法者而言**（所以"图腾/召唤"是**瞬发**）
  > 四类：**瞬发 / 蓄力 / 持续 / 常驻**；**默认 = 瞬发**，内容里只标**不是瞬发**的那些
  > 激活方式只有四档：`press` / `release` / `hold` / `toggle`（`auto` 不删字段，但它是"常驻术式"的标志）
  > 相容表：瞬发→按一下/蓄力放开；蓄力→**只能**蓄力放开；持续→按住/开关；常驻→只能进"全常驻"的术式（`auto`）
  > **蓄力/持续技能必须是它所在序列的第一个技能**（前面不能有别的技能）
- **动了哪些文件**：3 个代码 / 测试 + 8 份内容 + 5 处文档，见第五节清单
- **⚠ 没做的事**（规格里明确点名的）：序列**没有**内联、瞄准**没有**搬到技能层、
  **没有**为"修饰技能"写任何字段或占位、编辑器 UI（`web/src/editor.ts` / `technique-editor.ts`）**一个字没动**
- **⚠ 战斗行为零改动**：`battle duel --duration 12` 的输出**逐字节不变**（见第四节）

---

## 一、这一片要解决的是什么

定稿文档 §一 把那三个被混在一起的概念分开了，其中**形态**（技能层）和**激活方式**（术式层）
是最容易被读成一个东西的一对。它们混着的时候，玩家的原话是这个症状：

> 毕竟你不能把一个被动和一个法球放在一个术式里，攻击的时候会出错。

⚠ **出错的不是判定，是语义本身不成立**：`Skill` 里原来**没有**"需不需要一次施法"这个东西，
而激活方式是**整个术式**的一个属性、编译器只能把技能串成**一条时间轴**。
于是「无下限」那类没有时间轴的技能被塞进"按一下"的术式时，
"按下去到底该发生什么"**没有答案**。

⇒ 所以这一片要的是：**让这种组合在数据上说不出来**，而不是等它在运行时出错。
那句话落在两个地方：**技能自己声明形态**，**校验器检查两者对不对得上**。

## 二、决定了什么

### 1. `Skill.form?: 'instant' | 'charged' | 'sustained' | 'passive'`（不写 = `instant`）

新增类型 `SkillForm`（`schema/skill-schema.ts`，紧挨着 `ActivationMode` —— 它们是一对）。
注释里写清了三件最容易读岔的事，这里各重复一句：

- **为什么默认是瞬发**：① 宗旨（每个可调值都有一个"默认值下点数为 0"的默认值）——
  出厂内容绝大多数技能都是瞬发，不写就不该付一行字；② **猜的面越小越好**：
  只有"不是瞬发"的那几个显式标出来，形态才是一张**可核对的小表**（今天 7 行）。
  ⚠ 默认值一旦填成"看起来更聪明"的那一种，猜错是**静默的** ——
  日志 44 里"猜 `kind`"把「标记 · 瞬影」猜错的教训就在眼前。
- **形态是相对施法者而言的**：所以"放一个图腾 / 召唤物"是**瞬发**（放下去那一下有完整时间轴 ✓）；
  图腾之后怎么活着是**它自己的事**，不是这个技能的形态。同一个技能只能有一个形态。
- **它和"激活方式"是两个概念**：激活方式回答"玩家怎么按"（**术式层**），
  形态回答"这次释放要不要一条时间轴、要多长"（**技能层**）。两者要**对得上**，见下面第 3 条。

### 2. 内容标注：只标**不是瞬发**的，一共 7 个

判据是**机制**，不是感觉（逐条依据见第三节）。核心两条：

- **`passive`（常驻）= 没有时间轴**：整个时间轴只有一段**占位相**（`idle` / `cast`），
  **没有固有效果**（`Skill.effect` 不写），干活的全是**反应规则**（`onLowHp` / `onCrit` / `onTick` / `onEnter`…）。
  另一半判据是"**只被 `activation: 'auto'` 的术式用到**"—— 两条判据在能被引用的技能上**指的是同一件事**。
- **`charged`（蓄力）= 时间轴里有一段 `duration: -1`**（时长**由玩家控制**：按下开始、松开结束）。

⚠ 判据是 `duration: -1` 这一条，**不是"名字里带蓄力"**：裂魂的 `charge` 相是固定 1 秒、
突进的 `wind` 相是固定 0.1 秒 —— 那些是**固定的前摇**，跑完就结束，仍然是瞬发。
这一条正好是"猜的面越小越好"的兑现：如果按名字猜，这两个都会被标错。

⚠ **`sustained` 内容里一个都没有 —— 那就一个都别造**（没有为了演示新造技能）。
**持续那一行**只在测试里用一个**临时的**技能验（它只活在 `tests/smoke.ts` 那个函数里）。

### 3. 校验器加两条规则（+ 一条取值检查）

| code | 报什么 | path 长什么样 |
| --- | --- | --- |
| `FORM_INCOMPATIBLE` | 术式的激活方式和它用到的技能形态不相容 | `skills[1]` / `sequences[0].skills[0]` |
| `FORM_NOT_FIRST` | 蓄力 / 持续技能**不是它所在序列的第一个** | `skills[1]` |
| `BAD_ENUM`（`path: form`） | `form` 取值非法 | `form` |

相容表是**一张 `Record<SkillForm, ActivationMode[]>`**（`src/validator/index.ts` 的 `FORM_ACTIVATIONS`）：

```
instant   → press / release
charged   → release
sustained → hold / toggle
passive   → auto
```

⚠ 写成 `Record<SkillForm, ...>` 而不是一张散表：少写一个形态 **TypeScript 当场报错**，
"表里漏了一行"这种漏法就被堵死了。

**为什么第三条（`BAD_ENUM`）在规格那两条之外**：`form` 拼错（`"passiv"`）时，
如果校验器**静默当成瞬发**，症状是"这个技能是瞬发的"——而它显然是想写常驻。
这项目的纪律是"判不了 ≠ 没问题"，所以它必须响。⚠ 这是唯一一处**超出规格清单**的改动，
理由是上面那句；要是嫌多，删掉 `checks.ts` 里那 8 行即可（两条主规则不依赖它）。

`message` 里一定有**术式名 + 技能名 + 两个取值**，`hint` 里有**相容表 + 具体改法**，例如：

```
[FORM_INCOMPATIBLE] skills[0]
术式「形态探针」的激活方式是 press（按一下），但技能「贯日」的形态是 charged（蓄力） —— 两者不相容
→ 相容表：瞬发 → 按一下 / 蓄力放开；蓄力 → **只能**蓄力放开；持续 → 按住 / 开关；
  常驻 → 只能进"全常驻"的术式（activation: "auto"）。蓄力技能的时间轴里有一段
  `duration: -1`（时长由玩家控制，按下开始、松开结束）——放进"按一下"的术式里，那一段永远跑不完。…
```

### 4. 一个必须写下来的实现决定：**顺着 `sequences` 往里查**

写 `sequences` 的术式**自己没有 `skills`** —— 技能全在被引用的那份子术式里
（`tech.longsword-basic` → `tech.ws-slash` / `tech.ws-thrust` → `skill.ws-slash`…）。
只看 `tech.skills` 的话，**序列术式一条都查不到**。

- **`FORM_INCOMPATIBLE` 顺着查**，判据用**父术式的** `activation`：
  序列在"激活方式"上位于术式层级的下方（schema 的 `Technique.sequences`），玩家按的是父术式那个键。
  依据是定稿文档 §五 规矩 2：_"同一门术式的不同序列可以是不同形态 ✓ —— 前提是**每一段都和术式的激活方式相容**"_。
- **`FORM_NOT_FIRST` 只查术式自己的 `skills`**：被引用的那份子术式**自己就是一个术式**，
  它被单独校验时（那时 `tech.skills` 就是"它所在的那条序列"）会报同一条错。
  顺着父术式再报一遍的话，一份被两门术式引用的序列会被报**三次**（`tech.ws-slash` 就是被两份引用的），
  而"改哪个文件"反而糊了 —— 报错的另一半价值就是让人一眼知道去改哪儿。

| 技能 | 不标的理由 |
| --- | --- |

| `skill.soul-rend`「裂魂」 · `skill.charge-dash`「突进」 | 有**固定时长**的蓄势 / 前摇（1 秒 / 0.1 秒），跑完就结束 → 瞬发 |
| `skill.lava-armor`「熔岩护甲」 · `skill.iron-shirt`「铁布衫」 · `skill.aegis`「灵光盾」 | 有 `effect`（时间轴走到那一段就发生）→ 瞬发。⚠ "效果持续很久"不等于"持续形态"：持续形态说的是**时间轴一直挂着** |

### ⚠ 设计决策（规矩没说清的那一处，我做了选择 —— 请裁定）

有 4 个候选技能**没有被任何术式引用**（`hunter-instinct` / `infinity` / `named-blade` / `last-stand`），
于是那两条判据会**分开**：

- "只被 `auto` 术式用到" → 对它们**不成立**（用它们的术式根本不存在）
- "没有时间轴（没有固有效果）" → 对它们**成立**

**我选了后者**（都标 `passive`），理由：定稿文档 §二 的常驻例子列的就是
「无下限 / 血契记账器 / 猎手直觉 / 背水」，玩家这一轮的说明里也点到了这几个名字。
**如果应该按前者**（只标字面上能被证实的 `blood-pact` / `slow-field` 两个），
那就是把 4 行 `"form": "passive"` 删掉 + 改一下 `tests/smoke.ts` 里那张写死的对照表即可。

**⚠⚠ `skill.last-stand`「背水」这一条是真冲突**，写在它的文件里、也在这里：

- 它自己的 `_comment_toggle` 写着"**故意**做成 `toggle` 而不是像名刀那样的 auto 被动"
  （为了让能量 30 / 冷却 8 是**真的**代价，不是账上的假代价），`tests/probes.ts` 的
  `tech.last-stand` 也确实写 `activation: 'toggle'`；
- 但那一节是**旧五档模型**下的话（当时的 `auto` = "装上就生效"、`toggle` = "常驻开关"）。
  现在定稿的相容表是 **常驻 → 只能进全常驻的术式（auto）**、**持续 → 按住 / 开关**；
  而背水的时间轴是**有限的一段**（`brace` → `ready`），不是"一直挂着"，所以它也**不是持续**。
- ⇒ 两者不能同时成立。我按定稿文档 §二 判成 `passive`，
  代价是：**"toggle 的背水"现在会被报 `FORM_INCOMPATIBLE`**。
  那是**内容要改**（不是判错了），两条出路（选哪条是设计决策，我没定）：
  ① 去掉两段代价相 → 纯常驻（但那就没法收费了，正是 `_comment_toggle` 担心的）；
  ② 把它做成**真正的持续**技能（时间轴挂着直到关掉）→ `toggle` 成立。
  ⚠ **如果按"背水 = 持续"来定**，那它就变成内容里**唯一**一个 `sustained`，
  和这一轮"sustained 一个都别造"的说法要一起改。
