## ① 追踪 → 「追到消失」

### 用户原话（意思）

> **限制不应该是射程，而是持续时间 —— 这样就追到消失**
> 那个"射程"旋钮（`maxRange`）：**改语义为「索敌距离」** —— **发射那一瞬间**
> 能找到多远的目标（**找上了就一路咬到消失**）

### 改之前是什么样

`steerProjectile` **每一 tick** 都拿 `maxRange` 重新搜一遍最近的敌人
（`nearestProjectileTarget(world, p, judge, spec, homing.maxRange)`）——
所以目标**跑出 8 米就丢锁**：那一发当场变成直线弹，而且**没有任何提示**。

### 改之后（代码形状）

1. **索敌只在发射那一刻发生一次**：`sim/pipeline.ts` 的 `spawnProjectileFrom`
   在 `spawnProjectile(...)` **之后**立刻调 `acquireHomingTarget(...)`
   （位置就是出生点 —— `integrate` 还没跑），结果写进 `spec.homing.lockedId`。
   - ⚠ **`judge` 用 `ctx.actor`**：和 `tickProjectiles` 里那个
     "`world.entities.find(id === spec.sourceId) ?? p`" 此刻是**同一个实体** ⇒ 两处敌我视角逐位一致。
   - ⚠ **不许"飞近一点再找"**：那一刻没找到就一路直走（玩家点名的是"发射那一瞬间"）。
2. **飞行途中不再搜**：`steerProjectile` 只读 `spec.homing.lockedId`，
   连 `world.entities.find(e => e.id === lockedId)` —— 目标跑多远都咬着。
   `maxRange` 在这条路上**一次都不读**（这不是漏了，是这一片要的语义）。
3. **锁上之后不换目标**：目标死了 / 已经打过了（穿透）/ 变得不合法 ⇒ **直走**。
   ⚠ 旧行为是"下一 tick 重新找最近的"（日志 56 的待裁定项 c 里写着"这是实现事实"）——
   按用户"不许猜"的纪律**删掉了**：换目标是**玩家没定**的语义，猜它比直走坏。
4. ⚠⚠ **跳过条件因此收成一个函数**（`chaseableTargetOf`）：命中判定 / 索敌搜索 /
   追锁**三处读同一批规矩**（死掉的、不是 `actor`、发射者自己、打过的、过不了 `valid`）。
   以前命中判定是**自己抄了一份**五行 —— 两处各写一份迟早漂移，
   而漂移的表现是"子弹追着一个它打不动的东西飞"。
5. ⚠ **`spec.homing` 必须抄成一份新对象**：`homingOfCast` 返回的是**编译产物**里
   那个对象（一份术式共用），而 `lockedId` 是**这一发自己的**状态 ——
   不抄的话**多重释放的 N 发会把锁写到别人头上**（和 `spec.bounce` 是同一个做法）。

### 「索敌距离」这个旋钮的**键名**故意没动

`content/modifiers/homing.json` 里那个参数**仍然叫 `maxRange`**（`params` / `paramsTemplate` 的
`default` / `min` / `max` / `step` 一个字都没改）。理由（用户给的口径，权衡后选最省的那条）：

- 改键名要同步 **`school.ts` 的 `MODIFIER_HOMING_RANGE_KEY` / `compile.ts` / 校验器两处 /
  `pricing.ts` / 点表 / 内容 / 一堆测试**，而这一片要的是**语义**；
- 改的是**名字和说明**（`label` / `_maxRange` / `_comment` / 两条 `_` 汇率说明 / `tierDrafts`）。
- ⚠ 待裁定项第 1 条列了这件事。

### 「追到消失」在代码里是**寿命**，不是"追到目标为止"

追多久 = **这一发自己的 `delivery.lifetime`**（飞完自然消失）。所以
"目标一直在 60 米外、追不上"的那种情况下，它照样咬着不放，直到**自己**到寿 ——
测试里有一条专门钉这个（第 60b 节 ①）。

## ② 触发器的「生成在瞄准的位置」= 取**按下技能那一刻**的瞄准

### 用户原话（意思）

> 触发器的「生成在瞄准的位置」= 取**按下技能那一刻**的瞄准 ——
> **不是**实时的鼠标位置（那要新增每帧输入通道 + 联机同步，**以后再说**）
> **取不到 ⇒ 什么都不做**（和"没目标就不发生"同一条纪律）—— **不许**退化成"最近敌人"

### 改之前是什么样

`sim/trigger.ts` 的 `resolveOrigin` 在 `aim` 那一档做的是：

```ts
const target = contextOf(world, owner).target      // ← "最近的敌人"
return { point: { x: target.pos.x, y: target.pos.y } }
```

那是一个**猜出来**的点（取不到就什么都不给）—— 玩家写的是"瞄准的落点"，
引擎给的却是"系统挑的那个人身上"，两者只有在"玩家恰好瞄准了最近那个人"时才重合。
日志 48 那一段"这是没定下来的地方"说的就是它。

### 改之后（代码形状）

1. **"那次施法"的意图在它还在的时候抄下来**：`CastInstance` 会被 `pruneCasts`
   移出世界，而载体往往活得比施法长 ⇒ 新类型 `CastIntent`（`mod-state.ts`）
   记两个半边（`cast.aimPoint` / `cast.facing`），由 `pipeline.ts` 的 `carrierOriginOf`
   在 `recordCarrier` 那一刻写进 **`CarrierOrigin.intent`**（**值、不是引用**：
   `cast.facing` 之后还会被阶段锁换掉，而"按下那一刻朝哪"不该跟着变）。
2. **触发时两个半边都传**：`fireModifier` 现在给 `activate` 传
   `aimPoint`（引擎里唯一读它的地方 = 范围类载体的落点）**和** `facing`（方向）。
   ⚠ 不传 `facing` 的话，一个朝前打的技能会跟着施法者**当前**朝向走 ——
   那正是玩家点名不要的"实时的"那一半。
3. **取不到 ⇒ 那一档不生效**（`resolveOrigin` 返回 `{}`）：既不钉落点、也不钉方向，
   技能照常按**自己那套瞄准**放出来。
   ⚠⚠ **读法的界**：这是"**这一档不生效**"，**不是"不触发"** ——
   和「环绕」/「追踪」对非飞行载体"什么都不做"是同一条读法（零件不生效，技能照跑）。
   ⇒ 测试里**同时**钉了"触发器照常响"，免得"整个触发器坏了"冒充通过。
4. **哪条路取得到**：**只有「载体消失」（`onExpire`）** —— 那次施法记在载体台账里。
   `onLowHp` / `onTick` / `onCast`（挂载）**没有"那一次施法"** ⇒ 那三条路上写 `aim`
   = **这一档不生效**。⚠ 这是"取不到 ⇒ 什么都不做"的直接后果，
   **不是**没实现（待裁定项第 5 条列着"要不要给它们另定一个口径"）。
5. **旧行为整段删掉**（`contextOf(...).target` 那一支）——
   `contextOf` 本身留着（监测器的**条件**还在用它，那是另一件事）。
