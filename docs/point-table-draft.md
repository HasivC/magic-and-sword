# 点表草稿：每个技能 × 每个可调变量 × 每个取值 → 一个整数点数

> ⚠ **这是草稿，等用户签字。** 点数不是"我觉得该值多少"，而是**今天真的算出来的现值**：
> 把这一片叶子改成那个取值、其余一个字不动，再对**出厂那一份**做相对账 —— 也就是 `skillLedger` 的合计。
> 用户觉得哪一格不对，就在最后一列写他要的数。

## 怎么起草的（一句话）

**枚举现值**：对每个技能的每个可调变量的每个取值，用现成的定价函数真的算一遍今天那个值，
四舍五入到整数点（逐条取整 + 每个非零条目至少 1 点已经在函数里了）。

## ⚠ 三条要说在前面的口径

1. **阶段时长这条轴今天已经走查表**（`content/balance.json` 的 `tierTables.phaseDurationPoints`，四档 `0 / 1× / 3× / 9×`）。
   本表印的是那个结果；用户要的全量点表会把它一起替掉。
2. **取值集合只取编辑器点表里的取值**。如果某个变量的取值不是有限集合（连续滑块 / 自由取值），
   本表**只列出来、不自己定档位** —— 见文末「待裁定项」。
3. **相对账的两条规矩**（逐条取整、每个非零条目至少 1 点）会让"小差别"在账上被压平：
   例如排布的每米那 0.1 点 × 半径，全行程也只有 0.6 点 ⇒ 账上都是 −1。这是已有规格的后果，不是本表引入的。
