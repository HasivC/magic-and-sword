# 自己做技能特效

**给玩家的手册。** 你手上有 AE，能用 —— 这份文件讲怎么用、有什么坑、
以及游戏这边已经为你准备好了什么。

> 一句话：**AE 里做，导出 PNG 序列帧，丢进 `content/fx/`，改一行 JSON。**
> 管线已经通了，`content/fx/slash/` 里那 24 张就是一条能跑的示例
> （占位素材，等着被你替换掉）。

---

## 一、三条路，选一条

从 AE 到 2D 游戏有三条路，各自适合什么：

| 路线 | 怎么走 | 适合 | 不适合 |
|---|---|---|---|
| **PNG 序列帧** ⭐ | AE 渲染成一张张 PNG，游戏当翻页动画播 | **2D 战斗特效** —— 刀光、爆炸、蓄力、命中 | 需要跟场景实时互动的东西 |
| Lottie | AE 装 Bodymovin 插件导出 JSON，运行时用 lottie-web 播 | UI 动效、图标、矢量小动效 | **特效** —— Lottie 不支持 AE 的 Glow / 混合模式 / 粒子，做出来和 AE 里完全不一样 |
| 视频 / GIF | 导出 mp4 或 gif | 只当参考图、发群里 | 游戏里用不了（没有 alpha、不能加色混合、解码贵） |

**结论：走 PNG 序列帧。** 它是 2D 动作游戏的标准做法，AE 就是干这个的。

⚠ **别用 Lottie 做特效。** 这是最容易踩的坑：你在 AE 里加个 Glow，
导出 Lottie 之后那层光**直接消失**，而且不会报错。

## 二、游戏这边已经准备好了什么

```
content/fx/
├── slash.json          ← 特效定义（帧数、帧率、比例、锚点、混合模式）
└── slash/
    ├── slash_0001.png  ← 第 1 帧
    ├── slash_0002.png
    └── ...             ← 一共 24 张
```

定义长这样（`content/fx/slash.json`）：

```jsonc
{
  "schemaVersion": 1,
  "id": "fx.slash",              // 技能里用这个 id 引用它
  "name": "刀光",
  "kind": "flipbook",
  "dir": "slash",                // 帧文件所在子目录
  "prefix": "slash_",            // 文件名前缀
  "pad": 4,                      // 帧号补零到几位 → slash_0001.png
  "start": 1,                    // ⚠ 第一帧的编号！AE 默认从 0 开始
  "ext": "png",
  "frames": 24,
  "fps": 60,                     // 播放帧率（和游戏 tick 一致最省事）
  "pxPerMeter": 64,              // 你做图时按多少像素 1 米
  "meters": 6,                   // 它在游戏世界里占多宽
  "anchor": [0.5, 0.5],          // 贴图上的哪个点对齐到施法者
  "offset": [0, 0],              // 相对施法者的偏移（米）
  "rotate": "none",              // none | facing（跟着朝向转）
  "blend": "add"                 // add（发光，推荐）| normal
}
```

### ⚠ `start` 别写错

**AE 默认从 0 开始编号**（`xxx_00000.png`），也有的从 1 开始。
写错的表现是整条特效 404，而报错只说"读不到图片"——
完全看不出是编号起点的问题。**看一眼你的文件名再填。**

### 写完先跑素材检查器

进游戏之前先跑这个，它会解码每一帧，把那些**不报错但会很难看**的事说出来：

```bash
node tools/check-fx.ts content/fx/<你的目录>
```

| 它查什么 | 不查会怎样 |
|---|---|
| 背景是不是真的透明 | 忘了关背景层 → 加色混合下变成一整块亮斑 |
| 内容有没有顶到画布边缘 | 合成开小了 → 特效被切一刀，画面上看不出来 |
| 有没有空帧 | AE 补零导出常带空白头尾 → 按下去先愣一下 |
| 内容和画布中心差多少 | 锚点对不上 → 火花炸偏 |
| 各帧尺寸 / 通道一致吗 | 有的带 alpha 有的不带 → 播到那一帧闪一下 |

你做的魔法飞弹命中火花跑出来是这样：

```
  12 帧  ·  256×256  ·  带 alpha
  内容中心  (127.5, 127.5)   画布中心  (127.5, 127.5)   ✓ 居中
  完全透明的像素  平均 68.2%
  ! [序列] 有 2 张空帧（..._00000.png, ..._00011.png）—— 播起来会先愣一下
```

**导出本身做对了**（背景透明、内容居中）。空帧是 AE 补零的正常现象，
不理它也行，想更利落就把 `start` 改成 1、`frames` 改成 10。

技能里这样引用（`content/skills/cleave.json`）：

```jsonc
"delivery": { "kind": "meleeArc", "radius": 2.5, "angle": 120,
              "vfx": "fx.slash" }     // ← 就这一行
```

### 投射物是**两个**时机，别搞混

| | 什么时候播 | 坐标 |
|---|---|---|
| 发射 | **不播** —— 子弹自己是实体，已经在画了 | — |
| **命中** | 播 `vfx` 指定的那条 | **目标的表面上**（接触点） |

⚠ 是**表面**，不是怪物中心。
用中心点的话，打大体型 Boss 会看起来像**自爆** ——
火花从身体正中炸开，而不是在身上炸开。半径 3 米的 Boss，差整整 3 米。

**不写 `vfx` 就用程序化的兜底特效**（投射物命中例外：那时什么都不额外画，
因为命中本来就有粒子、飘字和顿帧）。所以素材没做好之前游戏照样能跑，
加了新载体也不会变成隐形的。

## 三、⚠ `pxPerMeter` 和 `meters` 是两件事

这是**最容易搞错**的一处，单独讲：

```
pxPerMeter = 64     你做图时的比例（这张图里 64 像素 = 1 米）
meters     = 6      它在游戏世界里该占多大（6 米宽）
```

游戏画的时候会把你的图缩放到 `meters` 宽。
所以**想让特效大一倍，改 `meters` 就行，不用重做图**。

### 「是不是太小了」不用猜 —— 有预览器

```bash
node tools/preview-sprite.ts magic-bolt-hit              # 按定义里的 meters
node tools/preview-sprite.ts magic-bolt-hit --meters 4   # 试 4 米
node tools/preview-sprite.ts magic-bolt-hit --frame 7 --boss 3
```

它会把你的素材按世界尺寸合成到一张画布上，**三栏并排**：

```
[小怪 半径0.5米]      [Boss 半径3米]        [Boss 半径3米]
 接触点                接触点                目标中心 ← 旧行为
```

于是"多大合适""炸在哪"变成**一眼能判断**的事，不用来回开浏览器试。

### 该按什么尺寸做（先决定世界大小）

| 特效 | 世界大小 | 建议 pxPerMeter | 画布 |
|---|---|---|---|
| 单个挥砍的刀光 | 6 米见方 | 64 | 384×384 |
| 命中火花 | 3~4 米见方 | 128 | 384×512 |
| 大型爆炸 | 10 米见方 | 64 | 640×640 |

**别做太大。** 一帧 384×384 的 RGBA 解码后是 590 KB，
24 帧就是 14 MB 内存 —— 十条特效就 140 MB 了。
512×512 以上先别考虑，除非你打算上图集和压缩纹理。

### 米是什么概念

游戏里的参照物，你画的时候按这个来就不会错：

```
人物半径   0.5 米
场地半径   18 米
跑速       6 米/秒
裂地斩     扇形 2.5 米半径、120° 张角
魔法飞弹   12 米/秒，飞 1.5 秒（约 18 米）
```

### 怎么判断"太小了"

拿**怪物的直径**当尺子：

- 比怪物小 → 看起来像没打中
- 跟怪物差不多 → 像轻轻碰了一下
- **1.5~3 倍怪物直径** → 有力度（命中火花该在这档）
- 大过 4 倍 → 会盖住怪物本身，看不清打的是谁

小怪直径 1 米，所以命中火花 **2~3.5 米宽**是舒服的范围。
现在 `fx.magic-bolt-hit` 是 **3.5 米**。

## 四、AE 导出：一步一步

### 1. 新建合成

- 尺寸按上面的表（比如 **384×384**）
- **帧率设成 60** —— 和游戏 tick 一致，不会因为取整产生跳帧
- 时长按 `帧数 / 60` 算：24 帧就是 0.4 秒

### 2. 关键：原点放在哪

**合成的中心 = 施法者站的地方。**

因为 `anchor: [0.5, 0.5]` 的意思是"贴图正中心对齐到施法者"。
所以刀光的挥砍圆心要在画布正中，光效往一边铺开。

想让特效偏离施法者（比如从刀尖发出），用 `offset`。

### 3. 做动画

随便你怎么做，但有几条经验：

- **别在第一帧就是满屏**。特效要有"起—爆—收"：前 20% 亮起来，
  中间最亮，后面快速衰减。全程一样亮的特效看起来是贴纸。
- **亮的地方要过曝**。AE 里把亮度推到 1.0 以上（用 Linear Color + 32bpc），
  导出时会被钳到白 —— 那正是发光该有的样子。
- **加色混合的效果，在 AE 里就该当加色做**：把图层混合模式设成 **Add / Screen**，
  背景铺一层纯黑。这样导出的 PNG 直接扔进游戏用 `blend: "add"` 就是一样的。
- **别依赖 AE 的 Glow 效果**做主要亮度 —— 它不吃混合模式，
  换到 Lottie 就没了。用多层模糊 + Add 手搓一个，可控得多。

### 4. 渲染

⚠ 这里是坑最多的一步：

```
渲染设置：
  格式            PNG 序列
  起始编号        1          ← 不是 0！
  输出到          content/fx/<名字>/
  文件名          <前缀>_[####].png

输出模块：
  通道            RGB + Alpha     ← 要 alpha
  深度            8 位
  颜色            Straight (Unmatted)  ← 见下面的说明
  压缩            无（PNG 本身已压缩）
```

**关于 alpha，两种做法选一种：**

| 做法 | 渲染设置 | 游戏里 |
|---|---|---|
| **A. 黑底不透明**（推荐） | 通道 = RGB（不要 alpha），背景铺纯黑 | `blend: "add"` |
| **B. 带 alpha** | 通道 = RGB + Alpha，颜色 = Straight | `blend: "normal"` |

**A 更好，尤其对发光类特效**：加色混合下黑底等于透明，
而且完全没有"边缘一圈暗边"的问题（那是 Straight alpha 在加色下的经典毛病）。
只有需要**不透明实体**（石头、铁片）时才用 B。

### 5. 接进游戏

1. 把 PNG 放进 `content/fx/<名字>/`
2. 照着 `slash.json` 写一份 `content/fx/<名字>.json`（改 `dir` / `prefix` / `frames` / `meters`）
3. 在 `content/manifest.json` 的 `fx` 列表里加上名字
4. 技能里写 `"vfx": "fx.<你的 id>"`
5. 刷新浏览器（服务器不用重启，`npm run serve` 是直接读磁盘的）

## 五、别忘了几条硬约束

| 约束 | 为什么 |
|---|---|
| **帧数必须和磁盘上的 PNG 数量一致** | 少一张，序列播到一半会跳。`npm test` 会检查这一条 |
| **文件名必须是 `前缀 + 补零序号`** | 游戏按 `prefix + pad + 序号` 拼路径，没有清单文件 |
| **`meters` 要装得下整个特效** | 刀光半径 2.5 米，画布至少 5 米见方，不然会被切掉 |
| **fps 和 tick 对齐（60）** | 不对齐会出现某几帧被跳过或重复 |
| **只影响画面，不影响判定** | `vfx` 改任何东西都不会让技能变强或变弱 —— 判定看的是 `radius` / `angle` |

## 六、现在的兜底长什么样

你没做特效的时候，游戏用**程序化**的方式画（`web/src/fx.ts`）：

- 八种载体各一套画法（扇形扫、光束、突刺、范围扩散、光环）
- 按伤害类型上色：物理白青 / 火焰橙 / 奥术紫 / 暗影黑紫 / 冰霜蓝 …
- 想看一眼不用开浏览器：

```bash
node tools/preview-fx.ts                       # 扇形挥砍
node tools/preview-fx.ts --type fire           # 换配色
node tools/preview-fx.ts --kind beam           # 换载体
```

**两条路线并存，不是二选一。** 主角技能用你做的序列帧，
杂兵和临时效果继续用程序化的 —— 那不用画。

## 七、给你做的第一个特效的建议

**别从裂地斩开始。** 它涉及扇形扫过 + 锚点在圆心 + 跟着朝向，
一次要同时搞对四件事。

按这个顺序练手（每一步都能单独验证）：

1. **命中火花**：2 米见方、12 帧、`anchor` 居中、`blend: "add"`、`rotate: "none"`。
   不涉及朝向和偏移，最容易跑通。挂在 `skill.magic-bolt` 的 `onHit` 上。
2. **蓄力光环**：一圈由暗到亮再炸开，4 米见方、30 帧。挂在贯日的蓄力阶段。
3. **裂地斩的刀光**：把 `content/fx/slash/` 里那 24 张替换掉。
   参数不用改，只要你的画面比例和它一致。

**做完第一个就刷新浏览器看**，别一口气做五个 ——
`pxPerMeter` 和 `meters` 的关系第一次一定会搞错，早发现早改。
