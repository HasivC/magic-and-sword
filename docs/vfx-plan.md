# 技能特效：现状、分工、做法

> **进度：第 1~2 步做完了（裂地斩的扇形挥砍），第 3 步（数据化）还没做。**
> 预览图在 `technique-system/docs/fx/`，重跑一条命令就能再生成：
> `node tools/preview-fx.ts --kind meleeArc --type physical`

**玩家的问题：技能特效是我做还是你做？怎么做？**

结论先放这：

> **程序化特效（几何 + 颜色 + 时间）我做；美术资产和审美判断你做。**
> 现在这个阶段（手搓 Canvas、没有资源管线）**程序化是唯一划算的做法** ——
> 零资产、可数据化、能被编辑器调。
> 等到要贴图和序列帧的时候，那部分必须是你（或者买）。

| **按载体分派的绘制器** —— 扇形 / 光束 / 突刺 / 范围 / 光环，**没有一种是隐形的** | `web/src/fx.ts` |
| **按伤害类型上色的风格表** —— 8 种类型各有配色和性格 | `web/src/fx.ts` 的 `STYLES` |
| **离线预览器** —— 不用开浏览器就能把特效渲染成 PNG | `tools/preview-fx.ts` |
| **测试** —— 51 个断言，含"几何不出 NaN""打空也要有特效""每一层拖尾不能有百叶窗" | `tests/fx.ts`、`tests/cast.ts` |

**"描述与绘制分开"是这一轮最重要的结构决定**：
`deliveryPrims(fx)` 是纯函数，吐出图元列表；canvas 只负责把图元画出来。
好处是**特效可以离线渲染** —— 否则"这道刀光好不好看"只能靠你在游戏里看，
一轮迭代好几分钟。整个第一版是照着预览图改出来的（改了 5 轮）。

还留着没做的：**特效参数还是代码里的常量，不是内容里的数据**（第 3 步）。

## 一、现在是什么样

### 有的

| 表现 | 触发 |
|---|---|
| 受击闪白 | `damaged` |
| 伤害飘字 / 暴击大字 | `damaged` |
| 命中爆点粒子 | `damaged` |
| 顿帧 + 抖屏 | 模拟层（按掉血比例） |
| 施法条 | 当前阶段进度 |
| 状态点 | `entity.statuses` |
| 投射物（圆点 + 尾迹） | `projectile` 实体 |
| 音效（WebAudio 合成） | 命中 / 治疗 / 格挡 / 死亡 / 施法 |

### 没有的 —— 这才是问题

**八种载体里有五种完全没有表现：**

| 载体 | 谁在用 | 现在看得见吗 |
|---|---|---|
| `projectile` | 魔法飞弹 | ✅ 有 |
| `beam` | **贯日、裂魂** | ❌ **什么都没有** |
| `meleeArc` | **裂地斩** | ❌ 只能看到对方掉血 |
| `area` | **熔岩护甲反伤、无下限光环** | ❌ |
| `capsule` | （还没人用） | ❌ |
| `aura` | （还没人用） | ❌ |

**你报的"贯日没有技能特效"，不是一个技能的问题，是一整类载体没做。**
六个用了载体的技能里，**五个是看不见的**。

### 两个更深的缺口

1. **`StatusDef.vfx?: string` 是个死字段。** 它在 schema 里躺着
   （内容里写了 `"vfx": "fx.lava-armor"`），但**全项目没有一行代码读它**。
   这是"schema 承诺了、实现没跟上"的典型 —— 也就是这个项目一直在防的那种腐烂。

2. **`DeliverySpec` 连 `vfx` 字段都没有。** 它有几何（radius / angle / length / width），
   但没有任何表现相关的字段。

3. **事件里没有"动作打出去了"这一条。** 15 种事件全是"结果"
   （`damaged` / `healed` / `statusApplied`…），没有"过程"。
   所以客户端只能从 `damaged` 反推是谁打的 —— **打空了就没有特效**，
   而"打空了"恰恰是最需要看得见的时刻（玩家得知道自己空了）。

## 二、分工：谁做什么

### 我做

| 事 | 为什么是我 |
|---|---|
| **一个 `deliveryFired` 事件**（带 from / dir / length / width / kind） | 几何只有模拟核知道。让客户端反推 = 两份真相 = 一定会漂移 |
| **按载体分派的程序化绘制器**（扇形扫 / 光束 / 突刺 / 圆爆 / 光环） | 纯代码 |
| **数据化的特效规格**（颜色、大小、时长、层数） | 和点数、说明一样：**特效也必须是内容的函数** |
| **把 `vfx` 字段真正接上**（状态 + 载体） | 补上 schema 承诺过的东西 |
| **编辑器里能调** | 你的调色板滑块已经在了，加几个字段就够 |
| **测试**（事件发出去了、画了没报错） | 老规矩 |

### 你做

| 事 | 为什么只有你能做 |
|---|---|
| **颜色、亮度、速度、大小** | 这是品味。我可以给你三个候选，但选哪个是你的 |
| **"这一下打起来爽不爽"** | 只有玩的人知道 |
| **优先级**：哪个技能最需要 | 你玩得最多 |
| **将来上美术资源时的一切**（贴图、序列帧、骨骼动画、粒子贴图） | 那是资产制作，不是编程 |

### 一条硬边界

**美术资产你做，程序化特效我做。**

现在**不要做美术资产**：这个项目还没有资源管线（没有图集、没有加载器、
没有动画状态机），塞一张 PNG 进来要连着做三件事，而收益只是一道光。
程序化特效在这个阶段是**零成本、可数据化、能被编辑器调**的 —— 划算得多。

## 三、怎么做（按顺序，每一步都能单独验证）

### 第 1 步：让模拟核说"我打出去了"（约 40 行）

新增一个纯几何事件：

```ts
| { type: 'deliveryFired'
    casterId: number
    techniqueId: string
    kind: DeliveryKind
    from: Vec2          // 起点
    dir: Vec2           // 方向（单位向量）
    length?: number
    width?: number
    radius?: number
    angle?: number
    hitCount: number    // 打中了几个（0 = 打空，也要画）
  }
```

**它是几何，不是渲染指令** —— 和 `damaged` 带个 `amount` 是同一类东西，
不违反纪律 4（core-sim 不认识浏览器）。

**打空也发**，`hitCount: 0`。这是关键：玩家必须能看见自己空了。

验证：`tests/cast.ts` 里断言"放一个光束技 → 事件里有 deliveryFired，
`hitCount` 对得上"。确定性测试不受影响（事件是数据）。

### 第 2 步：一个按 kind 分派的绘制器（约 120 行）

```ts
// web/src/fx.ts（新文件）
export function drawDelivery(f: DeliveryFx): void
```

每种载体一条**最简**画法，先只求"看得见、方向对、有起止"：

| kind | 画法 |
|---|---|
| `beam` | 一条粗线，宽度渐细，加一层更亮的芯；0.15 秒内从亮到透明 |
| `meleeArc` | 从半径内到半径外扫过的一段圆弧（`angle` 度），0.12 秒 |
| `capsule` | 一条带圆头的短粗线，快速伸缩 |
| `area` | 圆环由内向外扩散 + 填充淡出 |
| `aura` | 跟随施法者的细圆环，呼吸 |
| `projectile` | 保留现在这个，尾迹加长一点 |

**先全部用一个颜色**（当前 `COLOR.projectile` 那类黄白色），
跑起来之后再谈颜色 —— 一上来就调色会陷进去。

验证：`npm run build:web` → 打开 5173 → 按 3 放贯日，应该看见一道光。

### 第 3 步：把特效变成数据（约 60 行）

`DeliverySpec` 和 `StatusDef` 各加一个 `vfx`，然后**真正读它**：

```jsonc
"delivery": { "kind": "beam", "length": 12, "width": 0.8,
              "vfx": { "color": "#7ee0ff", "glow": 1.6, "time": 0.15 } }
```

规矩和别处一样：
- 不写就用按 kind 的默认值（所以**现有内容一个字都不用改**）
- 编辑器里出现滑块（颜色可以先只给几个预设，别做取色器）
- 校验器管一件事：`vfx` 里不许出现只有渲染层认识的字符串
  （`"fx.lava-armor"` 这种"名字"就是死字段的来源 —— 要么是数据，要么别写）

### 第 4 步（可选，等前三步跑顺）：状态特效

`StatusDef.vfx` 现在是死的。接上之后：
- 熔岩护甲 → 身上一层脉动的橙圈
- 破甲 → 目标身上裂开的短线
- 名刀 → 拦下的那一瞬间一道竖光

同一套绘制器 + 一个 `statusVfx` 表。

## 四、我需要你给的三个决定

1. **先做哪一类？** 我建议 `beam`（你报的贯日，而且它最简单：一条线）。
   也可以选 `meleeArc`（裂地斩是近战主力，扇形比线更有存在感）。
2. **整体风格**：现在全场是**极简几何**（圆点 + 线 + 网格）。
   特效要**同一路**（干净的线光、少量粒子），还是**往艳丽走**（多层辉光、拖尾、粒子雨）？
   前者和现有画面自洽，后者更"有打击感"但会显得主角是特效。
3. **要不要随技能颜色变化**：比如火焰系偏橙、奥术偏青。
   这需要给伤害类型定一张颜色表（`damageType` 已经有 `fire` / `arcane` / `shadow` 这些值）。

**你不回答我也能动手**（默认：先做 beam + 同一路极简风格 + 按 `damageType` 上色），
但上面三个是你的地盘，你说了我就照你的来。

## 五、这件事顺带解决什么

- **打空了有反馈** —— 现在空放一个技能，屏幕上什么都没有
- **编辑器多一个维度** —— 特效参数和数值一样可调
- **`vfx` 死字段清掉** —— 少一处"schema 承诺了但没人做"
- **为"能卖"那一步留门** —— 当美术资产进场时，接的是同一张 `vfx` 表，
  而不是重写一遍渲染

## 六、不做的事（明确排除）

- ❌ 不做贴图 / 图集 / 序列帧 / 骨骼动画（等有资源管线）
- ❌ 不做屏幕后处理（Bloom、色差）—— Canvas 2D 做不了，要上 WebGL
- ❌ 不做摄像机（死跟着玩家是另一个已知问题，单独解决）
- ❌ 不给每个技能手写一段特效代码 —— **那正是这个项目一直在防的"两份真相"**
