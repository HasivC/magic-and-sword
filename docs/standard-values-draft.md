## 零、先看这五句（不然这张表会被误用）

1. **⭐ 中性点 = 每个技能自己的出厂值。** 账 = 现在的技能 − **这个技能自己的出厂值**
   （`skillLedger`）。**没有「全局冷却标准 = 8 秒」这回事**
   —— 横砍的 8 秒就是**横砍的 0 点**、突刺的 3 秒就是**突刺的 0 点**。
   **每一份技能各自为 0，一个例外都没有。**
2. **⭐ 所以本文那张「标准值」表只剩一个用途：给新造的东西一个起点。**
   你新加一条规则 / 加一个阶段时，默认数写多少（前摇 0.3 / 命中 0.2 / 后摇 0.2 / 能量 10…）。
   ⚠ **它不是中性点，也不是「每个技能该有的值」** —— 全篇凡出现「标准值」都按这个意思读
   （本文已把它改称「**起点值**」，两个词同义）。
3. **⚠ 不解决「起点」，`default-values.md` 自己写着的那句话就会发生** ——
   「**不定的话，后写的技能会慢慢和先写的对不上**」。
4. **本表的数字全部是「量出来的」，不是拍脑袋的。** 每个数字都能用
   `node .scratch/standard-values-stats.mjs` 从 `content/` 重算一遍
   （脚本在 `.scratch/`，没进仓库）。
5. **玩家已经定过的东西，本文一个字都不提改**：
   **CD 保留** ✓、**「取消前摇」= 阶段时长调到 0 秒那一档（不是删掉这个阶段）** ✓、
   **档位 `0 / 1× / 3× / 9×`** ✓、**0 档消耗点数 / 1× = 0 点 / 3×·9× 提供点数** ✓、
   **档位跟着技能自己的值走**（`×3` = 3 × **这个技能自己的**出厂时长）✓、
   **K = 9 先定** ✓（0 档与 9× 档同价反号，以后慢慢测试调整）。

## 二、伤害

### 最新量出来的分布（n=14 个 `payload.kind = 'damage'` 出现点）

| 值 | 次数 | 出现在哪 |
| --- | --- | --- |
| **25** | **5**（众数） | 魔法飞弹（飞弹）、猎杀（飞弹+追击）、寒冰锁（飞弹）、冲击波 |
| **30** | 3 | 破甲突刺、裂地斩、熔岩护甲（反伤） |
| 36 | 1 | 刺击（`ref: weapon.damage` 的曲线顶点） |
| 50 | 2 | 火墙、横砍（曲线顶点） |
| 150 | 1 | 蓄力射线（曲线顶点，蓄满） |
| 200 | 2 | 血祭斩、裂魂 |

- **众数 25**，中位 **30**，范围 **25 ~ 200**，取值数 6
- **伤害类型的分布**：`physical` 8 / `arcane` 2 / `fire` 2 / `ice` 1 / `shadow` 1
- ⚠ **200 那两处不是「标准技能」**：血祭斩是拿自己 200 血换的，裂魂是 20 秒冷却 + 40 能量的终结技
- ⚠ **25 出现 5 次，全在「一发普通技能」这个位置上** —— 飞弹类、追击类、爆发类都是 25

### ✅ 「起点值」（= 新造东西时的默认数）：**伤害 25**

⚠ 先说清它**不是**什么：它**不是中性点**（中性点 = 每个技能自己的出厂值，§0 第 1 句），
也**不是**「每个技能该有的伤害」。它是**你新造一发普通攻击时，默认写 25**。

- **为什么是 25 而不是 30**：25 是**多重锚点**指向的同一个数 ——
  ① 内容里的众数（5 次）；
  ② **武器倍率曲线**（`weapon-skills/slash.json` 的 `[[1,25],[2,50]]`）把 ×1.0 定义成 **25**，
  刺击那条是 36（×1.0 的另一种写法）；
  ③ 定价表自己的汇率 `damagePerPoint = 27.632`，1 点 ≈ 27.6 伤害 —— **25 离它最近**。
  **三条独立的路指向 25，30 只有「内容里的第二多」。**
- **它怎么和「默认值下配平为 0」对上**：**这一点正是关键** ——
  25 是**新造东西的起点**，不是**每个技能**的中性点。
  魔法飞弹出厂就是 25 伤害 → 它自己的账是 0 ✓；
  裂魂出厂是 200 → 它自己的账**照样是 0** ✓。
  **「25」的角色是**：你写第 31 个技能时，一发普通攻击就写 25；
  想写 200，那它就得**在别处**（冷却、能量、前摇）付出代价 ——
  而那笔代价是**这个技能自己的出厂值**定的，与 25 无关。**两者不打架。**
- **⚠ 25 的副作用（要知道）**：按现行汇率，25 伤害 = **0.90 点**，30 伤害 = **1.09 点**。
  也就是说**「25 还是 30」在账上只差 0.19 点** —— 远小于配平容差 2 点。
  ⇒ **这条其实是个「手感 / 文风」问题，不是平衡问题。** 定它的唯一实用价值是**统一**。

### ✅ 已裁定：伤害起点值 = **25**，不分类型

| | 案 | 内容 | 结果 |
| --- | --- | --- | --- |
| **A** ✅ **采纳** | 一刀切 **25** | 所有「一发普通技能」= 25；想更强就**明确当作重击**（不新开一档） | **这就是现行** |
| **B** ❌ 未采纳 | 分档 | 普通 **25** / 重击 **30**；并在表里定义「重击」= 伤害 ≥30 且带 ≥3 秒冷却或 ≥20 能量 | 多一个概念要维护 |

**为什么采纳 A**：25 已经被**武器曲线**（×1.0 → 25）和**汇率**双重锚定，
改 30 就要动 `slash.json` 的曲线（那是**只读内容**，且武器技能不算账、改它没有账上的好处）；
而 B 那套「重击」判据，其实就是**冷却和能量**在干的事，再说一遍是重复。

✅ **伤害起点值不分类型**（物理 / 元素一律 25）。
量出来的内容里 `physical` 占 8/14，元素合计 6/14，**没有哪个元素系统性更高或更低**
⇒ 按类型分档（物理 25 / 元素 20）**在当前内容里没有证据支持**，**先不分**，
等出现「元素天然更强」的实证再说。

## 三、前摇

### 最新量出来的分布（n=**21** 个「前摇」阶段）

| 值 | 次数 |
| --- | --- |
| 0.1 | 2 |
| 0.15 | 2（两处都是武器技能模板） |
| **0.3** | **9**（众数） |
| 0.5 | 8 |

- **众数 0.3**，中位 **0.3**，范围 **0.1 ~ 0.5**，取值数 4
- 值得注意的形状：**只有 0.1 / 0.15 / 0.3 / 0.5 四个值**，而且集中在 **0.3 和 0.5 两头**
  （9 vs 8）—— 中间是**空的**。这正好符合点表的哲学「**夹在中间那一格不是决策**」。
- **配套的量（写的时候要一起看）**：前摇是**能量代价**的家 ——
  **18/21 个前摇挂 `cost.energy`**（能量只在前摇出现过 20 次，其中 18 次在前摇）；
  `cancellable: true` **18 次**（前摇是唯一「默认可取消」的阶段）。
- ⚠ **一个反例**：`skill.cleave` 的前摇只有 **0.1 秒**却打 30 伤害 + 挂 3 秒破甲 ——
  它靠 **3 秒冷却 + 10 能量**付账。**说明前摇不是唯一的代价轴**（这条对 §12 的档位设计很要紧）。

### ✅ 「起点值」（= 新造东西时的默认数）：**前摇 0.3 秒**

- **为什么**：0.3 是众数（9/21），也是 `default-values.md` L72 已经写下的数 —— **两边一致，不用改**。
  另一头 0.5 秒出现 8 次，它不是「更大的前摇」，而是**另一类技能**：量出来 0.5 秒的 8 处里
  有 7 处是**自我增益 / 控制 / 场域**（护盾、魅惑、复活、铁布衫、圣光术、缓速场、血祭）
  —— 也就是**「我要读条施法」**这一类，不是「我一刀砍出去」。
  ⇒ **0.3 = 打人的招，0.5 = 施法的招**，两个档都在内容里活着（见 §六 的「按机制分开定价」）。
- **怎么和「默认值下配平为 0」对上**：⚠ **这里要把三件事分清**（§0 第 1、2 句）——
  - **起点值 0.3** = 新造一个前摇时默认写 0.3（**不进账**）；
  - **中性点** = **这个技能自己的出厂前摇**（魔法飞弹的中性点是它自己的，与 0.3 无关）；
  - **绝对账上 0.3 秒有价**（0.26 点）= 内部强度标尺，不判配平。
  **三件事各归各位，不打架** —— 这正是 `default-values.md` 内部打架的根，见 §13。
- **⚠ 顺带一条硬事实**：**「无前摇」（时长 = 0）今天写不出来** ——
  编辑器的时长点表是 `[-1, 0.1, 0.2, 0.3, 0.5, 1]`，**里面没有 0**；
  而 `-1` 是**蓄力**哨兵值（时长由玩家控制），**不是「没有前摇」**。
  schema 那层也不拦（`Phase.duration` 没有下限）。
  ⇒ 「取消前摇」这一档要落地，**先得把 0 加进点表**，而 0 一旦写进去，
  `src/sim/cast.ts` 会把它当**瞬发**处理（`advancePhase` 一个 tick 走完）——
  **定价却照 `0 × rate = 0` 算，等于免费**。**所以 0 档必须走 §12 的非线性算式**，
  否则就是「引擎给好处、账上不扣钱」。

### ✅ 已裁定：前摇起点值 = **0.3**（打人招）/ **0.5**（施法招）

| | 案 | 内容 | 结果 |
| --- | --- | --- | --- |
| **A** ✅ **采纳** | 前摇起点 **0.3 秒**，另设「施法型」**0.5 秒**（同表两行，不按机制分汇率） | **这就是现行** |
| **B** ❌ 未采纳 | 前摇起点 **一律 0.3 秒**，0.5 秒算「偏离」（那 8 个技能在尺子上全部算「慢」） | |

**为什么采纳 A**：0.5 秒在内容里出现 8 次，**不是偏差，是一整个技能类别**；
把它标成「偏离起点」会让**半个出厂内容在尺子上都显示超慢**，
下一轮写内容的人就会开始「把 0.5 改成 0.3」——**那是内容事故，不是配平**。

## 十二、⭐ 档位与每档点数（含 0 档的**非线性**）

⚠ 这一节的前提是玩家**已经定过的**四条：
`0 / 1× / 3× / 9×` ✓、0 消耗 / 1× = 0 / 3×·9× 提供 ✓、

**K = 9 先定** ✓（0 档与 9× 档同价反号）。
**本节只把「每档值多少点」和「0 档为什么贵得多」写成算式。**

### 12.1 先把币值摆出来（不然档位数字没有手感）

| 1 点 = | 值 | 出处 |
| --- | --- | --- |
| 伤害 | **27.63** | `damagePerPoint` |
| 能量 | **19.92** | `energyPerPoint` |
| 冷却 | **5 秒** | `1 / cooldownSecondPerPoint(0.2)` |
| 阶段时长 | **1.16 秒** | `1 / phaseSecondPerPoint(0.863)` |
| 射程 | **3.98 米** | `1 / rangePerMeter(0.251)` |

⇒ **配平容差是 2 点**，而**前摇 0.3 秒只值 0.26 点**。
⚠ **这个量级差就是本节全部难点的来源**：阶段时长这一轴**天生很便宜**
（整条前摇也就 1/4 个点），**所以「0 档要贵得多」不能靠「多给几秒」实现，只能靠一个乘数。**

### 12.2 记号的约定（**这条是本节能不能读对的关键**）

```
D = 【这个技能自己的】出厂时长（不是起点值！）
```

| 情形 | D 取什么 | 1× 档的账 |
| --- | --- | --- |
| **改一个出厂技能**（编辑器里拖滑块） | **这个技能自己的出厂时长** | **0 点**（因为中性点就是它自己） |
| **新造一个阶段** | **起点值**（前摇 0.3 / 命中 0.2 / 后摇 0.2） | 0 点（对「新造」而言，起点值就是它的出厂值） |

⚠ **两种情形下「1× 档 = 0 点」都成立**，因为**中性点永远是「这个技能自己的出厂值」**（§0 第 1 句）。
本文 12.3–12.5 的所有算式都按 **D = 这个技能自己的出厂时长**读。

### 12.3 按现行线性式算出来的账（**这就是问题的现场**）

`pricePhase`：`duration × 0.863`（`0` 档就是 `0 × 0.863`）

| 段 | 0 档（线性算） | 1×（= 各自出厂值） | 3× | 9× | 相对 1× 的净额（3×） | （9×） |
| --- | --- | --- | --- | --- | --- | --- |
| 前摇 0.3 | **0.00** | 0.26 | 0.78 | 2.33 | **+0.52** | **+2.07** |
| 命中 0.2 | **0.00** | 0.17 | 0.52 | 1.55 | **+0.35** | **+1.38** |
| 后摇 0.2 | **0.00** | 0.17 | 0.52 | 1.55 | **+0.35** | **+1.38** |

⚠ **问题一目了然**：按线性式，**「取消前摇」是 0 点**（0 秒 × 任何汇率 = 0），
而「**慢三倍**」能**挣 0.52 点**。
⇒ **玩家原话「没有前摇很超标」在今天的账上完全反映不出来** ——
**它比「慢三倍」还便宜，而且是永久免费。**
⚠ 而且还有第二层：`src/sim/cast.ts` 会把 0 秒阶段当**瞬发**处理（一个 tick 走完整条术式），
**定价却是 0** ⇒ **引擎给的好处，账上一点没扣。**
⇒ **0 档必须非线性，不是审美问题，是「不这么干就是白嫖」的问题。**

### 12.4 ✅ 0 档的算式（**已裁定：K = 9**）

档位本身是几何级数（1 → 3 → 9，公比 3）。既然 3× 和 9× 是 `+2D` / `+8D`，
那么 **0 档到 1× 之间的「距离」也按同一个公比往回退一格**：

```
1× 档价   = D × 0.863
3× 档价   = 3D × 0.863        净 +2D × 0.863
9× 档价   = 9D × 0.863        净 +8D × 0.863
0  档价   = 9D × 0.863        净 −9D × 0.863     ← K = 9，0 档与 9× 档同价、反号
```

⇒ **0 档 = 9 ×（D × 0.863）**，也就是「**往回收一格**」和「**往外放一格**」
在几何级数上走同样远，因此**价钱一样、符号相反**。

- ⚠ **K = 9 是玩家先这么定的，以后慢慢测试调整** ——
  **它不是不可变的常数。** 想改就改 K：`0档价 = K × D × 0.863`，
  K = 3 温和 / **9 对称（现行）** / 更大更狠。
- **为什么 K = 9 比 K = 3 好**（照实说，这是签字时的理由）：
  K = 3 之下 `0档(0.78) < 9×档(2.33)`，于是「把 9× 档改成 0 档」这条轴上的净变化是
  「少拿 2.33、多付 0.78」—— **那 2.33 点白赚的额度还留着大半**，
  玩家白拿一个瞬发、账面看起来还是「赚了 0.78」。**K = 9 把这个洞堵死。**
- **「0 档是全表最贵的一档」** 与玩家原话「**没有前摇很超标**」一致：
  超标的东西就该是最贵的。

> ⇒ **这笔账基本补不平，只能靠血契付 —— 也就是每次释放都在流血。**

- ⚠ **量级换算写清楚**（免得读者以为这是个位数）：
  **−14.4 点 ÷ 2 点容差 = 超出容差 7 倍以上**；
  **−14.4 点 ÷ 3 点/次血契 ≈ 5 次血契事件**才抵得上**一次**改动。
- ⚠ **一句口径说明**：血契是**它自己那本货币**（负值术式用它付），
  它**不是**直接给点数账冲抵的数 —— 所以这里的「靠血契付」说的是
  **玩家 2026-09-21 的原话意思**：这笔差额大到只能走**负值术式 / 血契**那条路，
  每次释放都得拿血换。**这个量级是玩家看过之后才签的字。**
- ⚠ **K = 9 先定，以后慢慢测试调整**（§12.4）：如果测下来「无冷却」贵得没法用，
  **改 K 就是改这一个乘数**，不用动别的。
- ⚠ **这是设计意图，不是 bug**：「无冷却」是很强的收益，贵是应该的；
  但**贵到只能靠血契付**是一个真实的手感后果 —— 玩家看过这个数才签的字。

### 12.7 「无冷却 / 不耗蓝」也走**同一个 0 档算式**（K = 9 一把尺）

> ⚠ **起草时我给这一节写的是「K 只用在阶段时长这一轴上」** ——
> **那条被裁定否掉了 ✗。** 现在的口径简单得多：**同一个 K = 9 套所有轴**（玩家 2026-09-21）。

算式**一个式子走所有轴** —— 区别只在「汇率取哪一根」和「D 取这个技能自己的哪个值」：

```
0 档价 = 9 × D × 该轴的汇率
```

| 轴 | 该轴汇率 | D（举例 = 起点值） | **0 档价（K=9）** |
| --- | --- | --- | --- |
| 阶段时长 | `phaseSecondPerPoint` 0.863 | 0.3 秒 | **−2.33 点** |
| 能量 | `1 / energyPerPoint` ≈ 0.0502 | 10 能量 | **−4.52 点** |
| 冷却 | `cooldownSecondPerPoint` 0.2 | 8 秒 | **−14.4 点** |

⚠ 三行的算式**完全一样**，差别只来自「D 有多大」和「汇率有多粗」——
**这就是「一把尺」的意思**（起草时我写过「K 只用于阶段时长」，**已被裁定否掉**）。

⚠ **「省下一个 8 秒冷却」= −14.4 点这件事的后果，已经在 §12.6 写清楚了**
（折合 72 秒冷却额度 / 287 点能量；只能靠血契付，每次释放都在流血）。
**玩家看过这个数才签的字** ⇒ **K = 9 先定，以后慢慢测试调整**。

- ⚠ **为什么「一把尺」是能站住的**：0 档的价**等于该轴 9× 档的价**，
  而「9× 档给多少」本来就是内容自己定的（D 越大给越多）——
  **所以「冷却的 0 档贵」不是公式畸变，是冷却这条轴本来就粗**
  （5 秒 = 1 点，一条 8 秒冷却 = 1.6 点，已经吃掉容差的 80%）。
  **同一把尺量粗轴，量出来的数当然大 —— 这是对的，不是错的。**
- ⚠ **以后要调，就调 K 这一个乘数**（§12.4），别去动单条轴的汇率。

### ✅ 冲突 1：已消解 ——「起点值」和「中性点」是两件事

> **裁定：中性点 = 每个技能自己的出厂值。**

| | 说法 | 出处 | 现在 |

| **A** | 时间类**有基准**：前摇 **0.3 秒**、命中 0.2、后摇 0.2 ⇒ **0.3 秒这一档才是 0 点** | [`default-values.md`](default-values.md) L72–L74 | ⚠ **半对半错**：0.3 是**起点值** ✓，但它**不是**「0 点在哪」✗ |

**消解的方式**：**把两个被混着用的概念拆开**，各归各位 ——

| 概念 | 是什么 | 谁说了算 | 例子 |
| --- | --- | --- | --- |
| **中性点** | **账上 0 点在哪** | **每个技能自己的出厂值** | 横砍的 8 秒冷却 = 横砍的 0 点；突刺的 3 秒 = 突刺的 0 点 |
| **起点值**（本文旧称「标准值」） | **新造东西时的默认数** | 本文这张表 | 新加一条冷却就写 8 秒、新加一个前摇就写 0.3 秒 |

⇒ ⚠ **A 和 B 之所以打架，就是因为它们把这两个量当成了一个量。**
拆开之后**两个都对**：0.3 秒是起点值 ✓（A 对）；不花能量是**某些技能的**中性点 ✓（B 对了一半）。
**❌ 唯一被裁定否掉的是「存在一个全局中性点」这个想法本身。**
⇒ **§七 / §八 不需要改代码** ✓（`pricePhase` 的绝对式本来就和宗旨一致，相减之后各自为 0）。
