## 一、为什么要重调（一句话）

**点数刚刚改成整数**（**1 点一格**，而且**每个非零条目至少 1 点**）——
于是**量级小于半格**的汇率在账上**跨不动一格**：旋钮拖到底，账上还是同一个数，
也就是我们这一整轮一直在清的**"死滑块"**那一类。

用户点名的那个症状，本轮脚本**逐字复现**了：

```
半径 0.5 米 ⇒ 账上 −1 点
半径 6  米 ⇒ 账上 −1 点      ← ✗ 12 倍的半径差，账上一动不动
```

另外：**「弹射」刚落地，它的三条汇率还没经过用户签字**，本文档一并给建议值。

## 二、口径（数字可复算）

所有数字都由**一次性脚本**量出来，脚本放在 `.scratch/`（**不进仓库**）：

| 文件 | 作用 |
| --- | --- |
| `.scratch/rate-span-audit.mjs` | 主脚本：量三族九条旋钮 + 核对 `rates`（**只读，不写任何文件**） |
| `.scratch/recon-rate-axes.mjs` | 侦察：从 `content/**` 量出 `rates` 各条轴的出厂参数范围 |
| `.scratch/span-audit-final.txt` | 主脚本的完整输出（本文档所有表格的出处） |

复算：`node .scratch/rate-span-audit.mjs`

### 口径定义

1. **格** = `src/pricing.ts` 的 `integerPointsOf` 印出来的**整数点**（用户规格：1 点一格）。
2. **一条旋钮的轴** = 它自己那一个参数的**全范围**；**其余参数钉在原型默认值上**
   （排布 = 环绕 1.5 米 / 起始角 0°、追踪 = 8 米 / 12°·tick⁻¹、弹射 = 2 次 / 衰减 0.7）。
   > ⚠ **这是"拖那一个滑块、账动不动"的唯一忠实口径。**
   > ⚠⚠ **把同一族的参数一起动是错的**（本建议稿第一版就是这么量的，结果九条全部"健康"）：
   > 那样每个零件都"跨 2 格"，而跨格的其实是**底价**那条档差，不是被量的旋钮。
3. **自己那一项** = 这根轴对应的那个增量项（半径 × 每米 / 角度 × 每度 / 次数 × 每次 …），
   **不含底价**。"它自己够不够得着一格"的门槛是 **1.5 点**。
4. **跨格数** = `账上(轴的一端) − 账上(轴的另一端)`，指的是那**一个条目**的整数点之差。

### 门槛为什么是 1.5 / 2.5（脚本 §零 自检原文）

单条目过 `integerPointsOf` 之后是一条阶梯：

| 原料的绝对值 | 印在账上 |
| --- | --- |
| 0.1 / 0.85 / 1.4 | ±1 |
| **1.49** | ±1 |
| 1.5 | 正向 2；**负向仍是 1** |
| **1.51** | ±2 |
| 2.49 | ±2 |
| **2.5** | 正向 3；负向 2 |
| **2.6** | ±3 |

⇒ **够得着一格的门槛 ≈ 1.5 点**；**跨 2 格（±1 → ±3）的门槛 ≈ 2.6 点**。
（取 2.5 做解析门槛是保守的，负向在 2.5 那一格还会掉回 ±2。）

## 五、天生跨不动的旋钮 + 各自的两个选择

### 5.0 先说清"天生跨不动"是什么意思

上一轮只改**权重**救不回来的，是**轴本身太短**的那些：

> **轴太短** = 它那个参数在**自己的全范围**上，原料连 **1.5 点**都走不到
> ⇒ 无论权重怎么调，它都够不着一次四舍五入的台阶。
> ⚠ 这一条**不是**让你无限抬权重：抬到够 2 格要抬几倍，下表列出来了。

| 键 | 轴的行程 | 现在那一项走 | 要跨 2 格的最小权重 | **要抬几倍** |
| --- | --- | --- | --- | --- |
| `layoutPerMeterPerPoint` | 5.5 米 | 0.55 点 | 0.45 | **4.5×** |
| `layoutPerDegreePerPoint` | 180° | 0.90 点 | 0.01 | **2.8×** |
| `homingPerMeterPerPoint` | 15 米 | 0.75 点 | 0.17 | **3.3×** |
| `homingPerDegreePerPoint` | 29 °/tick | 1.45 点 | 0.09 | **1.7×** |
| `bouncePerBouncePerPoint` | 3 次 | 2.10 点 | 0.83 | **1.2×** |
| `bouncePerFalloffPerPoint` | 0.9 | 0.72 点 | 2.78 | **3.5×** |

### 5.1 三条**底价**（`layoutBasePerPoint` / `homingBasePerPoint` / `bounceBasePerPoint`）

**它们不是"跨不动"，是压根没有滑块。**

底价是"**装上这个零件**"那一笔**定额**（`pricing.ts`：`points = 底价 + 米×每米 + 度×每度`）。
引擎里没有一根叫"底价"的滑块 —— 组件总是恰好买一次。
所以它在账上永远是同一个数（0.8 → 印 −1；1.2 → 印 −1），**0 格行程**。

#### 处置

| 方案 | 内容 | 代价 |
| --- | --- | --- |
| **甲（本建议稿采用）：维持不动** ✅ | 底价保持 0.8 / 1.2 / 1.2。**它不需要自己的滑块** —— 只要零件整体跨得出 2~3 格就够，而这件事由**半径 / 距离 / 次数**那几条轴兑现。底价活在整段行程的**起点**上（现在整件账是 −1 → −6），一层都不缺 | 无。底价那一笔在账上恒为 −1，但"底价看不见"不再等于"零件看不见" |
| **乙（可选）：抬到 2.5 / 3 / 2.5** | 让底价自己也能把一个"最省档"印到 −3 | ⚠ **会把整件零件的价格整体抬高一档**（最省档 0.8 → 2.5 = 印 −3 而不是 −1）。⚠ 同时**打破**现有设计锚点：`layoutBasePerPoint` 的 0.8 是"`extraCopyPerPoint` = 2 点的 0.4 倍"（`pricing.ts` 与 `layout.json` 的注释都记着这个参照系）。⚠ 还会**打破 3 条现有测试**（见第七节） |

> **本建议稿的立场**：走**甲**。理由：底价的作用是"**给这个零件定一个起价**"，
> 不是"被玩家拖来拖去的一个旋钮"。让**可拖的那几条轴**跨得动，就已经兑现了用户的规格。

### 5.2 真正"天生跨不动"的旋钮：两条候选

#### 候选 A：`bouncePerFalloffPerPoint`（**头号**）

- 轴只有 **0.9** 宽（衰减 0.1 ~ 1.0），现在那一项只走 **0.72 点** —— 连一格的 1.5 门槛都不到。
- 全衰减与完全不衰减在账上**完全同格**（都是 −3）。

| 方案 | 内容 | 代价 |
| --- | --- | --- |
| **甲：提高权重**（本建议稿采用） | 0.8 → **3**（抬 3.5 倍），账上 −3 → −6 | ⚠ 每 0.1 衰减值 0.3 点，是这一套修饰里**最陡的一条小增量**；"几乎不衰减"会明显更贵 |
| **乙：撤掉这个旋钮** | 把 `damageFalloff` 从计价里摘掉 —— ⚠ **但它不能写死** | ⚠ `damageFalloff` 是**玩家真的会拖的一个参数**（`mod.bounce` 的 `damageFalloff`，默认 0.7 = 用户说的"每次 −30%"），它是**引擎行为参数**、不是定价参数。⇒ 撤掉旋钮**不会**让这个参数消失，只会让它**完全免费**：弹射"完全不衰减"和"全衰减"同价。⚠ 那会开一个**免费变强**的口子，而这是本项目列为最危险的那一类 |

> **结论**：这一条**没有"把参数写死"这个选项** —— 参数本来就在引擎里、必须存在。
> 所以乙实际上等于"**这一轴不计价**"，即"完全不衰减"白送。
> ⇒ 建议**甲**；如果用户认为陡，可以折中取 **2**（走 1.8 点，仍跨 2 格：−3 → −5）。

#### 候选 B：`homingPerDegreePerPoint`（**擦边**，不是真"天生"）

- 轴 29 °/tick，现在走 **1.45 点** —— 距 1.5 门槛只差 **0.05 点**。
- 它**已经**能跨 2 格（1 → 30 是 −2 → −4），但最省那三档挤在 −2。

| 方案 | 内容 | 代价 |
| --- | --- | --- |
| **甲：提高权重**（本建议稿采用） | 0.05 → **0.1**（抬 1.7 倍，六条里最温和），跨 3 格 | ⚠ "拐得最快"那几档会明显更贵（30 °/tick 单独值 3.0 点） |
| **乙：撤掉这个旋钮** | 让转速与距离共用一条汇率 | ⚠ `turnRate` 是引擎参数（`mod.homing` 的 `turnRate`），撤掉只会让它**免费**。⚠ 而且用户的原型里"每米 / 每度"是**故意分开的两条键**（`school.ts` 的 `MODIFIER_HOMING_*` 注释：合成一条就调不了"只让看更远更贵"） |

> **结论**：同上 —— 引擎参数不能"写死"，撤掉 = 免费。
> ⚠ 另外提醒：**这个数当初正是为了已删除的容差被压到 0.05 的**，抬回 0.1 只是把当年那一刀收回来。

### 5.3 一张"能不能撤"的总判据

| 旋钮底下的那个参数 | 能撤吗 |
| --- | --- |
| 纯定价系数（`*PerPoint`） | ✅ 能撤 —— 撤掉就是把这一轴并进别的轴 |
| **引擎行为参数**（`radius` / `spread` / `startAngle` / `mirrorAngle` / `maxRange` / `turnRate` / `maxBounces` / `damageFalloff`） | ❌ **不能"写死就完事"** —— 参数必须存在（引擎要用）。撤掉旋钮 = **让它免费**，会开"免费变强"的口子 |

⚠ 本文档涉及的六条增量旋钮，底下**全都是引擎行为参数** ⇒ 一律只剩"**提高权重**"这一条路。
