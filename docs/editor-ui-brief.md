## 一、先说清楚我的立场

我做的 UI 不直观、不美观，这一点用户说得对，而且**根因不在配色**：

1. **信息密度是任务逼出来的**：术式编辑器一屏要塞下"技能链 / 每段的账 / 条件门 /
   序列 / 按键绑定 / 编译问题 / 分享码"七样东西。我用的是最省事的排法
   （一行一行、竖着堆），所以它像一份表格，不像一个工具。
2. **我没有设计能力**：配色、层级、留白、图标、动效，我只会取"能看清楚"的下限 ——
   这就是它现在这么素的原因。
3. **它还是一个"列表式"的界面**：你早就说过路线是"**先列表，之后加图**"
   （见 README 的下一步）。图视图那一层还没做 —— 而"序列 + 技能"这种结构
   **本来就该是图**。

所以：**外观、布局、交互归你**；我保证两件事 ——
（a）你现在能看到的信息，改版之后**一条都不许丢**；
（b）你交什么我就能多快套上去（下面第三节写了这个契约）。

## 二、现在有什么（设计底稿）

两个页签，都在同一个浮层里（`Tab` 开关，打开时游戏暂停）。浮层的壳是和游戏共用的，
**这层壳是我最该改而没改的地方** —— 它盖住半个场地（`ui-plan.md` 里第 21 条）。

### 页签 1：技能（零件）

| 区域 | 有什么 | 是什么 |
| --- | --- | --- |
| 技能选择条 | 「基础技能库（出厂 · 只读）」/「我的技能（自定义）」两个分组 + 新建/另存为/删除 | 选一个技能来编辑；出厂那份只能当模板 |
| 数值区 | 每条规则一行的**滑块**（值必须是点表上的格子）+ 一个数字输入 | 拖滑块 = 改数值，右侧实时显示"这一条值多少点" |
| 固有效果 | 单独一块，排在规则前面 | "这个技能**是什么**"（载体 + 载荷），不是"额外做了什么" |
| 阶段（时间轴） | 前摇 / 命中 / 后摇，各自的时长、打断等级、代价（能量 / 冷却） | 时间轴进点数账（时间是代价） |
| 规则区 | 8 条模板的「＋ 加一条」，每条可删、可选触发时机 | 额外行为与反应 |
| 账 | 相对模板的偏离：**负数 = 效果消耗的额度**（在这个技能上买了强度）、**正数 = 代价提供的额度**（改弱了、退回来的额度）；合计 < 0 = 超模 → 用**血契**补（⚠ 原句写反了，见本表下方 ⚠） | 技能是零件，**可以歪**，不判配平 |
| 顶部 | 一句话说明"你在改的是哪一份、能不能改" | 出厂 = 只读；变体 = 可改可删 |

⚠ **2026-09-30 修：原句把正负写反了。** 这一行原话是：

> 相对模板的偏离：**正 = 买的额度，负 = 提供的额度**

**照原句配色会把绿红整个做反**（而这是"看起来正常、语义全错"那一类）✗。正确口径（用户纠正过两次
"**点数为负值的才是超模技能**"）：**负数 = 效果消耗的额度，正数 = 代价提供的额度**；
**合计 < 0 = 花超了 = 超模 → 用血契补**。出处：[日志 03](log/2026-09-19-03-ledger-sign-and-interrupt-levels.md) §一、
[`skill-editing-decisions.md`](skill-editing-decisions.md) §3.1（"负数 = 效果消耗的额度，正数 = 代价提供的额度"）、
[`standard-values-draft.md`](standard-values-draft.md)（"Δ > 0（变强）→ 收益 → 消耗额度（负）"）。
⚠ 顺带一处同源佐证：编辑器 CSS 里绿色那条本来就叫 `.gain`、红色叫 `.cost` —— 照原句配色会正好反过来。

### 页签 2：术式（成品）—— 你的创作台

| 区域 | 有什么 | 是什么 |
| --- | --- | --- |
| 工具条 | 选（我做的）/ 新建 / 另存为一份 / 删除 / 导出 JSON / 导入 JSON / 复制分享码 / 粘贴分享码 / 装到 键1..0 | 空术式不给"装到按键"那一栏 |
| 元信息 | 名字 / 怎么按（press·release·hold·toggle·auto）/ 怎么瞄（self·directional·locked·auto·areapoint）/ 射程 / 对谁有效 | 一份术式一行 |
| 技能链 | ① ② ③ … 每段一张卡：技能名、拖不动但可删、可上下移 | **这是要变成"序列"的地方**（见下） |
| 段之间的门 | 每一对相邻段之间可以选择"什么时候才走下一段"（9 种条件） | `links` / `sequenceLinks` |
| 账（主视觉） | 合计 + 每一段值多少 + "还差多少额度没用完 / 超了多少" + 明细可展开 | 负值术式会写成"每次释放消耗 N 点血契" |
| 编译问题 | 红字：这份术式现在**跑不起来**（悬空技能引用 / 空壳） | 和账分开 —— 一个是"配平没有"，一个是"能不能跑" |
| 状态 | 已配平 / 还差 N 点 / 负值术式 / 跑不起来 | 四种 |

### 一套术式有哪几种状态（设计时每种都要有样子）

```
空壳（还没加技能）      → 不给装键 + 一句原因
配平（合计 0）          → 可以装键、可以分享
还差额度（合计 > 0）    → 白送中，提示"加强效果或降代价"
负值术式（合计 < 0）    → 每次释放花血契（紫色，不是错误）
跑不起来（编译问题）    → 能按但什么都没发生，必须红字说清
序列（B 模型，见下）    → 一条术式里有 N 条序列，每条 = 若干技能（⚠ "自己的瞄准"那半已被取代 —— 详见本文件 §四 的 ⚠）
```

## 四、序列要变成什么样（模型 B，用户 2026-09-21 定的）

用户原话：

> 我设想的是术式中有若干条序列，每条序列放若干技能，按下按键就按顺序激活序列

> 补充，如果释放某条序列时其中的某个技能在 cd，则释放下一条序列。

⚠ **这条的口径在日志 49 改过**：现在是"**不激活**这条序列 + 给提示 + 指针挪到下一条、
**等下一次按键**才试"（旧版会当场把下一条打出去）——
见 [日志 49](log/2026-09-27-49-cd-skip-and-hint.md)。

选的是 **B：序列内联在术式里**（不是引用另一份术式）。所以编辑器里那块会变成：

```
术式「我的二段」
├ 序列 1   技能：标记           瞄准：自动选最近的（14 米）      冷却：无
├ 序列 2   技能：瞬影           瞄准：打带标记的那个（30 米）    冷却：8 秒
└ ＋ 加一条序列
```

- 每条序列里可以放**若干技能**（一条序列内部就是一条技能链，可以有段间条件门）
- 序列之间也可以有门（`sequenceLinks`）—— "身上有标记才走第二段"
- 按键：按一次走一条序列，**这一条在冷却就自动放下一条**（引擎已经做了）
- ⚠ 每条序列**自己的瞄准**（上面那张表里的"瞄准"列）—— 二段技能全靠它：
  第一段"自动选最近的"，第二段"打带标记的那个"

设计这一块时最要紧的是：**一眼看出"现在按下去会走哪一条"**（哪条在冷却、哪条是下一条）。

⚠ **这一节已经过时了两处**，以 [`sequence-and-modifier-model.md`](sequence-and-modifier-model.md)
（2026-09-21 定稿）为准：

1. 上面那张表里的"**瞄准**"列 —— 瞄准**已经移到技能层**（每个技能各自解释那一个意图，
   术式本身**没有瞄准**了）✗ 不要再把瞄准做进序列行
2. "每条序列里可以放若干技能" —— 现在要按**形态**分：瞬发序列可放**多个**瞬发技能；
   蓄力/持续技能**必须在序列最前面**，后面可以跟瞬发技能 ✓
   （另外还多了**常驻序列**和**修饰技能**两样东西）

## 五之三、**你具体怎么改布局**（四条路，从小到大）

### 路 1：只换样子（不用碰结构）—— 90% 的情况就够

**改 `web/index.html` 里那一个 `<style>` 块。** 里面已经有一整套类名（`.te-bar` `.row` `.hint`…），
你只要给它们换颜色/字号/间距/圆角/布局（flex、grid 都行）。

```powershell
npm run serve                            # 已经在跑就不用
# 浏览器打开 http://127.0.0.1:5173/
# F12 → Elements 里点中元素 → 右边 Styles 直接改（所见即所得）
# 满意了 → 把值抄回 web/index.html 的 <style> → 刷新
```

⚠ 别在 .exe 里迭代样式（那边要重编 + 重打包）—— 浏览器里改顺了，我打包一次。

### 路 2：挪块 / 换顺序（一行的事）

每块的位置 = `mountBlock(...)` 调用的**先后顺序**：

- 术式页：`web/src/technique-editor.ts` 的 `renderAllInner()` ——
  `mountBlock(body, 'bar', …)` / `'meta'` / `'chain'` / `'library'` / `'ledger'`
- 技能页：`web/src/editor.ts` 的 `renderInner()` —— `flush('head')` / `'points'` / `'rules'`
  / `'leaves'` / `'phases'` / `'issues'` / `'export'`

**改顺序 = 把这几行调换位置** ✓（比如把「账」挪到最上面：把那两行挪到最前面）。

### 路 3：改一块内部的排布（改那段 html）

各块的模板函数（都在上面那张块地图里）：

| 想改的东西 | 改哪儿 |
| --- | --- |
| 工具条（选/新建/导出…） | `technique-editor.ts` 的 `barHtml()` |
| 名字 / 怎么按 / 怎么瞄 / 射程 | `metaHtml()` |
| 每一段那张卡（① ② ③） | `segmentHtml()` |
| 段之间的门 | `gateHtml()` |
| 可加的技能列表 | `libraryHtml()` |
| 账（合计 + 每段 + 明细） | `renderLedger()` |
| 技能介绍 / 冷却 / 规则行 / 点数段 | `editor.ts` 的 `introHtml()` / `coolDownTiming()` / `ruleRow()` / `flush('points')` 之前那段 |

⚠ 改了 html 之后**必须自己看一眼浏览器**（我不能替你判断好不好看）。

### 路 4：加一块新的

1. 写一个函数返回一段 html（比如 `function wipBar(t): string { return \`<div class="wip">…\` }`）
2. 挂上它：技能页 `flush('wip')`（在某个边界之后）、术式页 `mountBlock(body, 'wip', wipBar(t))`
3. ⚠ **把 `'wip'` 加进 `endBlocks(body, [...])` 的清单** ——
   忘了加的话它每次重画都会被当成"这一轮没挂的块"删掉 ✓（这是唯一一个必须记的坑）
4. 样式写在 `<style>` 里 ✓

### 路 5（给动效/拖拽）：让"会变的数"别重建

一个元素只要在**值变的时候会被重建**，它上面的 transition / 拖拽就会断。
做法：给它写 `data-v="名字"`，然后渲染时调：

```ts
applyValues(body, { name: t.name, total: String(total) })
```

`applyValues` **一样就不写** ✓ —— 于是值变的时候只有那一个文字节点变化，
元素本身还在、动效和拖拽都不受影响 ✓（HUD 早就是这么干的：`data-hud-*`）

### ⚠ 别碰这些（碰了功能会坏 / 测试会红）

| 别碰 | 为什么 |
| --- | --- |
| `data-block="…"` | **自动加的**，你不用写、也不要删（删了会每帧多出一块） |
| `data-act="…"` | 所有点击靠它分发 —— 改名 = 按钮失效 |
| `#stage #stats #skills #editorBody #techBody #teLedger #pick` | 测试按 id 找元素 |
| `data-hud-*` | HUD 靠它做"只更新那几个数" |
| 这些**文字**：`术式栏`、`基础技能库`、`我的技能`、`进入第 N 段`、`放不出来`、`（起手）` | 有测试断言文字内容；挪位置没事，**删/改字**我要跟着改测试 |

**改完说一声** —— 我跑一遍测试（有些断言盯 id 和文字）+ 重新打包 exe。
