# 名词记录（**说清每个词，别再混**）

> 玩家 2026-09-21：
> > 在**名词记录文件**中补充：这个叫**修饰技能**，在技能编辑器里的规则中添加的叫**技能修正**，注意区分。
>
> 所以这份文件是**唯一的用词表**。写代码、写日志、写界面文案都用这里的词。
> 两个词只要差一个字（修饰技能 / 技能修正），就是**两样不同的东西** ——
> 混着用的后果是"我们各说各的，而且都以为自己懂了"。

---

## 一、四层结构（从下往上）

| 词 | 是什么 | 在哪编辑 | 一句话记法 |
| --- | --- | --- | --- |
| **技能** `Skill` | 一个**机制**（打人 / 位移 / 挂状态）+ 它的数值 + 时间轴 + 反应 | 技能编辑器 | **一块料** |
| **序列** `Sequence` | 若干技能按顺序走一遍，**它本身就是一门术式** | 术式编辑器 | **一段连招** |
| **术式** `Technique` | 绑按键的那一套：技能的**组合 + 条件 + 修饰技能** | 术式编辑器 | **一手牌** |
| **来源** `SkillSource` | 这些术式**属于谁**（角色 / 武器） | 场景 + 武器 | **谁的** |

⚠ 本作**不做成 Noita 的法杖**（玩家 2026-09-21 明确："不要做法杖，这个游戏是术式"）。
术式**没有**容量 / 法力 / 施法延迟 / 充能 / 乱序这些数值。
Noita 只是**理解方式**的参照：技能 ↔ 魔法，术式 ↔ 一手编排。

## 一之二、技能的两个库（**技能不属于术式**）

| 词 | 是什么 | 谁改 | 存在哪 |
| --- | --- | --- | --- |
| **基础技能库** | 我们写的出厂技能，默认**配平为 0 点**；也是"创造一个技能"的**模板** | 玩家不能改 | `content/skills/*.json` |
| **自定义技能库** | 玩家**创造**出来的变体（`basedOn` 记住模板） | 随便改，可改名 | **存档**里 |
| **变体 / 副本** | 自定义技能库里的一份技能，比如「火球·爆裂」 | | |
| **模板** | 一份变体是从哪个**基础技能**长出来的（算账的基准） | | |

流程（玩家 2026-09-21 定的）：

```
技能页 → 选中一个基础技能（只读）
      → 「创造一个技能」        ← 拿它当模板，开一份**草稿**（还没进库）
      → 编辑
      → 「保存」                ← 这才进自定义技能库、才开始生效
      → （也可以「另存为」成又一份新的）
```

三条要紧的：

- **基础技能和它的变体是两样东西**（各有各的 id）。基础版永远在，
  所以一份术式里可以一段用基础版、一段用你的变体。
- **变体是全局的**：它不属于任何术式。改它，**所有用到它的术式一起变**。
- **删变体先要清引用**：还有术式在用它就不给删，并列出是哪几份。

## 一之三、术式的两个库（**玩家只看得见自己那一个**）

| 词 | 是什么 | 谁改 | 存在哪 |
| --- | --- | --- | --- |
| **内部术式库** | 引擎 / 敌人 / 武器在用的术式 | 我们改（玩家看不到） | `content/internal-techniques/*.json` |
| **玩家的术式库** | 玩家自己拼的术式（`tech.mine-*`） | 随便改，可改名 | **存档**里 |
| **起手术式** | 开局发给玩家的那一份（从内部库复制来） | 改 / 删 / 另存为 | 存档 |

⚠ 玩家 2026-09-21 定的：

> 敌人用的术式存到别的地方，玩家在编辑器里看不到这些示范术式，也没法引用它们。

所以术式编辑器里那个列表**只有玩家自己那一个库**（以前出厂那三十多份"一个技能
配一份同名术式"的示范会列成一个「出厂示范（只读）」分组，把创作台淹成了一条技能栏）。
内部库仍然会被加载、也仍然能被场景引用 —— 只是**不进玩家的列表**。

## 二、技能里面有什么（四个格子）

| 词 | 是什么 | 进点数账吗 |
| --- | --- | --- |
| **固有效果** `effect` | 这个技能的**机制**：载体 + 载荷 + 它的数值（伤害、距离、时长…） | ⚠ 机制**免费**，**数值有价**（偏离它的基点才计价） |
| **规则** `rules[]` | 额外行为与反应：挂在某个时机上的条件动作 | 进账 |
| **阶段** `phases[]` | 时间轴（前摇 / 命中 / 后摇…） | 进账（时间是代价） |
| **代价** `cost` | 能量 / 冷却 / 生命 | 进账（代价提供额度） |

⚠ **固有效果不进"规则栏"**（玩家 2026-09-21 第 1 条）：
它是这个技能**是什么**，不是"它额外做了什么"。编辑器里它单独一块。

## 三、两个最容易混的词

### 技能修正（skill modifier）

- 位置：**技能编辑器**里，加在**这个技能的规则**里。
- 管什么：**数值和几何** —— 伤害 ×2、距离 +2 米、张角变 360°、时长减半……
- 什么时候生效：跟着它所在那条规则的**时机 / 条件**走
  （"蓄满力时伤害 ×2"就是一个技能修正）。
- 玩家 2026-09-21："**数值和几何都可以由技能修正负责**"。

### 修饰技能（modifier skill）

- 位置：**术式编辑器**里，作为术式里的一件**特殊技能**插进去。
- 管什么：**术式中技能的连接、条件选择**等任务。
- ⚠ 它**不管数值和几何**（那是技能修正的事）。
- 玩家 2026-09-21："**修饰技能只负责术式中技能的连接、条件选择等任务**"。

### 触发器技能（trigger skill）—— 修饰技能的一种

- 位置：术式里，**后置在某个技能后面**。
- 编辑时要选两样：
  1. **触发条件** —— 技能结束 / 碰撞（命中）
  2. **触发的技能** —— **任意个**
- 行为：被后置的那个技能**达成触发条件之后**，把那些技能**同时激活**。
- 玩家 2026-09-21：
  > 编辑触发器技能时需要选择触发的条件（技能结束、碰撞）和触发的技能（任意个）。
  > 若术式中某个技能后置了触发器，会在这个技能达成触发条件后同时激活触发的技能。

## 四、点数相关的词

| 词 | 意思 |
| --- | --- |
| **点数（额度）** | 一本账。**负 = 收益**（消耗额度），**正 = 代价**（提供额度） |
| **配平** | 一份东西的点数合计到 0。**判据在术式上** |
| **默认值** | 玩家不动任何滑块时的那套值。⚠ **宗旨：默认值下点数 = 0**（按**技能**算） |
| **出厂版本 / 基础技能** | `content/skills/*.json` 里那一份。**只读**，也是算"你改了多少"的基准 |
| **模板** `basedOn` | 一份变体是从哪个基础技能长出来的 —— 它的账就对着这个算 |
| **自定义技能库** | 存档里的变体列表（`SavedState.skills`）。玩家自己的东西只有它 |
| **相对账** | 玩家真正看的那个数：`现在的技能 − 它的模板`（见 `skillLedger`） |
| **绝对账 / 强度标尺** | `priceSkill` 算出来的数：这个技能站在汇率表的哪个位置。**不判配平**，只给报表看 |
| ~~**出厂负债件** `factoryDebt`~~ | **删掉了**（2026-09-21）。曾经用来让少数技能从绝对账起算，好让出厂内容里也有"一放就吃血契"的技能。删的理由：宗旨没有例外，而且玩家原话"**负债件的变体不一定是负债件**"—— 那个标记在变体上说不通 |
| **基点 / 基准（baseline）** | 写内容时用的**强度标尺**（见 `docs/default-values.md`）。⚠ 它**不参与**算账 |
| **负值术式** | 合计为负的术式 —— 每次释放消耗**血契** |
| **血契** | 局内资源，从"进入危机的行为"里攒，不自动回复 |
| **血契记账器** | `tech.blood-pact`：**不是被动，是系统机制**（不在被动栏显示）—— 出厂就挂着，管"攒" |
| **冷却是技能唯一的属性** | 一个秒数 + **一个时机**（从哪一段开始算）。不能在两个阶段都有（校验器报 `COOLDOWN_TWO_PHASES`）；编辑器里只有一个控件 |

⚠ 宗旨的原文（玩家 2026-09-21）：

> 所有点数相关的可调整的值，都具有一个默认值，在这个默认值下点数是配平为0的。

⚠ 它怎么落地（玩家 2026-09-21 追问之后的三个回答，缺一不可）：

> （那个 0 对着谁算）**每个技能自己定，内容里的就是默认**
> （固有效果里的数值算不算进账）**机制免费、数值偏离默认才计价**
> （少数技能想生来就不公平）**给技能加一个「出厂就是负债」的显式标记**
>   —— ⚠ **这一条当天就撤了**：玩家看过之后说"没什么必要"。
>   > **负债件的变体不一定是负债件**……宗旨是铁的。

所以：**出厂内容全部是 0 点，一个例外都没有**（`tests/pricing.ts` 逐个扫 30 个技能钉着它）。
账算的是"**你改了多少**"，不是"这个东西值多少钱"。
想超模就自己编变体（把技能改强），那份术式的合计变成负的 —— 那才是**负值术式**，
才吃血契。血契要服务的就是这个。

## 五、其它已经在用的词

| 词 | 意思 |
| --- | --- |
| **载体 delivery** | 这一下"怎么出去"：投射物 / 光束 / 近身扇形 / 突刺 / 区域 / 光环 / 召唤 |
| **载荷 payload** | 这一下"干了什么"：伤害 / 治疗 / 改属性 / 挂状态 / 位移 / 感知 / 召唤 |
| **动作 action** | 载体 + 载荷 + 目标 |
| **时机 when** | 施放时 / 命中时 / 未命中时 / 阶段结束 / 进入范围… |
| **规则位 ruleSlots** | 一个技能能写几条规则（复杂度税，基准 4 条） |
| **常驻术式** | `activation: 'auto'` / `toggle`：不用按就在生效的被动 |
| **序列链** | 术式的 `sequences` + `sequenceLinks` + `sequenceTimeout`：按一次走一段 |
| **屏障 obstacle** | 会挡东西的实体（能挡子弹、能挡人，四个穿透开关） |
| **强度标尺** | 见 `docs/default-values.md`（写内容时用的各机制标准数值，**不进账**） |
