# 项目结构

**这份文件回答一个问题：哪个文件该改。**
设计动机和踩过的坑在 `technique-system/README.md`，类型为什么长这样在 `schema/README.md`。

> **两条宗旨**（动手改点数或点数相关字段之前先读）：
> 1. **点数相关的每一个可调值都有一个"配平为 0 的默认值"** ——
>    这个"默认值"是**每个技能自己的出厂数值**（用户 2026-09-21 定的），
>    所以账算的是"**你改了多少**"，出厂内容全部是 0 点。
>    写在 `schema/README.md` 第五节，实现在 `src/pricing.ts` 的 `skillLedger`。
> 2. **玩法参照 Noita 的法杖编程**：本作的**技能** ↔ Noita 的**魔法**，
>    **术式** ↔ **一把法杖里的全部魔法**。所以"技能"和"术式"的边界按 Noita 那套想。

```
magic and sword\
├── schema\              规格（唯一真相来源：既是设计文档，也是类型定义）
├── technique-system\    实现（全部代码 + 内容）
└── docs\                这份说明 + 设计稿 + 修改日志
```

## 一、依赖方向

从内到外，**只允许向外依赖**：

```
① src/sim/          无头模拟核 —— 不认识浏览器、不认识文件、只认数据和 tick
② src/              pricing / describe / loader / bridge（纯计算 + 内容装载）
③ src/cli/ + web/   两个驱动：命令行和浏览器，共用 ①②
④ tools/ + tests/   工具和十二套检查
```

① 是**将来要独立出去的那一层**。`npm run test:purity` 强制它不许出现
`Date` / `Math.random` / `console` / `window` / `process` / 三角函数等 12 条禁令 ——
`Math` 只白名单 `sqrt / abs / floor / ceil / round / min / max / imul / sign / trunc`。

## 十、一次按键的数据流

```
content/skills/*.json ─────────────┐
                                   ├─→ loadLibrary() ─→ 校验 ─→ compileTechnique() ─→ 编译产物
content/internal-techniques/*.json ┘                                 │
                                                                     ├─→ applyScenario(world) ─→ stepWorld 60Hz
                                                                     └─→ library (Map) ─→ 按键 / HUD / AI
（玩家的术式住在存档里，开局把场景发的那一份复制成自己的 —— 见 seedStarter）

编辑器改技能 ─→ applySkillEdit() ─→ 全量重编译 ─→ 换回 world 里的引用
                                     （不重编译 = 改了等于没改）

编辑器拼术式 ─→ 就地改 Technique ─→ recompileAll() ─→ registerTechnique(world)
                └─→ localStorage 存档（刷新不丢）/ 分享码（给朋友）
                └─→ 换了技能栏 → restart() 重开一局（半路换会新旧混着）
```

`stepWorld` 的 11 步（**顺序不许改**）：

```
1 状态计时  2 回复  3 上限钳制  4 冷却  5 施法  6 常驻技 onTick
6b 状态 onTick  7 AI  7b 阶段锁定  8 位置积分  8b 区域进出
9 投射物碰撞  10 存在时间  10b 释放区域占位  11 清理
```

⚠ 带 `b` 的那三步是后加的（阶段锁定 / 区域 `onEnter`·`onLeave` 差分 /
区域消失时补一次 `onLeave`），**位置是刻意的**：它们必须在被观察的那一步
之后、在清理之前。加新步骤时先回答"它相对谁在前"。`tests/scenario.ts` 盯着这几条。
